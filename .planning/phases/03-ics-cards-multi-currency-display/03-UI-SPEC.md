# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: ICS Cards + Multi-Currency Display. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope (UI surfaces produced):**

1. `/imports/new` — UploadWizard refactored from flat dropdown into a **two-step issuer → format picker** (D-33). ASN → CSV / CAMT.053 / MT940; ICS → CSV.
2. `/imports/{id}/preview` — wizard inline **"Name your ICS Account"** step on first ICS upload (D-36, D-38) — generalised from Phase 1's IBAN-account-naming step.
3. `/transactions` — adds a **currency-view segmented control** (EUR-only vs Original) per D-44, surfacing the dual-currency stack render per D-47.
4. `/` (dashboard) — `ThisPeriodAtAGlanceQuery` grows a **group-by-currency mode** (D-46): in EUR-only the three KPI tiles are unchanged; in original mode the tile row stacks vertically per currency present in the period.
5. `/transactions/{id}` (detail) — surfaces the **per-transaction effective FX rate** when both legs are present (D-48). Detail page is consumed by but not introduced in this phase; Phase 3 only adds the FX line to whatever detail view exists.
6. `/settings` — **new minimal Settings page** (D-45) with `default_currency_view` toggle + `period_start_day` integer field. Discharges Phase 1's deferred D-19.
7. Top nav — gains a **Settings** link (between "Uncategorized" and the user-email/sign-out cluster).

**Out of scope this phase:**

- ICS Excel ingestion (D-31 — CSV only).
- Per-card visibility within the single ICS Account (D-36 — no `card_last4`, no per-card grouping).
- PayPal, Google Play, email receipts (Phases 4–7).
- Chain-resolution drill-down (Phase 5), recurring detection (Phase 8), forecasting (Phase 10).
- Splitting ICS FX markup as a separate canonical row (D-40 — rolled into one row; markup recoverable from `rawPayload` if a later phase wants it).
- Dark mode.

**Dual-currency row typography (D-47):**

- **Primary line (native amount):** Body 14px weight 400 in `text-slate-900` — the same weight and color as the amount column today; the "primary" framing is positional, not typographic.
- **Secondary line (settled EUR amount):** Body 14px weight 400 in `text-slate-500` (`text-muted-foreground` equivalent). Placed directly under the native amount with `mt-0.5` (a 2px optical gap; the calm aesthetic forbids `mt-sm`-and-above multi-line stacks).

**FX-rate label on the detail page (D-48):** Body 14px regular for the label ("Effective rate"); Body 14px regular `text-slate-900` for the value with tabular-nums. Format locked: **`€0.929 / USD`** (one EUR buys 0.929 USD? — see "Currency display" interaction contract below for the locked orientation and precision).

### Dual-currency row presentation (`/transactions` original mode, D-47)

For an FX row:

```
$12.99 USD         ← primary line, text-slate-900
€12.07 EUR         ← secondary line, text-slate-500, mt-0.5
```

For an EUR-native row in either mode:

```
€12.07 EUR         ← single line, text-slate-900
```

**Currency code suffix:** ISO 4217 three-letter code (`USD`, `EUR`, `GBP`). The symbol prefix + ISO suffix is redundant by design — the suffix prevents misreading `$12.99` as Canadian or Australian dollars when the column is scanned quickly. Locked verbose form: **`$12.99 USD`** not `$12.99` alone.

**Negative amounts:** Leading minus before the symbol: `-$12.99 USD` (matches Phase 1's `-€12.07` pattern). Color stays `text-slate-900` — never red. Calm aesthetic.

### Per-currency KPI tile rows (`/` original mode, D-46)

For a period with USD and EUR activity:

```
EUR                                           ← caption label, 12px, text-slate-500
[In: €3,422.50]  [Out: -€1,180.00]  [Net: +€2,242.50]   ← three tiles, same as Phase 1

USD                                           ← caption label, 12px, text-slate-500
[In: $0.00]      [Out: -$12.99]    [Net: -$12.99]       ← three tiles
```

For an EUR-only period in original mode: only the EUR caption + three tiles render — visually identical to EUR-only mode.

**Zero-activity currencies are omitted.** A currency with no in/out movement in the period does not render a row. This avoids visual clutter from currencies that haven't seen activity this period but exist in historical data.

### FX rate on the transaction detail page (D-48)

Detail page renders one additional `<dl>` row when `fx_rate_used IS NOT NULL`:

| Element | Copy |
|---------|------|
| Label (`<dt>`) | `Effective rate` |
| Value (`<dd>`) | `€{rate} / {native_currency_code}` — e.g. `€0.929 / USD` |

**Rate orientation locked: EUR-per-unit-native.** `€0.929 / USD` reads as "0.929 EUR per 1 USD". This is the orientation that matches "I paid X EUR for Y USD" — the user's mental model when reviewing a card statement. Reject the inverse orientation (`$1.077 / EUR`) because it forces the user to flip their mental model versus the receipt they're holding.

**Precision: 3 decimal places.** `€0.929 / USD` not `€0.9292 / USD` and not `€0.93 / USD`. Three places balances "useful for drift detection" against "calm, not screaming-precision".

**Helper text below the row:** `Includes any ICS markup.` — single calm sentence in `text-slate-500` 12px. Discharges D-39's "effective post-markup rate" semantic without burying the user in disclaimers.

## Interaction Contracts

### Currency display (UI-06, MC-02, D-47)

- **Format authority:** the brick/money `MoneyLocaleFormatter`, called via `Modules\Ledger\Public\ValueObjects\Money::format('nl_NL')` for EUR amounts (matches existing dashboard usage), and `Money::format('en_US')` for non-EUR amounts (so the symbol prefix matches the user's mental model of foreign currencies — USD as `$1,234.56`, GBP as `£1,234.56`, JPY as `¥1234` with 0 decimals).
- **Verbose ISO suffix:** Append the ISO 4217 code after a non-breaking space (`$12.99 USD`, `€12.07 EUR`). Locked, prescriptive.
- **EUR-only mode:** The list and dashboard render only `display_minor` / `display_currency` = settled-EUR. The toggle value `eur` corresponds to `?currency=eur` on `TransactionListQuery::recent(..., ?string $currency = 'eur')` and to the existing summation path on `ThisPeriodAtAGlanceQuery` (no `groupByCurrency`).
- **Original-currency mode:** The list renders the dual-currency stack on FX rows (native primary, settled secondary). Dashboard tiles split by currency. URL: no `?currency=` parameter falls back to user default; `?currency=original` explicit.
- **Tabular nums everywhere.** Both lines of the dual-currency stack carry `font-variant-numeric: tabular-nums` so columns visually align across rows.
- **Negative amounts:** Single leading minus, never parentheses. `-$12.99 USD`, not `($12.99) USD`. Color stays `text-slate-900`.
- **Currency badges / chips:** none. Currency is communicated by the formatted string only. Adding a `[USD]` chip would conflict with the calm density target.

### FX rate display (D-48)

- **Detail page only.** Never inlined on the list. Never shown as a tooltip.
- **Format locked:** `€0.929 / USD`. Three decimal places. EUR-per-unit-native orientation. Helper text below: `Includes any ICS markup.`
- **Derivation:** Phase 3 derives `fx_rate_used = settled_amount_minor / amount_minor` as `decimal(18,8)`. The detail-page render uses `number_format($rate, 3, '.', '')` for the display — three decimal places, period separator (not comma) because the rate is a ratio not an amount.
- **Null rate:** When `fx_rate_used IS NULL`, the row does not render. EUR-native transactions show no FX section.

### Currency-view toggle (D-44)

- **Component:** `flux:radio.group variant="segmented"` with two options.
- **State binding:** Livewire 4 `#[Url(as: 'currency')]` property `$currency`. Browser back/forward respects the URL. Refresh-stable.
- **Default fallthrough:** When `$currency === null` (no `?currency=` query), the Livewire `mount()` reads `$currentUser->user()->default_currency_view` and applies it to the rendered output without rewriting the URL. **The URL stays clean** ('default mode') — `?currency=` only appears after the user actively toggles.
- **Persistence:** The toggle is per-session per-page. It does NOT update the user's stored default. Updating the default is exclusively a Settings page action.
- **Keyboard:** Native radio-group semantics — `←` / `→` switch options, `Space` selects. Flux handles this automatically.
- **Focus ring:** Inherits the project-wide `focus-visible:ring-2 ring-slate-900 ring-offset-2` pattern. Verified Flux applies a compatible ring by default.

### Two-step wizard picker (D-33)

- **Issuer select** drives the **Format select** options. Implemented as two synchronous Livewire properties; changing issuer resets the format to the first valid option for that issuer.
- **Submit validation:** The composite `sourceFormat` (e.g. `ics-csv`) must match the `in:` allow-list — defensive, since the cascade should make invalid composites impossible.
- **Refresh stability:** The wizard's Livewire state is wire:model-bound, so a mid-form refresh loses the in-progress selection. Acceptable — the wizard surface is short.
- **Snapshot tests:** The Phase 1/2 wizard Blade snapshot must be re-baselined. Carve a task in the planner.

### Name-your-ICS-Account inline step (D-38)

- **Trigger:** On first ICS upload, the preview wizard surfaces the naming prompt instead of the rows table — exact same UX shape as the existing IBAN-naming step.
- **Validation:** Account name required, max 80 chars (mirrors the existing IBAN-naming validation).
- **Persistence:** Save inserts a single row into `accounts` with `type = 'ics_card'`, `name = {input}`, `currency = 'EUR'`. The row's `user_id` comes from the `CurrentUser` service.
- **Skip path:** Once an ICS Account exists for the user, the prompt does not render on subsequent ICS uploads — the wizard goes straight to the rows preview.

### Settings page (D-45)

- **Form submission:** Single Livewire `wire:submit="save"` action. Updates the `users` row (or `user_preferences` row — planner's call) atomically.
- **Validation:** `default_currency_view` ∈ {`eur_only`, `original`}; `period_start_day` ∈ 1..28 integer.
- **Success state:** Inline "Saved." text below the button. No toast (Phase 1's Flux toast contract carries forward but Settings doesn't require it).
- **Cancel:** None. The form has no Discard button — leaving the page abandons unsaved changes silently, which matches the calm-aesthetic principle of not interrupting the user.

### Date display

Unchanged from Phase 1. Format: `12 May 2026`.

### Loading & latency
