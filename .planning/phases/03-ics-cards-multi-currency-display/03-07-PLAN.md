       ```php
       <?php
       declare(strict_types=1);

       namespace Modules\Ledger\Internal\Http\Livewire;

       use Illuminate\Contracts\View\Factory as ViewFactory;
       use Illuminate\Contracts\View\View;
       use Livewire\Component;
       use Modules\Core\Public\Contracts\CurrentUser;
       use Modules\Ledger\Models\Transaction;
       use Symfony\Component\HttpKernel\Exception\NotFoundHttpException;

       final class TransactionDetail extends Component
       {
           public int $transactionId = 0;

           public function mount(int $transactionId, CurrentUser $currentUser): void
           {
               $this->transactionId = $transactionId;

               // 404 immediately if the transaction does not belong to the user.
               $exists = Transaction::query()
                   ->where('id', $transactionId)
                   ->where('user_id', $currentUser->user()->id)
                   ->exists();

               if (! $exists) {
                   throw new NotFoundHttpException(sprintf(
                       'Transaction %d not found.',
                       $transactionId,
                   ));
               }
           }

           public function render(CurrentUser $currentUser, ViewFactory $views): View
           {
               $transaction = Transaction::query()
                   ->where('id', $this->transactionId)
                   ->where('user_id', $currentUser->user()->id)
                   ->firstOrFail();

               return $views->make('ledger::livewire.transaction-detail', [
                   'transaction' => $transaction,
               ]);
           }
       }
       ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser /transactions/{id} URL → server | The id is a route parameter; must not be trusted to belong to the current user without an explicit WHERE clause |
| Authenticated user → Transaction row read | The detail page reads a Transaction model; the user_id scope is the ONLY thing preventing cross-user leakage |
| fx_rate_used (decimal(18,8) string) → Blade `number_format` | The `(float)` cast is display-only; the canonical store stays as the BigDecimal string from NormalizeStage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-07-01 | Information Disclosure | /transactions/{id} cross-user leak | mitigate | TransactionDetail::mount() and ::render() both call Transaction::query()->where('id', $id)->where('user_id', $currentUser->user()->id) — the user_id WHERE is on EVERY query. mount() throws NotFoundHttpException on mismatch; render() throws via firstOrFail(). `UserIdColumnArchTest` regression-test verifies the user_id WHERE on every transactions query. The optional fifth test case in Task 1 step 4 explicitly asserts the 404 cross-user path. |
| T-03-07-02 | Tampering | fx_rate_used display value | accept | The `(float)` cast in Blade for `number_format` is display-only; the canonical store stays as decimal(18,8) string. The float cast is bounded to 18-digit precision plus the formatter's 3-decimal cap, which never re-enters the money pipeline. Verified by `NoFloatMoneyArchTest` staying GREEN (the arch test scope excludes `.blade.php` files). |
| T-03-07-03 | Spoofing | CSRF on the detail page | mitigate | Phase 3 detail page is read-only (no form submissions). Livewire's wire:click / wire:submit handlers would carry built-in CSRF if added in a later phase. No new mitigation needed in Phase 3. |
| T-03-07-04 | Tampering | Non-numeric {transactionId} URL segment | mitigate | The route declares `->whereNumber('transactionId')`, rejecting non-numeric segments at the routing layer. A malicious URL like `/transactions/abc` returns 404 before TransactionDetail::mount() runs. |
</threat_model>
