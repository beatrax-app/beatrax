<task type="auto">
  <name>Task 2: Per-module review pass — write REVIEW-DEEP.md + action findings</name>
  <files>REVIEW-DEEP.md, (cleanup edits across Modules/ as findings dictate)</files>
  <read_first>
    - composer-require-checker output captured in Task 1
    - For each of the 17 modules, glance at: ServiceProvider, Public/ inventory, Internal/ inventory, recent commits touching that module to spot churn / refactoring debt
  </read_first>
  <action>Create `REVIEW-DEEP.md` at repo root. Structure:
    - `# Deep Modules Review` (top)
    - 2-3 sentence intro: the purpose of this review, the date completed, the audit categories used.
    - `## Audit categories` — define BLOCKER (must-fix to publish), WARNING (should-fix, may defer to v1.1), INFO (noted; no action).
    - `## composer-require-checker outcome` — append the cleaned final output from Task 1; note any whitelisted symbols + rationale.
    - One `## Module: <name>` section per module (17 modules: auth, categorization, chains, community, core, counterparties, desktop, dev-mode, drift-alerts, email-scan, forecasting, import, ingestion, ledger, onboarding, receipts, recurring).
    For each module section, walk these 4 dimensions:
      - **Boundary hygiene** — does anything outside `Modules/<Name>/` import from `Modules\<Name>\Internal\*`? (Should be caught by BoundaryArchTest already; if anything sneaks past, document + fix.)
      - **DI compliance** — does any class in the module use facades or global helpers? (Should be caught by noLaravelFacadeUsageInModule / noLaravelGlobalHelpersInCoreConsoleCommands; if anything sneaks past, document + fix.)
      - **Dead code** — are there public methods on services that no one consumes? Old migrations that have been superseded? Test fixtures no test references?
      - **Perf smells** — N+1 queries, eager-loading misses, missing indexes on heavily-queried columns.

    For each finding, record: severity (BLOCKER/WARNING/INFO), description, recommended fix, status (FIXED — link to commit / DEFERRED v1.1 / ACCEPTED).

    Per the project's `feedback_fix_all_severities` rule (CLAUDE.md memory): address BLOCKER + WARNING + INFO together where possible. Quality above speed. Only defer something to v1.1 if it would expand the plan's scope beyond the closeout intent.

    Conclude REVIEW-DEEP.md with `## Summary` — totals per severity, total fixed, total deferred, total accepted. Time-stamp the document with the date completed.

    The actual fix commits should each be small + focused (one finding per commit where possible); reference the REVIEW-DEEP.md section in the commit message body (without GSD-leaking the planning vocabulary — just say "REVIEW-DEEP.md Module:<name> finding: <one-line>").</action>
