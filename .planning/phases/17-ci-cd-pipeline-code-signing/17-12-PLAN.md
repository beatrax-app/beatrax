<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub repo settings → all collaborators + visitors | Misconfigured settings (e.g., force-push allowed on main) could allow history rewriting in production |
| Issue + PR templates → contributors | Templates set expectations; missing security-disclosure note could push vuln reports to public issues |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-12-01 | Tampering | accidental force-push on main wiping history | mitigate | Branch protection ruleset restricts force-push to nobody (even owner cannot force-push) |
| T-17-12-02 | Repudiation | unsigned commits sneaking through | mitigate | Require signed commits on main; owner sets up signing locally (Plan 17-16 mentions key setup if not done) |
| T-17-12-03 | Information disclosure | vulnerability report landing in public issues instead of private reporting | mitigate | Private vulnerability reporting enabled; SECURITY.md + bug-report template explicitly redirect to it |
| T-17-12-04 | Elevation of privilege | malicious dependency update auto-merged | mitigate | Dependabot opens PRs (does not auto-merge); CODEOWNERS requires owner review |
</threat_model>
