<objective>
Wire the auto-update path end-to-end with Ed25519 manifest signing + SHA-512 binary verification as the SOLE binary-integrity signal.

Purpose: UPDATE-01..04 + A-06. With paid signing dropped (A-01), the in-bundle Ed25519 + SHA-512 verification is no longer belt-and-braces — it's the only thing standing between a tampered GitHub-Releases asset and a malicious binary running on a user's machine. The Ed25519 layer is custom (electron-updater ships SHA-512 verification natively but not manifest signing); this plan adds the signing step to release.yml's publish job and the verification step to a new `ElectronUpdateChannel` service consumed by the existing SystemAlertsBanner. The banner UX layers three new alert kinds onto the existing infrastructure (no new Livewire component).

Output: A tag push to `v0.1.1-rc.1` produces a signed `latest.yml` + signed binaries; an installed `v0.1.0-rc.1` bundle detects the new release within 4 hours, verifies the manifest signature + binary hash, and surfaces the `update.available` banner; tampering with any byte of `latest.yml` causes verification to fail and no banner appears.
</objective>

<!-- ElectronUpdateChannel contract -->
namespace Modules\Core\Public\Services;

final readonly class ElectronUpdateChannel
{
    public function __construct(
        private DatabaseManager $db,
        private LoggerInterface $logger,
        private Clock $clock,                     // existing Public contract
        private Repository $config,               // Illuminate\Contracts\Config\Repository — reads auto_update.publisher_public_key_hex + update_channel
    ) {}

    // Returns the channel name (stable|preview) from current bundle config
    public function channel(): string;

    // Polls electron-updater (via injected adapter or direct shell-out to electron) for new manifest
    // VERIFIES Ed25519 signature before returning; null on no-update or verification failure
    public function poll(): ?ManifestDto;

    // Verifies an Ed25519 detached signature against the in-bundle public key
    // Returns true iff sodium_crypto_sign_verify_detached succeeds
    public function verifyManifest(string $manifestBody, string $detachedSignature): bool;

    // Verifies SHA-512 of a downloaded binary against the value declared in latest.yml
    public function verifyBinary(string $binaryPath, string $expectedSha512Hex): bool;

    // Hardcoded 30-day threshold per D-22
    public function isStale(string $currentVersion, string $latestVersion, CarbonImmutable $latestPublishedAt): bool;
}

<!-- In-bundle Ed25519 public key -->
Lives in `config/auto_update.php` under key `publisher_public_key_hex` (64 hex chars).
ElectronUpdateChannel reads it via injected `Illuminate\Contracts\Config\Repository $config` — `$config->get('auto_update.publisher_public_key_hex')`.
The PRIVATE key half lives in repo secret ED25519_PRIVATE_KEY (set during the human-action step).
Public + private key generated ONCE via `php -r 'echo bin2hex(sodium_crypto_sign_keypair());'` — split into seed/pk/sk per sodium conventions.
Rationale: config-based discovery means future key rotation is a config diff (no class recompile); per RESEARCH Q7 (RESOLVED).

<!-- electron-updater channel mapping (per RESEARCH Q3 RESOLVED) -->
Stable channel resolves `latest.yml` (and per-platform `latest-mac.yml` / `latest-linux.yml`).
Preview channel resolves `beta.yml` (electron-updater convention for prerelease channels).
The channel is selected via `config/auto_update.php` → `update_channel` (default `'stable'`).
Users on the preview channel set the value to `'preview'` (Settings UI for this is v1.1 polish; v1.0 ships the config-knob only).
softprops/action-gh-release publishes RC tags with `prerelease: true` so GitHub Releases marks them appropriately; electron-builder is configured to write `beta.yml` for prerelease builds via the `publish.channel` field (planner sets in Task 4).

<!-- New alert kinds (system_alerts.kind) -->
'update.available' — severity default (slate), copy + actions per UI-SPEC § Auto-update banner
'update.stale' — severity warning (amber), 30-day threshold per D-22
'update.critical' — severity critical (rose), no skip option

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Releases CDN → installed bundle | Auto-update path; with no OS-level signing, Ed25519 manifest + SHA-512 binary are the SOLE integrity signals |
| repo secret ED25519_PRIVATE_KEY → release.yml publish job | Private key has access only inside the publish job's runtime; never echoed to logs |
| in-bundle public key → ElectronUpdateChannel | Compiled-in constant; an attacker would need to ship a NEW bundle with a different public key to override (which requires winning a separate attack on the bundle delivery itself) |
| skipped versions in user_preferences → other users | Per-user; BelongsToUser scope prevents cross-user leak |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-04-01 | Tampering | latest.yml manifest in transit or at GitHub | mitigate | Ed25519 signature verification (Task 1, behavior tests 1-3) — a single flipped byte causes verifyManifest to return false; no download proceeds, no banner appears |
| T-17-04-02 | Tampering | downloaded binary in transit | mitigate | SHA-512 hash verification (Task 1, tests 4-5) against the value in latest.yml; latest.yml itself is signed so the hash itself is also covered |
| T-17-04-03 | Information disclosure | ED25519_PRIVATE_KEY exfil via fork PR | mitigate | release.yml triggers only on `push: tags: [v*]`; fork PRs cannot push tags; CODEOWNERS (Plan 17-03 Task 3) requires owner review on workflow edits |
| T-17-04-04 | Repudiation | a malicious release tagged by a compromised collaborator account | accept | Branch protection (Plan 17-15) + signed commits (D-50) reduce this; full mitigation requires hardware-token-backed 2FA which is user-configured |
| T-17-04-05 | Information disclosure | renderer-JSON leaking the in-bundle PUBLIC key or skipped_update_versions | mitigate | PUBLIC key is non-secret by design (public-key cryptography); skipped_update_versions is per-user and only consumed server-side by SystemAlertQuery — never declared on a Livewire `$listeners` or `$queryString`; noSecretsInLivewireSnapshot arch invariant (Plan 17-08) will enforce this once landed |
| T-17-04-06 | Denial of service | a tampered manifest causing the auto-update banner to permanently disappear | accept | Verification failure logs a warning and returns null; next poll cycle re-tries; if every manifest is tampered the user simply doesn't auto-update (degrades to manual install via README install-bypass copy from Plan 17-07) |
| T-17-04-07 | Elevation of privilege | electron-updater's `disableDifferentialDownload:true` on macOS opening a side channel | accept | disableDifferentialDownload bypasses electron-updater's incremental-patch path which requires OS-signature checks that ad-hoc-signed binaries fail; the full-binary path retains Ed25519 manifest verification, so integrity is preserved end-to-end |
| T-17-04-08 | Tampering | partial upload / CDN corruption of `latest.yml` between publish and first download | mitigate | New `verify-published` job (Task 4 Step Y) downloads the published manifest + `.sig` AFTER publish and re-runs Ed25519 verification; failure fails the workflow so the release never appears "green" to humans while broken in the CDN |
</threat_model>
