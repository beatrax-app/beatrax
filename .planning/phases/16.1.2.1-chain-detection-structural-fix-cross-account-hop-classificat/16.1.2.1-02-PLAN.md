<objective>
Close Gap 2 from the ROADMAP goal: extend `PaypalCsvEventTypeMap` so PayPal funding-leg parent event types (`Bankstorting`, `General Withdrawal`, `Transfer to bank`) produce `transfer_in` on the PayPal account.

Purpose: The PayPal-side leg of an ASN→PayPal funding hop currently ends as `expense` because the parent-event-type map only carries the two purchase strings. As a result, `PaypalFundingResolver::resolveForUser()` finds no PayPal-side candidate row to chain back to the ASN side. Adding the funding-leg mappings restores the input the resolver expects (`transactions.type='transfer_in'` on the `paypal`-kind account).

Output: An extended `PaypalCsvEventTypeMap` with both `MAP` (action vocabulary: `parent` / `child-fee` / `child-fx` / `skip`) and `TRANSACTION_TYPE` (Transaction::TYPES enum value) entries for every funding-leg event type; unit test coverage for every new entry; a feature test that drives a synthetic PayPal CSV containing a funding-leg parent row through the existing import pipeline and asserts the resulting `transactions.type` is `transfer_in`.
</objective>

- `classify()` throws `UnknownPaypalEventTypeException` when the `MAP` lookup fails (no entry for the event type at all).
- `transactionType()` throws `MissingPaypalTransactionTypeMapException` (extends `UnknownPaypalEventTypeException`) when the event type is mapped in `MAP` but has no matching `TRANSACTION_TYPE` entry — i.e. the class knows the event type's classification family but cannot turn it into a Transaction::TYPES enum value.
