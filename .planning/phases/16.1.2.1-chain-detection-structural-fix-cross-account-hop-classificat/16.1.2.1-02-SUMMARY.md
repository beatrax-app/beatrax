## Decisions Made

- **Distinct event-type literals stay distinct.** The standalone `Bankstorting` PayPal event is a different string from the localised `Bankstorting naar PP-rekening` child-fee event. The plan was explicit on this point; the new entries augment the map rather than overwriting the existing child entry. Confirmed by a dedicated regression `it(...)` case.
- **Feature test drives the adapter, not just the classifier.** The rollup walker calls `PaypalCsvEventTypeMap::classify()` on every row in Pass 1 — a missing MAP entry for a funding-leg parent would surface as `UnknownPaypalEventTypeException` at parse time, BEFORE the classifier ever runs. Driving the adapter therefore exercises BOTH call sites in a single test run.
- **No counterparty IBAN in the fixture.** The empirical NL `Bankstorting` row leaves the `Bankrekening` cell empty (the funding-source IBAN flows through the chain-resolver from a separate event memo, not the row's own counterparty cell). The fixture preserves that shape, and a dedicated `it(...)` case asserts `counterpartyIban === null` on the canonical row to lock the contract that the typing comes purely from the event-type map.

## Deviations from Plan

None — plan executed exactly as written. The plan named the Type column `Type` in its action-step prose, but the existing PayPal CSV adapter uses `Omschrijving` (the NL header) as the event-type column. The feature-test fixture uses the actual NL header set verified against the existing `paypal-sample-1.csv` regression fixture, which is the only correct interpretation. The plan's interfaces section already pointed at this (it referenced the existing `PaypalCsvAdapterTest` for the header pattern), so no deviation rule applies.

## Issues Encountered

- **Worktree vendor symlink fooled the autoloader.** The worktree initially had no `vendor/` directory (gitignored). Symlinking from the main repo caused PHP's `__FILE__` to resolve to the main repo's path, so `composer/autoload_classmap.php` baseDir pointed at the main repo and the test runner edited the wrong copy of `PaypalCsvEventTypeMap.php`. Resolved by running `composer install` inside the worktree to materialise a fresh `vendor/` tree whose autoload paths anchor to the worktree root. No production code affected; only the worktree's local test infrastructure.
- **PHPStan parallel workers ignore CLI `-d memory_limit=`.** The Homebrew `php.ini` defaults to `memory_limit=128M`; PHPStan spawns child workers inheriting that ini and the analysis hits OOM on Modules/Ingestion. Resolved per-invocation by running `phpstan analyse --debug` (single-process mode, inherits the CLI flag) instead of the default parallel scheduler. Not a project change; a Homebrew-PHP environment quirk. The CI matrix in Phase 17 will pin a higher `memory_limit` so this is invisible in CI.
