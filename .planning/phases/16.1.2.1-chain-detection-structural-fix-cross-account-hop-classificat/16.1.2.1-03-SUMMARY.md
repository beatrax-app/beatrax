## Decisions Made

- **Option A listener pattern** (User lookup in the listener, not in the seeder) — Listener resolves `User::query()->findOrFail($event->userId)` and the seeder signature stays `run(User $user)`. A future plan that wants to call the seeder programmatically from a CLI / refresh path can pass the User directly without a faked event payload.
- **`firstOrCreate` over `updateOrCreate`** — preserves the `notes` column on re-runs. A new test (seeder test 3) explicitly locks this against a refactor regression.
- **Explicit `where('user_id', $userId)` filter** is load-bearing inside the resolver, not redundant — the `BelongsToUser` global scope fires only under an HTTP-bound authenticated context. Resolver test 6 locks the invariant against a refactor that might delete the explicit filter on the assumption the global scope alone is enough.
- **Returns the full Account model** from the contract, not just an `account_id` — Plan 04's `ClassifyTransactionType` consults `kind` to decide the retype direction, and `PairTransferCandidates` needs the `id` for partner-account lookup. Returning the model collapses two cross-module queries into one.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Replaced `select(['target_account_kind'])->first()` with `value('target_account_kind')` in resolver**
- **Found during:** Task 1 (Larastan L10 strict)
- **Issue:** Larastan rejected the inline `@var object{target_account_kind: string}|null` PHPDoc as "not a subtype of stdClass|null" — the query builder's `->first()` returns `stdClass|null` and the structural type override violated `phpstan-strict-rules`.
- **Fix:** Switched to `->value('target_account_kind')` which returns the column value directly (`mixed`) and added a `is_string($alias) && $alias !== ''` guard before passing it into the next query.
- **Files modified:** `Modules/Import/Internal/Services/KnownCounterpartyIbanResolver.php`
- **Verification:** Larastan L10 strict — 0 errors on `Modules/Import`.
- **Committed in:** `a222bba` (Task 1 commit)

**2. [Rule 3 - Blocking] Test bootstrap helpers needed `app(...)` global helper instead of `test()->app->make(...)`**
- **Found during:** Task 3 (initial Pest run)
- **Issue:** The `seedUserWithAccounts` helper is defined at file scope (not inside `it()`/`beforeEach`); inside a free function, `test()->app` is inaccessible because `$app` is `protected` on the test case.
- **Fix:** Use `app(DefaultKnownCounterpartyIbansSeeder::class)` and `app(ResolvesKnownCounterpartyIban::class)` — the global helper is allowed in tests (other module tests under `Modules/Categorization/tests/Unit/MerchantMemoryQueryBatchTest.php` use the same idiom).
- **Files modified:** `Modules/Import/tests/Unit/KnownCounterpartyIbanResolverTest.php`, `Modules/Import/tests/Unit/DefaultKnownCounterpartyIbansSeederTest.php`
