## Listener pattern — Option A

The `UserInstalled` event carries `int $userId` (not a `User` model). The Categorization rule seeder is per-user (`RuleEvaluator` scopes by `where('user_id', $userId)` with no NULL fallback). The listener resolves the User from the event's id:

```php
public function handle(UserInstalled $event): void
{
    $user = User::query()->findOrFail($event->userId);
    $this->seeder->run($user);
}
```

This keeps the seeder's signature as `run(User $user)` — matching the per-user seeder convention — while leaving the legacy global `DefaultCategoryTreeSeeder::run()` listener template (which calls `$this->seeder->run()` with no arguments) untouched. Plan 03's `SeedDefaultKnownCounterpartyIbans` will adopt the same Option-A pattern for consistency. `findOrFail` is intentional: a `UserInstalled` event referencing an unknown userId throws `ModelNotFoundException` and aborts the install loudly — the correct failure mode for a Core-module bug.

## firstOrCreate semantics lock

The unit test mutates a seeded row's `hits_count` to `42` and `active` to `false`, then re-runs the seeder, then asserts both values survived. A future refactor that swapped `firstOrCreate` → `updateOrCreate` would reset `hits_count` to 0 (erasing real usage data) and re-enable a user-disabled rule. The assertion catches that regression at PR-gate time.

## Deviations from plan

### Auto-fixed during execution

**1. [Rule 1 — Test bug] Live-distribution fixture rows collapsed to one persisted transaction under RecordTransactions' fingerprint UNIQUE.**

- **Found during:** Task 3 first test run.
- **Issue:** All 200 canonical rows built with identical `posted_at`/`amount_minor`/`counterparty` produced the same fingerprint hash; only the first row per counterparty persisted, so the "persisted == categorised count" assertion failed (45 persisted vs 183 categorised).
- **Fix:** `buildCanonical()` now varies `bookedAt` (per-row minute offset) and `amountMinor` (per-row -1 cent delta) so each canonical row receives a unique fingerprint. Real ingestion paths produce these natural per-row variations automatically; the test fixture had to simulate them.
- **Files modified:** `Modules/Categorization/tests/Feature/SeedRulesEndToEndCategorizationTest.php` (within the same Task 3 commit).
- **Commit:** `8372bdd`.

**2. [Rule 3 — Blocking infra workaround] PHPStan parallel-worker memory exhaustion inside worktree.**

- **Found during:** First Task 1 verification run.
- **Issue:** The PHPStan parent process accepts `--memory-limit=2G` but spawns parallel workers that re-read the default `php.ini` `memory_limit=128M`, which is insufficient to load the 18MB `vendor/composer/autoload_static.php` from inside the worktree path. Identical setup in the main repo runs cleanly — likely a worktree path-length effect on the worker process's realpath / opcache fingerprint.
- **Fix:** Invoke PHPStan with `--debug` (forces serial execution), which avoids the worker fork. Result: `[OK] No errors` on `Modules/Categorization`.
- **Out-of-scope notice:** Logged in `deferred-items.md` for the phase — pre-existing worktree-only infrastructure concern, not a defect introduced by this plan.

### Out of scope — logged, not fixed

- 4 `TriagePageTest` Livewire view-render failures in the full `pest Modules/Categorization` run, all due to a missing `public/build/manifest.json` in the worktree. The worktree never built Vite assets and `public/build` is gitignored. Verified the same tests pass in the main repo. Logged in `deferred-items.md`.
