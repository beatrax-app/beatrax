<objective>
Build the foundation that closes Gap 1 from the ROADMAP goal: a per-user `known_counterparty_ibans` table that maps real institution IBANs to the user's own synthetic-IBAN account kind, and a Public contract `ResolvesKnownCounterpartyIban` that two downstream consumers (Plan 04's `ClassifyTransactionType` + `PairTransferCandidates`, Plan 05's `IcsSettlementResolver` rewire) depend on without reaching into `Modules\Import\Internal\*`.

Purpose: The user's PayPal account uses synthetic IBAN `'PAYPAL'` and the ICS card account uses `'ICS-CARD'` (intentional — those wallets have no real IBAN per row). The ASN side ALWAYS reports the institution's real IBAN (`LU89751000135104200E` for PayPal Luxembourg, `NL08ABNA0526650664` for ICS at ABN AMRO). Without an alias bridge, neither `ClassifyTransactionType::run()` step 2 nor `PairTransferCandidates::handle()` partner-account lookup can map the real IBAN to the user's synthetic-IBAN account, so cross-account hops stay typed `expense` and never pair. This plan establishes the single source of truth that both consumers (and Plan 05's resolver rewire) call into.

Output: A new migration + Eloquent model + idempotent per-user seeder + UserInstalled listener + Public contract + concrete resolver implementation + service-provider bindings + unit-test coverage that locks the contract behavior and per-user scoping. This plan does NOT wire the consumers — Plan 04 wires the classifier + pair-listener consults, Plan 05 wires the IcsSettlementResolver rewire.
</objective>
