# Phase 9 — UI Design Contract

> Visual and interaction contract for Phase 9: Subscription Drift Detection + Alerts. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope (UI surfaces produced):**

1. **`/drift` top-nav page** (D-928 resolved: top-level route, NOT `/recurring/drift`) — the dedicated alerts surface. Sections in render order: page heading + subheading + global-threshold helper link top-right; three tabs (`Open` default / `History` / `Dismissed`); (when zero open alerts in Open tab) the empty-state hero; (when ≥1 open alert) the alerts list, sorted `detected_at DESC` with rows that share a `recurring_series_id` collapsed under a single group header carrying the series name + a stacked-count chip ("3 drifts open") + a bulk `Acknowledge all`. Each per-alert row carries direction-aware copy, annualized impact, the inline "Cancel this → save €X/yr" hint, and three actions: `Acknowledge` / `Snooze` (popover identical to Phase 8 D-810) / `I cancelled this`.
2. **Per-series threshold override editor (inline on `/drift`)** (D-915) — appears at the top of each grouped-by-series header as a small text-link `Threshold: ±5%` (slate, hover underline) that opens a 6-step radio popover (`±1% / ±2% / ±5% / ±10% / ±25% / ±50% / Use global default`). Same posture as the `/uncategorized` per-row category picker. Saves on click; closes popover; flashes `Threshold updated.` inline (3s).
3. **Per-series threshold override editor (on `/recurring/series/{seriesId}`)** (D-915 second placement) — the same editor mounted under the existing detail page header so the user can adjust threshold without an open alert. One row, single text-link trigger, same popover.
4. **`/settings` global-threshold field** (D-915 global) — new section appended to the existing settings page. Single `<select>` row "Default drift alert threshold" with the same six options as the per-series editor (minus "Use global default"). Default `±5%`. Help text below explains the override hierarchy.
5. **Dashboard "Drift alerts" tile** (REC-07 dashboard count badge) — new tile rendered alongside the existing "This month at a glance" + "Next ICS settlement" + "Fixed monthly payments" tiles. Calm count-only chrome: tile heading "Drift alerts" + tabular-nums count (`3`) + helper line `"open · ↗ €54/yr annualized impact"`. Wrapped in `<a href="{{ route('drift.index') }}">` so the whole tile clicks. Hidden entirely when `openDriftAlertsCount === 0`.
6. **Top-nav "Recurring" badge — secondary count chip** (D-927 resolution: secondary count on the existing Recurring slot, NOT a new "Drift" top-nav item) — the existing top-nav "Recurring" entry's badge becomes a compound `{pending_count}+{drift_count}` indicator when `driftOpenCount > 0`. Visual: when `recurringPendingCount > 0 AND driftOpenCount > 0`, render `[12] [3↗]` (two adjacent pills); when only one is non-zero, render the single existing pill chrome. See § Navigation Decision below for rationale + exact chrome.
7. **Acknowledge / Snooze / Dismiss-as-cancelled toast surface** — every action dispatches a 10-second Undo toast via `$this->dispatch('toast', ...)` inheriting Phase 4 / Phase 5 / Phase 8 chrome verbatim. Bottom-center, single line, single inline `[Undo]` action when applicable.
8. **"This series also flipped cadence" inline hint** (D-910 cross-surface coordination) — on any `/drift` row whose underlying series is in `state='cadence_changed'`, render a single line of meta text "Cadence flipped — also showing in /recurring/review" with the route as an inline text-link. Same pattern from the other direction: `/recurring/review` cadence-changed rows already render their own meta; Phase 9 does not modify that surface, only adds the reciprocal hint on `/drift`.

**Out of scope this phase:**

- Rich what-if-cancel modal / projection (Phase 10) — Phase 9 ships only the inline static `Cancel this → save €X/yr` text and the `CancellationImpactQuery` Public surface.
- Bulk acknowledge across series ("Acknowledge all open drifts everywhere") — deferred (per-series bulk acknowledge SHIPS via the group header; cross-series bulk is v2 power-user).
- Drift digest email / push notification — out of scope (PLT-01 localhost-only).
- Adaptive auto-threshold-loosen — v2.
- Drift backfill mode (retroactive evaluation against historical occurrences) — Phase 9 only fires on new occurrences after ship-date.
- Cross-series drift correlation ("Netflix and Disney+ both went up") — v2.
- Per-currency aggregate "your subscription spend changed by €X" dashboard line — could fit Wave 4 if budget allows; otherwise v2. UI-SPEC reserves the slot but does not promise it.
- Drift-alert tagging / custom user labels — v2.
- Coarser "snooze all future drift detection on this series for N months" — v2.
- Email-based auto-dismiss when a cancellation receipt arrives — v2 (Phase 7 hand-off).
- Dark mode.

## Navigation Decision (D-927)

**Decision:** Keep the nav flat at 9 items. Reuse the existing "Recurring" slot to surface drift signal as a **secondary count chip** rather than adding a 10th "Drift" top-nav item.

**Final top-nav order (left to right, unchanged from Phase 8):**

```
diederik   Dashboard   Transactions   Imports   Inboxes [N]   Uncategorized [N]   Rules   Review chains [N]   Recurring [N | N↗]   Settings
```

**Compound-badge chrome (Recurring slot):**

The existing pending-suggestion count pill stays. When `driftOpenCount > 0`, a second pill renders immediately to its right with the open-drift count + a small `↗` arrow glyph to distinguish it from the pending count. Chrome:

```
{{-- Single-pill (pending-only OR drift-only) — existing chrome --}}
<span class="inline-flex items-center justify-center rounded-full bg-slate-900 px-2 py-0.5 text-xs font-medium text-white"
      style="font-variant-numeric: tabular-nums;">{{ $count }}</span>

{{-- Compound (both non-zero) — pending pill + drift pill side-by-side --}}
<span class="inline-flex items-center gap-1">
    <span class="inline-flex items-center justify-center rounded-full bg-slate-900 px-2 py-0.5 text-xs font-medium text-white"
          style="font-variant-numeric: tabular-nums;"
          aria-label="{{ $pending }} pending recurring suggestions">{{ $pending }}</span>
    <span class="inline-flex items-center justify-center rounded-full bg-rose-50 px-2 py-0.5 text-xs font-medium text-rose-700"
          style="font-variant-numeric: tabular-nums;"
          aria-label="{{ $drift }} open drift alerts">{{ $drift }}<span class="ml-0.5" aria-hidden="true">↗</span></span>
</span>
```

**Rationale (why secondary chip, not new top-nav slot):**

1. **The bar already carries 9 items.** Phase 7 D-721 noted that an 11+ item bar starts to crowd; Phase 8 took the bar to 9 by replacing the planned "Recurring" + "Fixed payments" twin with a single "Recurring" entry. Adding a 10th item now spends the budget Phase 10 (`/forecast`) is going to want.
2. **The Recurring entry is the user's mental anchor for "subscription stuff."** A user investigating a drift will land on `/recurring` first to scan their approved series; `/drift` is a sibling view of the same domain, not a separate one. Co-locating the count badge with "Recurring" matches the user's mental model.
3. **Pending vs drift are visually distinguishable.** The pending pill stays `bg-slate-900` (slate, calm); the drift pill renders `bg-rose-50` + `text-rose-700` + `↗` glyph. The user immediately sees "Recurring has both pending suggestions AND drift alerts" without parsing labels.
4. **A separate "Drift" slot would compete with "Recurring" for the user's gaze.** Both surfaces concern the same mental category; splitting them across two top-nav items invites the user to context-switch needlessly.
5. **Phase 10 reservation.** A future "Forecast" item is already implied by the roadmap; spending the slot on "Drift" now would force re-pruning when Phase 10 lands. Better to fold Drift into Recurring.

**`/drift` is its own route.** The compound badge links to `/recurring` (because the user's intent when clicking "Recurring" is to see their series). The user reaches `/drift` via (a) the **dashboard tile**, (b) the in-context "View drift alert" link from `/recurring` rows that have an open drift (planner picks whether this row decoration ships in Wave 3 or defers), or (c) directly via URL / bookmark.

**Active-state behavior:** `/drift` activates a SEPARATE active state — it does NOT highlight the "Recurring" top-nav item. The active-state contract is: a top-nav anchor is active only when the user is on that anchor's exact route. `/drift` has no top-nav anchor of its own; therefore no top-nav item is highlighted while the user is on `/drift`. Page-level heading + breadcrumbs carry the location signal. This is an intentional consequence of the nav-flatness decision and matches `/recurring/review`'s active-state posture (also no separate top-nav item).

**Why not a "Drift" sub-route under `/recurring`?** Considered. `Modules/Recurring/Routes/web.php` already owns `/recurring`, `/recurring/review`, `/recurring/series/{id}`. Adding `/recurring/drift` would force the DriftAlerts module to either reach into Recurring's route file (boundary violation) or duplicate the routing chrome. Top-level `/drift` keeps the module-boundary clean (RESEARCH.md confirms — top-level matches the `/chains/review` precedent). The top-nav doesn't need its own slot just because the route is top-level.

**Direction-aware sign-color rules:**

- **Expense going UP (cost increased) → delta + annualized in `text-rose-700`** (sign is `+`, color signals "you're paying more")
- **Expense going DOWN (cost decreased) → delta + annualized in `text-emerald-700`** (sign is `−`, color signals "you're paying less — calm-positive")
- **Income going UP (you're receiving more) → delta + annualized in `text-emerald-700`** (sign is `+`, color signals "calm-positive")
- **Income going DOWN (you're receiving less) → delta + annualized in `text-rose-700`** (sign is `−`, color signals "you're earning less")

The icon glyph mirrors the sign: `↗` (arrow-trending-up) for positive delta in either direction; `↘` (arrow-trending-down) for negative delta. The icon's color matches the delta's color so the row reads holistically.

Inherited 60/30/10 palette from `07-UI-SPEC.md`. **No new accent colors.** Phase 9 introduces one new directional-semantic application of existing tokens (rose + emerald as drift-direction signals on the per-row delta amount only — see § Direction-aware sign-color rules above) which is consistent with Phase 4's transfer-vs-income directional cue precedent.

| Role | Value | Usage in Phase 9 |
|------|-------|-------------------|
| Dominant (60%) | `bg-white` + `text-slate-900` body | `/drift` page background; alert row cards; dashboard tile background; threshold-editor popover background; snooze popover background |
| Secondary (30%) | `bg-slate-50` + `border-slate-200` + `text-slate-500` meta | Grouped-by-series header card background; empty-state hero card; tab-bar bottom border; meta-line text under each alert row; toast container border; threshold-editor radio hover state (`hover:bg-slate-50`) |

| Destructive / drift-up signal | `text-rose-700` + `bg-rose-50` | The delta + annualized impact text on (a) expense-going-up alerts, (b) income-going-down alerts; the secondary-count drift pill on the top-nav `Recurring` slot (`bg-rose-50 text-rose-700`); `I cancelled this` action chip uses the slate posture (it's not destructive — it's an intent recording); error-toast tint when an action fails |

**Accent reserved for** (explicit list — Phase 9 introduces zero new accent uses):

- Threshold-editor `Save` button
- `Default drift alert threshold` `Save` button on `/settings`
- `Acknowledge` action chip when rendered with primary posture (one variant per row — see § Action-chip posture below)
- (Inherited) primary CTAs across `/uncategorized`, `/chains/review`, `/recurring/review`, `/settings`, `/inboxes`, `/rules`

**Accent is NEVER applied to:**

- Group header `Acknowledge all` (uses slate `bg-slate-100`)
- `Snooze` action chip (uses slate `bg-slate-100` — secondary action)
- `I cancelled this` action chip (uses slate `bg-slate-100` — intent-recording, not destructive)
- Tab bar (uses slate-200 underline + slate-900 active text)
- Threshold pill text-link trigger (uses slate `text-slate-500 hover:text-slate-700`)
- Dashboard tile heading or count (uses slate)
- Top-nav drift pill (uses rose-50 + rose-700, NOT emerald — the user shouldn't read drift alerts as "good news to celebrate")
- Toast Undo action (uses slate text-link `text-slate-900 hover:underline`)
- EUR-shadow amounts (uses `text-slate-400`)

**Direction-aware sign-color rules** (locked above in § Typography — repeated here for color-section completeness):

- Expense ↑ / Income ↓ → `text-rose-700` on the delta + annualized + icon
- Expense ↓ / Income ↑ → `text-emerald-700` on the delta + annualized + icon

**Why is the directional cue acceptable under the 60/30/10 rule?** Rose and emerald appear here as **content semantics** (the delta IS the alert content, not chrome around it). The chrome (card border, card background, padding, action chips, group header, tab bar) stays slate/white/emerald-accent per the inherited rules. The user's eye reads the row as: calm slate chrome → directional semantic on the data → emerald-accent on the primary action. The same rule governs Phase 8 D-841 (status badges use semantic tints) and Phase 6's status badge matrix. Phase 9 does not invent a new convention; it applies the existing convention to drift deltas.

**Cross-tab color states (Open / History / Dismissed):**

- Open: full chrome with directional tints active.
- History (acknowledged): full chrome but the delta text and icon dim to `text-slate-500` (the data is no longer urgent — historical record).
- Dismissed (cancelled): full chrome with the delta text and icon in `text-slate-400` AND a strikethrough on the series name (`line-through decoration-slate-400`) so the visual signal "this series is cancelled in your mind" reads at a glance.

**Tabular-numerals + numeric formatting rules** (inherited from Phase 3/5/6/7/8):

- Every amount: `font-variant-numeric: tabular-nums`.
- Every percentage on the alert row or popover: `font-variant-numeric: tabular-nums`.
- Every count: `font-variant-numeric: tabular-nums`.
- Every date: `font-variant-numeric: tabular-nums`.
- EUR amounts format in nl_NL locale (`€ 1,50`); non-EUR in en_US locale (`$1.50`) — matches the inherited Money formatter routing (Phase 3 D-46).

## Action-chip posture rule

Within a single group (or within a single alert when ungrouped), exactly **one** chip carries the emerald-600 primary posture: the leftmost meaningful action.

| Group state | Acknowledge posture | Snooze posture | Dismiss posture |
|-------------|---------------------|----------------|-----------------|
| Group with 1 open alert | Primary (emerald-600) | Secondary (slate) | Secondary (slate) |
| Group with 2+ open alerts | Per-row Acknowledge is Secondary (slate); the group-header `Acknowledge all` is Primary (emerald-600) | Secondary | Secondary |
| History tab row (already acknowledged) | (no chip — row is read-only) | (no chip) | (no chip) |
| Dismissed tab row | (no chip — row is read-only) | (no chip) | (no chip) |

This rule prevents "five emerald buttons stacked in a row" visual noise that Phase 5 D-104 + Phase 8 D-825 both warned about. Within any group, exactly one focal action.

## Interaction Contracts

### `/drift` page lifecycle

1. **Mount** — `DriftPage::mount(CurrentUser $currentUser, DriftAlertQuery $query)` reads:
   - `$openAlerts = $query->openForUser($currentUser->user(), cursor: null, limit: 50)` (cursor-paginated by `(detected_at DESC, id DESC)`).
   - `$groupedAlerts = $query->groupedBySeriesForUser($currentUser->user())` (array<seriesId, list<DriftAlertDto>>).
   - `$historyAlerts = $query->historyForUser(...)` lazy-loaded on tab click.
   - `$dismissedAlerts` lazy-loaded on tab click.
   - Sort: `detected_at DESC` for the flat list; groups appear in the order of their newest alert.
2. **Tab switching** — `wire:click="setTab('history')"` flips `$tab` and lazy-loads the relevant collection. `#[Url(as: 'tab', except: 'open')]` so the URL reflects state for shareability + back-button correctness.
3. **Group header click (chevron-down icon)** — Alpine `x-data="{ open: false }"` per group; click toggles `open`. First click expands; second click collapses. Default state is collapsed for groups with 3+ alerts, expanded for groups with 1-2 alerts (to reduce required clicks on the common case).
4. **Per-alert Acknowledge click** — `wire:click="acknowledge({{ $alert->id }})"` invokes `AcknowledgeDriftAlert` Public Action. On success, removes the row from `$openAlerts` (Livewire re-render), dispatches `toast` event with body `Acknowledged.` + Undo button. Undo invokes a reverse-action that re-opens the alert.
5. **Group-header Acknowledge all click** — `wire:click="bulkAcknowledge({{ $seriesId }})"` invokes `AcknowledgeDriftAlert` per alert ID in a single Livewire request. Toast body: `Acknowledged {N} alerts for {series_name}.` Undo re-opens all N.
6. **Snooze chip click** — Opens the Phase 8 D-810 popover (Alpine `x-data="{ open: false }"`). Click on `1 week` / `1 month` / `3 months` / `Custom…` dispatches the date; `wire:click="snooze({{ $alert->id }}, '{{ $until_iso }}')"` invokes `SnoozeDriftAlert`. On success, removes the row, dispatches toast `Snoozed until {d M Y}.` + Undo.
7. **I cancelled this chip click** — Sets `$confirmingDismissalForAlertId = $alert->id`. The row re-renders with the two-step confirm UI in place of the three action chips. Esc clears `$confirmingDismissalForAlertId`.
8. **Yes, I cancelled it click** — `wire:click="dismissAsCancelled({{ $alert->id }})"` invokes `DismissDriftAlertAsCancelled` Public Action. On success, dispatches `DriftAlertDismissedCancelled` event (Phase 10 listens), removes row, toast `Marked as cancelled.` + Undo.
9. **Threshold-editor text-link click (on group header)** — Opens the threshold-editor popover (Livewire-rendered, `wire:model.live` on the radio). Selecting a value dispatches `wire:click="saveThreshold({{ $seriesId }}, {{ $percent }})"` (or `null` for "Use global default"). Calls a new Recurring-side Public Action `SetSeriesDriftThreshold` (NOTE: this action lives in `Modules/Recurring/Public/Actions/` because the column it writes is on `recurring_series` — DriftAlerts MUST NOT write to Recurring's table per D-902 invariant 2). On success, popover closes; flashes `Threshold updated.` inline above the group; full alerts list refreshes (the new threshold may immediately retire some pending future evaluations).
10. **wire:poll** — `wire:poll.30s="refreshOpenCount"` on the count-badge cell in the tab bar header only — NOT on the full table (avoids interaction races during snooze popover or threshold edit). The poll re-queries `$query->openCountForUser($user)`. If the count diverged from the local list length, a subtle inline cue `(new alerts available — refresh)` appears between the tab bar and the alerts list with a `[Refresh]` button. Click reloads the list.
11. **Loading skeleton** — None on first paint (server-rendered Blade). Loading state on action click is the standard `wire:loading.attr="disabled"` posture on the clicked chip.

### Threshold editor lifecycle (per-series variant)

1. **Mount** — `ThresholdEditorPopover::mount(int $seriesId, ?int $currentOverride, int $globalDefault)` opens with the radio set to the matching option (or "Use global default" if `$currentOverride === null`).
2. **Radio click** — `wire:model.live="selected"` updates the displayed selection.
3. **Save click** — `wire:click="save"` calls `SetSeriesDriftThreshold::execute($currentUser, $seriesId, $this->selected === 'global' ? null : $this->selected)`. On success, dispatches `threshold-editor:saved` event; popover closes via `modal-hide`-style Alpine dispatch; parent `DriftPage` re-renders the affected group header's threshold text.
4. **Cancel click** — Closes popover without save; no state change.
5. **Validation** — Server-side validates `selected ∈ {null, 1, 2, 5, 10, 25, 50}`; non-matching values reject with `Threshold must be one of the available options.` (defensive — UI prevents but server validates).

### Dashboard tile lifecycle

1. **Mount** — `DashboardDriftBadge::mount(CurrentUser $currentUser, DriftAlertQuery $query, AnnualizedImpactSummaryQuery $summary)` queries the open count + sum of `annualized_impact_minor` across all open alerts (in EUR, via the per-alert FX shadow values).
2. **Render** — When count is 0, the SFC renders nothing (no chrome). When count is ≥1, renders the tile with heading + count + helper line.
3. **Click** — The entire tile is wrapped in `<a href="{{ route('drift.index') }}">` → navigates to `/drift`.
4. **wire:poll** — None on the tile itself (the page-level dashboard already polls; the tile re-renders when the dashboard does).

### `/settings` integration

1. **Mount** — `SettingsPage::mount()` extension reads `$user->drift_alert_threshold_percent` (default 5 from migration).
2. **Change** — Bound via `wire:model="driftAlertThresholdPercent"` on a `<select>` (NOT instant-apply — joined with the existing `Save settings` button).
3. **Save** — On `Save settings` click, persists alongside other settings fields. Inherits existing settings-page Save UX.
4. **Scroll-to from `/drift`** — `/drift`'s "Adjust threshold →" link uses `#drift-threshold` fragment; the new `<section id="drift-threshold">` carries the anchor target.

### `/drift` page

## Multi-currency rules (D-918)

Every per-alert amount renders with original-currency primary + EUR shadow when the original currency is not EUR:

```
+$1.50/mo  →  +$18/yr    (≈ +€16.80/mo  →  +€201.60/yr)
└─ rose-700 primary       └─ slate-400 shadow, parenthesised
```

**Tile sum (`Drift alerts` dashboard tile helper line):** ALWAYS rolls up to EUR. When alerts span multiple currencies, the headline shows `↗ €{sum_eur} annualized impact` using each alert's stored `fx_rate` at detection time (per LED-03). No mixed-currency primary on the tile — the dashboard chrome insists on a single comparable headline.

**Cancel-this hint inline link copy:** Always in the series's `latest_currency`. EUR shadow only on the alert primary line, not on the cancel-hint (otherwise the row gets visually noisy).

**Edge case — currency switch mid-series:** Phase 8 D-839 creates two distinct series when currency flips. Phase 9 renders them as separate alerts (each in its own currency) — no cross-series merging.

- **Drift-alert tagging / custom user labels** — Deferred to v2.
- **Push / email digest notifications** — Out of scope (PLT-01 localhost-only).
- **Adaptive auto-loosen threshold on volatile series** — Deferred to v2.

- **Top-nav "Drift" standalone slot** — Declined for v1 (compound badge on Recurring slot). Re-evaluation trigger: if Phase 10's "Forecast" item lands AND the secondary chip pattern starts feeling cramped, revisit then.
