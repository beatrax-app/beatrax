RuleEvaluator scoring (D-711):
  - equals match on field === value (case-insensitive): score = 100
  - merchant_memories row for this merchant_id: score = 90
  - starts_with: score = 50 + len(value)
  - contains: score = 10 + len(value)
  - Highest score wins. Tiebreaker: rule beats memory.

MerchantMemoryWriter triggers on TransactionCategorized (existing Phase 1 event). Upserts merchant_memories (user_id, merchant_id, category_id) with occurrence_count+1 + last_seen_at. The unique constraint (user_id, merchant_id, category_id) on the existing table makes the upsert idempotent.

ApplyEnrichments extension: detects a true field-value conflict (when enrichment would OVERWRITE an existing non-null transactions.<field> value with a DIFFERENT non-null value). If users.receipt_conflict_resolution === 'unset':
  1. INSERT pending_enrichment_conflicts row (user_id, transaction_id, field_name, stored_value, incoming_value, incoming_source_format, import_run_id).
  2. Dispatch ReceiptConflictDetected event.
  3. Skip the per-field write (the policy will be applied when ApplyReceiptConflictResolution runs).
Otherwise (setting is 'prefer_receipt' | 'prefer_first_write'): apply the policy silently per-field, no event.

ApplyReceiptConflictResolution Public action:
  __invoke(User $user, string $choice): int
    - Validate $choice in {'prefer_receipt', 'prefer_first_write'} (whitelist).
    - UPDATE users.receipt_conflict_resolution = $choice (raw query builder).
    - For every pending_enrichment_conflicts row for this user, apply the chosen policy: update transactions.<field_name> = (incoming_value if 'prefer_receipt' else keep stored_value), then DELETE the pending row.
    - Return count of resolved conflicts.
