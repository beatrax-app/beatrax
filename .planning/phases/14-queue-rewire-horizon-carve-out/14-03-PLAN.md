Output: Modified `HorizonServiceProvider`, `bootstrap/providers.php`, `composer.json`/`composer.lock`, an extended `BoundaryArchTest`, and two new tests (SC3 + SC4).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| shipped build → /horizon route | The Horizon dashboard serializes queue payloads (transaction data); whether it registers is the boundary that keeps the partner from reaching it |
| autoload → require-dev classes | A `--no-dev` install lacks Horizon classes; an unconditional provider reference crosses into a class that does not exist |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-03-01 | Information Disclosure | `/horizon` dashboard in a shipped build | mitigate | `boot()` early-exits on `config('app.dev_mode') !== true` so dashboard routes/assets never register; `laravel/horizon` is `require-dev` so the route code is not even shipped — defense beyond the existing Fortify auth gate |
| T-14-03-02 | Denial of Service | unconditional `HorizonServiceProvider` registration | mitigate | `class_exists()` guard in `bootstrap/providers.php` prevents a fatal `Class not found` at autoload in a `--no-dev` tree, which would otherwise crash every request and artisan call |
| T-14-03-03 | Elevation of Privilege | `DIEDERIK_DEV_MODE` accidentally truthy in a shipped `.env` | accept | Out of scope here — the `(bool)` cast + fail-closed `false` default land in Plan 01; shipping `.env.bundled` with the key absent/false is a Phase 17 (CI-06) concern. Noted, not mitigated in this phase |
| T-14-03-04 | Tampering | future code re-importing `Laravel\Horizon\*` into shipped code | mitigate | `noHorizonImportsInShippedBuildCode` arch invariant fails the build if any non-allow-listed file references the Horizon namespace |
| T-14-03-SC | Tampering | composer dependency manipulation | mitigate | Task 2 relocates two already-present packages between `composer.json` sections — no new install, no registry fetch. RESEARCH Package Legitimacy Audit confirms zero new packages; no `[ASSUMED]`/`[SUS]` packages, so no blocking-human checkpoint applies |
