<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| queue dispatch → lock store | `ShouldBeUniqueUntilProcessing::uniqueVia()` decides whether a second concurrent dispatch is admitted; a fail-open lock admits a duplicate |
| job code → cache facade | Module job code crosses into the `Cache` facade; the DI-only rule confines that crossing to one file |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-02-01 | Tampering | `database` lock store under concurrent dispatch | mitigate | `Illuminate\Cache\DatabaseLock` provides atomic acquire with owner tokens; `LockStore::forUniqueJobs()` routes `uniqueVia()` to it; the SC2 test proves a duplicate dispatch is rejected before `handle()` and no duplicate `chain_resolution_runs` row is written |
| T-14-02-02 | Tampering | per-user lock key collision | mitigate | `uniqueId()` returns the `userId`, so the unique-lock key is partitioned per user — a partner's job cannot collide with the owner's; the SC2 test scopes its `chain_resolution_runs` count by `user_id` |
| T-14-02-03 | Repudiation / Integrity | DI-only boundary erosion | mitigate | `Cache` + `config()` use is confined to `LockStore`; `BoundaryArchTest`'s `no Laravel facade usage` invariant carve-out lists exactly that one file, so any new facade use elsewhere fails the build |
| T-14-02-04 | Information Disclosure | lock store fails open on missing `cache_locks` table | mitigate | Plan 01 (depends_on) creates `cache_locks`; the SC2 test runs against the real `database` store so a missing table surfaces as a hard test failure, not a silent uniqueness bypass |
| T-14-02-SC | Tampering | composer installs | mitigate | No package installs in this plan — it relocates existing config and code only. RESEARCH Package Legitimacy Audit confirms zero new packages |
</threat_model>
