## Decisions Made

- **Wrap appended CSS in a new `@layer components` block.** The existing `resources/css/app.css` puts every prior class rule inside an `@layer components` block; mirroring the convention keeps the cascade ordering consistent and avoids the appended rules accidentally winning over `@theme`-derived utilities.
- **Use Pest's `expect()->toMatch()`/`toContain()` rather than `assertSeeHtml()`.** The Vite-hashed path requires a regex match; staying in Pest's functional style for the whole test keeps the file homogeneous and reads cleanly against the analog `AppSidebarRenderTest.php`.

### Execution-environment note (not a code deviation)

The worktree spawn-time filesystem was missing `vendor/` and `node_modules/`. Initially symlinking the main repo's `vendor/` triggered a Composer autoload class-redeclaration conflict (because `vendor/composer/autoload_real.php` declares a class hashed from the absolute project root path, and the worktree's `__DIR__` resolves to a different absolute path through the symlink). Resolved by running a proper `composer install` inside the worktree (a worktree-local `vendor/` directory with autoload paths rooted at the worktree). `node_modules/` is safely symlinked from the main repo because Vite resolves modules relative to the project root, not absolute autoload-class identity. `vendor/`, `node_modules/`, and `public/build/` are all gitignored, so this environment setup leaves no committed artifacts. **No source-code change. No plan deviation. No Rule 1/2/3/4 trigger.**
