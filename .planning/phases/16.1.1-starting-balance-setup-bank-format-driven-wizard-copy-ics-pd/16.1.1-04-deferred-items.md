# 16.1.1-04 — Deferred items

Discoveries surfaced during execution that are out of plan-04 scope.

## 1. CorpusLoader cannot find Symfony YAML class in the built `.app` bundle

**Where:** `~/Library/Application Support/beatrax/storage/logs/laravel-2026-05-26.log` lines 1–2.

**Symptom:**
```
CorpusLoader: unexpected error reading YAML.
exception_class: Error
exception_message: Class "Symfony\Component\Yaml\Yaml" not found
paths: resources/corpus/merchant-mappings.yaml
       resources/corpus/built-in-heuristics.yaml
```

**Why deferred:** Unrelated to ICS PDF / PayPal CSV import. Looks like a Composer-classmap build-issue specific to the NativePHP `.app` bundle — the autoloader does not see `symfony/yaml` even though it is in the lock file. Either the `composer dump-autoload -o` step missed it, or NativePHP's bundling strips it. Needs a Phase 15 / Phase 16 followup to investigate the bundling pipeline.

## 2. Five Import-module Feature tests fail with `Vite manifest not found`

**Where:** Local CI runs of `vendor/bin/pest Modules/Import/tests/Feature/`. Failing tests:

- `Modules\Import\tests\Feature\AliasesSettingsPageTest::it renders /settings/aliases for an authenticated user with the first-run banner pinned`
- `Modules\Import\tests\Feature\PreviewWizardTest::it renders the canonical results summary on the results page`
- `Modules\Import\tests\Feature\UploadWizardPaypalTest::it renders the PayPal issuer option on the wizard page`
- `Modules\Import\tests\Feature\UploadWizardTest::it renders the calm upload form on GET /imports/new`
- `Modules\Import\tests\Feature\UploadWizardTest::it renders the two-step picker on the upload page`

**Symptom:** All five fail with `Vite manifest not found at: public/build/manifest.json`.

**Why deferred:** Pre-existing — verified by stashing plan-04 changes and re-running the same tests on the prior HEAD; they still fail. Caused by the missing `npm run build` artifact in the worktree. Either CI should run `npm run build` before pest, or these route-level tests should mock the Vite manifest. Out of plan-04 scope.

## 3. PayPal CSV — second-locale support

**Discovery:** The new `UnsupportedPaypalCsvShapeException` carves the BRR export out from the language-profile mismatch, but the underlying `UnsupportedPaypalCsvLanguageException` will still fire for any non-Dutch Activity Download. The PayPal portal exports in the account's locale; English / German / French users are blocked.

**Why deferred:** Plan 04 is reproduce-then-fix scoped to the user's reported failure. The non-Dutch surface is a known limitation already documented in the existing `HeaderSnifferPaypalTest::it rejects a CSV whose header tokens do not match any registered language profile` test. A second-language profile is a separate feature plan, not a regression fix.
