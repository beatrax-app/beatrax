<objective>
Diagnose and fix the "ICS PDF preview throws an error" failure the user reports on `ConnectCardStep`. RESEARCH.md Hook 8 narrows the failure to three candidate layers:
- **Layer (a) — Parser regression:** A regex / spatial-extraction change broke a downstream assumption in `IcsPdfAdapter::parse()` / `parseFourColumnSummary` / `parseTwoColumnLimitBlock`. The `NormalizeStage` raises, the pipeline catches the `Throwable` and emits an ERROR preview row.
- **Layer (b) — PaymentType CHECK trigger:** The Phase 16.1 `transactions.payment_type` enum CHECK trigger rejects rows where the `IcsPdfPaymentTypeHinter` returns `null` and the description-keyword fallback also produces `null`. NOTE: this fires at COMMIT, not at PREVIEW; layer (b) is more likely G9's commit-never-persists root cause than G4's preview-fails root cause.
- **Layer (c) — Livewire 4 upload regression in NativePHP runtime:** The temp file is uploaded but `hash_file('sha256', $localPath)` fails because the temp dir is unwritable in the bundled .app. Cross-references batch-7 Issue 4.

Purpose: Close UAT finding G4 per locked decision D-21. The plan is reproduce-first — Task 1 captures the actual reproduction; Task 2 applies the surgical fix at the identified layer; Task 3 writes the regression test using the fixture that surfaced the bug.

**Wave placement note (defensive coupling, intentional):** This plan runs in Wave 2 with `depends_on: ["16.1.1-06"]` because Plan 06's `ImportPipeline::preview()` signature extension (adding the optional `?BankCsvFormatHint $formatHint = null` parameter) ships first. - **layer (b) or (c) likely touches `ImportPipeline.php`** — this is where the dependency becomes load-bearing.

Since the layer is unknown until Task 1 runs, the planner conservatively serializes after Plan 06 in both cases. This avoids a re-plan if reproduction pins layer (b) or (c) and is documented as intentional rather than a mistake. See the `dependency_rationale` block in this plan's frontmatter for the full explanation.
