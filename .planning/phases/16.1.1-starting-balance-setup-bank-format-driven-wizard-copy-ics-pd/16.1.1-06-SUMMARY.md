## Decisions Made

- **Additive parameter, default null** — kept BankCsvFormatHint as a trailing optional parameter rather than a positional rewrite. Six existing call sites (PreviewWizard, UploadWizard, both connector steps, and three contract tests) compile unchanged. Trade-off vs. a dedicated `runCsvFromUpload(...)` method: chose additive because the format-hint applies to ANY future CSV adapter, not just bank CSVs, and a dedicated method would explode the contract surface.
- **Two-layer Pitfall 5 guard, not one** — Layer A (Livewire `rules()`) catches realistic browser-tampering attacks (Dev-Tools form-state edits) with a UX-friendly inline chip-row error. Layer B (`ImportPipeline::preview()` exception) catches programmatic misuse at the public contract boundary — important because `RunsImports` is a Public contract that other modules + tests can call directly. Both layers are independently tested.
- **Per-file try/catch in ConnectCardStep** — one malformed PDF in a batch of 3 logs and continues; the step crashes only when ALL files fail. Trade-off vs. fail-fast: chose continue because the user's intent is "import everything I dropped" — partial success + per-file chip feedback beats "your batch of 5 PDFs failed because file 3 was corrupt."
- **card_import_run_ids merged with array_values(array_unique(...))** — re-running submit (e.g., adding 2 more files later) preserves existing ids and appends new ones. Idempotent by construction.
