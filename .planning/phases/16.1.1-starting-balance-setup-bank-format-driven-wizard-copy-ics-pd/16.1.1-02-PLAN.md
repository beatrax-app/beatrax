<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Livewire dispatcher | The `oauth-client-wizard:open` event payload (`provider`, `inboxId?`) crosses the browser-to-server boundary on every dispatch. |
| Livewire event bus → OAuthClientWizardModal listener | Cross-component dispatch within the same Livewire page. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16.1.1-03 | Tampering | `oauth-client-wizard:open` event payload (provider field) | mitigate | OAuthClientWizardModal's `#[On('oauth-client-wizard:open')]` listener already validates `$provider` against a strict enum (`OAuthProvider::Gmail|Outlook`) before mount — no change required by this plan, but the planner asserts the existing guard is intact. A malicious dispatch with `provider: '../../etc/passwd'` would type-error at the enum cast and fail to mount the modal. |
| T-16.1.1-04 | Information disclosure | `oauth-client-wizard:open` event payload (inboxId field) | mitigate | OAuthClientWizardModal's listener user-scopes the inbox lookup (existing `InboxesPageReconnectParamTest` per RESEARCH.md Security Domain row). A `{inboxId: 999}` for an inbox owned by another user resolves to `null` via the `BelongsToUser` global scope on the `Inbox` Eloquent model. No new code path opened by this plan. |
| T-16.1.1-05 | Repudiation | Modal opens but action is unattributable | accept | OAuth flow itself emits its existing audit-log entries on successful connect (Phase 12 flow). This plan only relocates the modal mount point — no new auditable action introduced. |

No HIGH-severity threats. Plan is a layout-mount relocation; existing security guards on the underlying modal are unchanged.
</threat_model>
