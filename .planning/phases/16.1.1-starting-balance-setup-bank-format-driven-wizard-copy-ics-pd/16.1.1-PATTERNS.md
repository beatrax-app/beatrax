## Pattern Assignments

### 1. Migration — `add_starting_balance_to_accounts_table.php`

**Analog:** `Modules/Forecasting/Database/Migrations/2026_05_19_010005_add_forecast_columns_to_accounts.php`

**Why exact match:** The existing analog literally adds three nullable columns to the SAME `accounts` table — `forecast_min_buffer_minor` (bigInteger), `opening_balance_minor` (bigInteger), `opening_balance_as_of_date` (date). **Reuse its shape verbatim** — only the column names differ. The migration also documents the cross-module-owned-by-Forecasting-but-physically-in-Ledger pattern, which applies equally to a Ledger-owned starting-balance column add.

**Pattern: anonymous migration with container-resolved DatabaseManager** (lines 29–73):
```php
return new class extends Migration
{
    private ?DatabaseManager $resolvedDb = null;

    public function up(): void
    {
        $this->schema()->table('accounts', static function (Blueprint $table): void {
            $table->bigInteger('starting_balance_minor')->nullable()->after('default_currency');
            $table->date('starting_balance_date')->nullable()->after('starting_balance_minor');
        });
    }

    public function down(): void
    {
        $this->schema()->table('accounts', static function (Blueprint $table): void {
            $table->dropColumn(['starting_balance_minor', 'starting_balance_date']);
        });
    }

    private function schema(): Builder
    {
        return $this->db()->connection($this->getConnection())->getSchemaBuilder();
    }

    private function db(): DatabaseManager
    {
        if ($this->resolvedDb === null) {
            /** @var DatabaseManager $db */
            $db = Container::getInstance()->make(DatabaseManager::class);
            $this->resolvedDb = $db;
        }
        return $this->resolvedDb;
    }
};
```

**Naming conflict to flag for planner:** `accounts.opening_balance_minor` and `accounts.opening_balance_as_of_date` already exist (Forecasting's plan). Phase 16.1.1's columns are `starting_balance_minor` + `starting_balance_date` — different names, semantically distinct (Forecasting's columns are a manual fallback for PayPal-style accounts; Phase 16.1.1's are the auto-detected baseline). Both can coexist; the planner clarifies the distinction in PHPDocs.

```php

    'Modules\\Import\\Internal\\Parsers\\Asn\\AsnCamt053PaymentTypeHinter',
    'Modules\\Import\\Internal\\Parsers\\Asn\\AsnMt940PaymentTypeHinter',

    // ...
    foreach (self::PAYMENT_TYPE_HINTER_FQNS as $fqn) {
```

### 6. Aggregator service — `DetectStartingBalancesQuery`

**Analog:** `Modules/Import/Internal/Pipeline/Stages/PaymentTypeClassifierStage.php`

**Pattern: iterable injection + walk-and-rank loop** (lines 41–72):
```php
final class PaymentTypeClassifierStage
{
    /**
     * @param  iterable<PaymentTypeHinter>  $hinters
     */
    public function __construct(
        private readonly iterable $hinters,
    ) {}

    public function run(CanonicalTransaction $tx, User $user, string $sourceFormat): CanonicalTransaction
    {
        $winner = null;
        foreach ($this->hinters as $hinter) {
            $hint = $hinter->hint($tx, $sourceFormat);
            if ($hint === null) {
                continue;
            }
            if ($winner === null || $hint->confidence > $winner->confidence) {
                $winner = $hint;
            }
        }
        // ... default ...
    }
}
```

**Application to D-04 tie-break:** `DetectStartingBalancesQuery::collect(list<int> $importRunIds, User $user): array` walks the tagged detectors, merges their `list<StartingBalanceCandidate>` outputs grouped by `accountId`, then picks the winner per account using D-04 ordering: prefer canonical CAMT.053 → MT940; further tie-broken by earliest `openingBalanceDate`. RESEARCH.md `## Validation Architecture` row `G1 (D-04)` provides the asserted shape.

### 10. ConnectBankStep — `submit()` stash + format-hint extension

**Analog (current file, before this phase):** `Modules/Onboarding/Internal/Http/Livewire/Steps/ConnectBankStep.php` lines 123–159

**Pattern: validate → catch → log → dispatch** (lines 123–159, already in place; this phase ADDs stash + format-hint):
```php
public function submit(
    RunsImports $importer,
    CurrentUser $currentUser,
    LoggerInterface $logger,
    Application $app,
): void {
    $this->uploadError = null;
    $this->validate();

    if ($this->file === null) {
        return;
    }

    $user = $currentUser->user();
    $tmp = $this->file->getRealPath();
    $originalFilename = $this->sanitiseFilename($this->file->getClientOriginalName());

    try {
        $importer->runFromUpload($tmp, $this->selectedFormat, $user, $originalFilename);
    } catch (Throwable $e) {
        $logger->error('ConnectBankStep: import preview failed.', [
            'source_format' => $this->selectedFormat,
            'filename' => $originalFilename,
            'exception_class' => $e::class,
            'exception_message' => $e->getMessage(),
            'exception_trace' => SafeTrace::cap($e, $app->basePath()),
        ]);
        $this->uploadError = sprintf('Could not read this file (%s). The full error is in /dev/logs.', $e::class);
        return;
    }

    $this->dispatch('wizard.step.completed');
}
```

### 13. FirstImportStep — REWRITE with commit-everything (D-07 / D-08 / D-11)

**Analogs (composed):**

```php

$result = $this->db->connection()->transaction(function () use ($canonical, $enrichments, $importRun, $user): ImportConfirmResult {
    $recorderResult = ($this->recorder)($canonical, $user);
    $enrichedCount = ($this->applyEnrichments)($enrichments, $user);
    // ...
    $importRun->update([
        'inserted_count' => $recorderResult->inserted,
        'duplicate_count' => $totalDuplicates,
        'enriched_count' => $enrichedCount,
        'error_count' => $errorCount,
        'confirmed_at' => $this->clock->now(),
        'status' => 'confirmed',
    ]);
    return new ImportConfirmResult(/* ... */);
});

// Dispatch chain resolver post-commit — NEVER inside the transaction closure
```

**FirstImportStep `commit()` skeleton** (from RESEARCH.md lines 952–1006 — already worked out by researcher):
```php
public function commit(
    DatabaseManager $db,
    ConfirmsImports $confirmImport,
    CurrentUser $currentUser,
    Clock $clock,
    LoggerInterface $logger,
    Application $app,
): void {
    $this->commitError = null;
    $user = $currentUser->user();

    $importRunIds = $this->resolveImportRunIds($user);
    if ($importRunIds === []) {
        $this->commitError = 'Nothing to commit.';
        return;
    }

    try {
        $db->connection()->transaction(function () use ($importRunIds, $user, $confirmImport, $clock, $db): void {
            foreach ($importRunIds as $id) {
                ($confirmImport)($id, $user);
            }
            foreach ($this->balanceConfirmations as $accountId => $confirmation) {
                $db->connection()->table('accounts')
                    ->where('id', $accountId)
                    ->where('user_id', $user->id)
                    ->update([
                        'starting_balance_minor' => $confirmation['minor'],
                        'starting_balance_date' => $confirmation['date'],
                        'updated_at' => $clock->now()->toDateTimeString(),
                    ]);
            }
        });
    } catch (Throwable $e) {
        $logger->error('FirstImportStep: commit failed.', [
            'exception_class' => $e::class,
            'exception_message' => $e->getMessage(),
            'exception_trace' => SafeTrace::cap($e, $app->basePath()),
        ]);
        $this->commitError = sprintf("We couldn't commit your statements: %s. Nothing was changed.", $e->getMessage());
        return;
    }

    $this->dispatch('wizard.step.completed');
}
```

**RESEARCH.md Pitfall 2** documents a known gotcha: `ConfirmImport` dispatches `ResolveChainLinksJob` AFTER its inner transaction commits but BEFORE the outer transaction commits. The planner must either (a) refactor `ConfirmImport` to accept an optional `dispatchChain: bool = true` flag, or (b) document the gap. **Prefer (a).**
