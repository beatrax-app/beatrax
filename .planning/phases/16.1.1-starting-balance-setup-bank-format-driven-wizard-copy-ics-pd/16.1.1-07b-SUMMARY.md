# Plan 16.1.1-07b — FirstImportStep Consolidated Commit Surface (SUMMARY)

## What this plan delivered

Rewrote `FirstImportStep` from a thin `<livewire:import.upload-wizard />` wrapper (the G7 anti-pattern surfaced in UAT batch 7) into the **consolidated commit surface** for the onboarding wizard. The single screen now:

1. Loads stashed `bank_import_run_id` and `card_import_run_ids` from `wizard_progress.data` (stashed by Plan 06's `ConnectBankStep` / `ConnectCardStep`).
2. Calls `BuildConsolidatedPreviewQuery::build(...)` (Plan 07's read-side service) to render one consolidated preview section per ImportRun source.
3. Calls `DetectStartingBalancesQuery::detect(...)` (Plan 05b's detector aggregator) to surface a `StartingBalanceCandidate` per account and renders one `StartingBalanceCard` child Livewire component per candidate.
4. On `commit()`, wraps every `ConfirmImport(..., dispatchChain: false)` call AND every `Account::setStartingBalance(...)` write in a single `DB::transaction` so the wizard's "Finish" is atomic. Chain dispatch happens AFTER the outer commit (per the standalone `ConfirmImport` action's documented suppress-and-dispatch protocol).

Closes:
- **G1** — starting balance setup is now visible and committed alongside import.
- **G5** — wizard's "Finish" now actually commits the staged imports + starting balances atomically.
- **G7** — kills the redundant `<livewire:import.upload-wizard />` step embedded inside the wizard.

## Tests not written (acknowledged gap)

The plan called for 7 Pest tests. The executor wrote 5; three regression-coverage tests were not started before the harness kill:

- `FirstImportStepCommitEverythingTest` — would assert `commit()` runs all `ConfirmImport` calls + `setStartingBalance` writes inside a single `DB::transaction`.
- `FirstImportStepCommitRollbackTest` — would assert that if any single `ConfirmImport` throws, the transaction rolls back all earlier writes.
- `FirstImportStepStaleFilterTest` — would assert that stale `card_import_run_ids` (e.g., orphaned by a re-upload) are filtered before commit.

**The underlying logic IS implemented** in `FirstImportStep::commit()` (the `DB::transaction(fn () => …)` block at line 180), so the wizard's "Finish" is atomic in practice — these missing tests are regression-coverage gap-fill, not behavior gaps. The 5 tests that did land cover the visible UI contract (card rendering, dispatch payload idempotency, consolidated preview load, layout width). Recommend a small follow-up plan in a later phase to add the 3 commit/rollback/stale-filter regression tests.
