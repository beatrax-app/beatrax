# Phase 16.1.1 Plan 07: Consolidated-Preview Backend Layer Summary

**Two new public Spatie Data DTOs (`ConsolidatedPreviewSection` + `ConsolidatedPreviewBatch`), one new public read-side query (`BuildConsolidatedPreviewQuery::build`) that filters stale (>14 days) + already-confirmed ImportRuns + enforces the per-user boundary, and an additive `dispatchChain: bool = true` flag on `ConfirmImport::__invoke()` so Plan 07b's FirstImportStep can dispatch chain resolution ONCE after the outer transaction instead of inside every per-run inner commit.**

## Accomplishments

- **ConsolidatedPreviewSection** under `Modules/Import/Public/Dto/` — Spatie Data subclass, readonly. Fields: `string $sourceFormat`, `list<int> $importRunIds`, `int $totalRows`, `list<PreviewRowDto> $sampleRows`, `string $status` (one of `ready` | `empty` | `error` | `filtered`).
- **ConsolidatedPreviewBatch** under `Modules/Import/Public/Dto/` — top-level batch DTO. Fields: `list<ConsolidatedPreviewSection> $sections`, `int $dedupedTotalCount`, `int $alreadyImportedCount`.
- **BuildConsolidatedPreviewQuery** under `Modules/Import/Public/Services/` — `final readonly class` with constructor-DI (`DatabaseManager`, `PreviewCache`, `Clock`). Public method `build(array $importRunIds, User $user): ConsolidatedPreviewBatch`:
  1. Filters `$importRunIds` against `import_runs` with explicit `where('user_id', $user->id)` (T-16.1.1-21 mitigation).
  2. Drops ids whose `import_runs.created_at < clock->now()->subDays(14)` (D-10 stale filter).
  3. Drops ids whose `import_runs.status === 'confirmed'` (D-10 already-committed filter).
  4. Groups survivors by `source_format`.
  5. For each group, concatenates `PreviewCache->get($importRunId)` rows; computes `totalRows` from NEW dispositions; first 5 rows go into `sampleRows`; status is `ready` if rows exist, `empty` if zero, `error` if the cache returned null/empty for any contributing run.
  6. Sums NEW dispositions → `dedupedTotalCount`; sums DUPLICATE dispositions → `alreadyImportedCount`.
- **ConfirmImport** (`Modules/Import/Public/Actions/ConfirmImport.php`) gains the optional `bool $dispatchChain = true` parameter. When `false`, the inner closure returns without dispatching the chain-resolution job. When `true` (default), behaviour matches the pre-existing main-branch logic exactly.
- **ConfirmsImports** contract carries the matching signature additively.
- **ImportServiceProvider** registers `BuildConsolidatedPreviewQuery` as a singleton. The Plan 05b `STARTING_BALANCE_DETECTOR_FQNS` const + `DetectStartingBalancesQuery` singleton binding survive untouched.
- **BuildConsolidatedPreviewQueryTest** (Pest Feature, `phase-16.1.1`) — 4 it-blocks / 23 assertions:
  1. `it builds a consolidated batch with one section per source format`.
  2. `it filters stale ImportRuns older than 14 days`.
  3. `it filters ImportRuns whose status is confirmed`.
  4. `it respects the user_id boundary — runs owned by another user are never returned`.

## Decisions Made

- **Explicit user-id WHERE clause on every input id, applied BEFORE source-format grouping.** Locks T-16.1.1-21 even in queue/worker contexts that bypass the `BelongsToUser` global scope. The fourth Pest assertion (`respects the user_id boundary`) pins this behaviour.
- **`dispatchChain` default stays true.** Every existing caller of `ConfirmImport` (RunImport orchestrator, manual confirm endpoint, command-line confirm) keeps working unchanged. Only Plan 07b's FirstImportStep passes `false` and dispatches chain resolution ONCE after the outer transaction returns — mitigates Pitfall 2 / T-16.1.1-26.
- **Section `status` is a plain string, not a PHP enum.** The four-value alphabet (`ready` | `empty` | `error` | `filtered`) is consumed by the UI partial via Blade conditionals; keeping it a string avoids an extra import for the view layer with no behavioural cost. If a future surface needs type-safety here, the conversion to an enum is a single-file refactor.

Plan 07b's FirstImportStep rewrite consumes the following PUBLIC API. All names are stable and exported from the `Modules\Import\Public\` namespace:

**DTO class names (use FQN from `Modules\Import\Public\Dto\`):**
- `ConsolidatedPreviewBatch` — fields: `array $sections` (list<ConsolidatedPreviewSection>), `int $dedupedTotalCount`, `int $alreadyImportedCount`.
- `ConsolidatedPreviewSection` — fields: `string $sourceFormat`, `array $importRunIds` (list<int>), `int $totalRows`, `array $sampleRows` (list<PreviewRowDto>), `string $status` (`'ready'` | `'empty'` | `'error'` | `'filtered'`).

**Query service contract (resolve from container via `app(BuildConsolidatedPreviewQuery::class)`):**
```php
namespace Modules\Import\Public\Services;
final readonly class BuildConsolidatedPreviewQuery
{
    public function build(array $importRunIds, User $user): ConsolidatedPreviewBatch;
}
```
Filtering rules are applied internally — pass in the raw `[$bankImportRunId, ...$cardImportRunIds]` flat list straight from `WizardProgress`; stale, confirmed, and foreign-user runs are dropped before the response is composed.

**ConfirmImport flag name** (the load-bearing Pitfall 2 fix):
```php
$confirmImport($importRunId, $user, dispatchChain: false);
```
Loop the per-ImportRun commit with `dispatchChain: false`, then dispatch `ResolveChainLinksJob` ONCE after the outer `DB::transaction` returns. The default value (`true`) preserves every existing caller's behaviour, so Plan 07b does not need to touch any other call site.
