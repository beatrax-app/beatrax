# Phase 16.1.1 — UI Design Contract

> Visual and interaction contract for the UAT close-out of Phase 16.1: G1 starting-balance setup, G2 Dev Mode artisan popover fix, G3 bank-format-driven wizard copy, G4 ICS PDF preview fix, G5 app-chrome brand logo, G6 OAuth modal mount-once, G7+G8+G9 wizard upload→persist (consolidated preview + multi-PDF + commit-on-FirstImportStep).
>
> **Source-of-truth chain:**
> 1. `16.1-UI-SPEC.md` (parent, APPROVED 2026-05-25) — locks every primitive, token, copy block, color, spacing exception, and component this phase touches. This spec **does not re-litigate** any of it.
> 2. `Skill("sketch-findings-diederik")` — sketches 002–005 already won. This phase adds **zero** new sketch territory.
> 3. `16.1.1-CONTEXT.md` D-01 through D-22 — locks the user-facing decisions for this phase. Pre-populated below.
>
> **What this phase adds visually:** four surfaces.
>
> | Surface | What changes |
> |---------|--------------|
> | G3 — `ConnectBankStep` | Format chips become **clickable radio group**; helper copy / bank list / mini-tile sub-labels / drop-zone `accept` reskin from the active chip; CSV chip requires a follow-on `{ASN, ING}` chip before the drop zone unlocks. No new tokens; no new primitives — reuses `format-chip` + `drop-zone` + `mini-step` components shipped in 16.1. |
> | G5 — Authenticated app shell brand | The `.side-brand` row's text `b` glyph is replaced by the existing `resources/brand/logo.svg`. Same slot, same layout, same lockup (`<logo> beatrax v2.0.0-dev`). Pixel-locked size from the existing 24×24 logo box. |
> | G7+G8+G9 — `FirstImportStep` consolidated preview | The step body becomes a `wiz-card` (1120px max-width per parent UI-SPEC's documented exception) hosting (a) per-source preview sections that reuse the locked `.ptype-chip` + `.cat-chip` + `.desc-fallback` + `.funding-tag` patterns from `import-preview-and-categorization.md`, (b) one starting-balance confirm card per detected account, and (c) a single "Commit everything (N transactions) →" primary CTA in the standard `.wiz-actions` footer row. |
> | G1 — Starting-balance confirm card | A new card variant inside the consolidated preview surface. Reuses `.wiz-card` chrome at a 540px width (sibling to suggest-mapping modal width); composed entirely from existing tokens. |
>
> **What this phase does NOT add:**
> - No new theme tokens — every color, spacing, typography, radius, shadow, and ease resolves to the existing `@theme` block in `resources/css/app.css`.
> - No new icon library — keeps the inline unicode glyph convention from Phase 16 + 16.1.
> - No new modal pattern — G6 fixes a mount location, not a modal style.
> - No new wizard step — G1 confirm cards are a **section** appended to FirstImportStep (researcher's discretion call from CONTEXT.md `## Claude's Discretion`; section choice keeps the 6-step count and matches the consolidated-preview shape).
> - No destructive actions — D-08 commit failure shows a non-destructive error toast; rollback is automatic.

**Density rules (locked, all inherited from parent UI-SPEC):**

- **FirstImportStep `wiz-card` max-width** — relaxed to ~1120px per the parent's documented exception. The starting-balance confirm cards stack inside this 1120px container at 540px each (single-column on narrow viewports, two-column on ≥960px viewports — fluid).
- **Starting-balance confirm card** — width clamped to `min(540px, 100%)`; padding `16px 20px`; gap between cards 16px (`--space-4`).
- **Per-file chip list** (G8 multi-PDF queue) — chip padding `4px 10px`, gap `8px` (`--space-2`), wraps onto multiple rows.
- **Consolidated preview source sections** — each is a `<section>` with `margin-bottom: var(--space-12)`; the section header is a 13px / 600 / muted eyebrow ("From your bank statement", "From your ICS card statements", "From PayPal") spaced 16px above its mini-table.
- **G3 format chips re-skin** — when a chip is selected, the mini-step row's sub-labels swap; the drop-zone's lead, sublink, glyph, and accept attribute swap. No layout dimension changes; only inner text + glyph + accept attribute swap. Reuses the existing 10px grid gap + 14×12 mini-tile padding + 28×20 drop-zone padding.
- **G5 brand SVG** — fits the existing `.side-brand .logo` slot (24×24 with `border-radius: 6px`; SVG renders edge-to-edge inside the slot, no inner padding). The neighboring "beatrax" text and `v2.0.0-dev` chip do not shift.

**Exceptions:** None new. The two parent-UI-SPEC chip-padding exceptions (`.ptype-chip` 2×8, `.cat-chip` 3×8) and the drop-zone 28-vertical exception continue to apply; this phase does not introduce additional sub-4 exceptions.

## Typography

Inherits parent contract verbatim. Two weights only (regular 400 + semibold 600). Phase 16.1.1 declares no new sizes.

| Role | Size | Weight | Line Height | Usage in Phase 16.1.1 |
|------|------|--------|-------------|----------------------|

| Label / small body | 13px (`--text-sm`) | 400 | 1.5 | Starting-balance card meta-row ("NL18 ASNB · 4321"), per-file chip filename + size, source-section header ("From your bank statement") |
| Eyebrow | 12px (`--text-xs`) | 400 / 600 | normal | Starting-balance card eyebrow ("🧮 Starting balance · {account-short}"), per-source preview-section eyebrow, "Got it as:" label (existing), G3 CSV-bank-format helper copy when CSV is selected but no bank picked yet ("Pick which bank exported your CSV — we need to know to read it correctly.") |

| Heading — H1 (FirstImportStep) | 32px (`--text-3xl`) | 600 | 1.2 (`-0.02em` letter-spacing) | "Review everything we found" page H1 (the only H1 on the consolidated preview surface) |

**Tabular-nums mandatory on:**

- Starting-balance card numeric value (e.g. `€1,234.56`) — tabular-nums + mono for the integer portion.
- Starting-balance card date (`2026-01-01` format, mono).
- "Commit everything (N transactions) →" — the `N` is tabular-nums so its width is stable as the count updates.
- Per-source preview-section row count (e.g. "Bank statement · 42 rows").
- Per-file chip size (`134 KB`).
- Live "deduplicated total" footer line ("42 + 18 from ICS + 6 from PayPal → 64 to commit (2 already imported)").

**Heading hierarchy on FirstImportStep:**

| Element | Role | Size | Weight |

## Accessibility & Interaction

All parent UI-SPEC accessibility contracts continue to apply. New requirements specific to this phase:

- **Brand SVG (G5)** — rendered via `<img>` (not `<svg>` inline) for cacheability; `alt="beatrax"` provides accessible name; `aria-hidden` is NOT set on the image. The wordmark "beatrax" remains as plain text so screen readers do not double-announce.
- **G3 format chips as radiogroup** — wrap the three primary chips (CAMT.053 / MT940 / CSV) in `role="radiogroup" aria-label="Bank statement format"`. Each chip-button gets `role="radio" aria-checked="true|false"`. Arrow keys move selection (existing Phase 16.1 behavior); Space activates; Tab moves to the drop zone or to the bank-follow-on row if visible.
- **G3 CSV bank follow-on row** — same `role="radiogroup" aria-label="Which bank exported your CSV?"`; only renders when CSV chip is selected; receives focus automatically when CSV becomes selected (programmatic focus on the first chip — ASN by default).
- **Starting-balance card** — each card is a `<section role="region" aria-labelledby="balance-card-{accountId}-h3">`; the H3 is the section's accessible name. Conflict-resolution radios are a proper `<fieldset><legend>` pair (legend visually hidden via `.sr-only` if it duplicates the H3). Inline validation warnings are wrapped in `<span role="alert">`.
- **Per-file chip remove button** — `aria-label="Remove {filename.pdf} from upload queue"`. Keyboard-reachable; Enter or Space activates.
- **Consolidated preview sections** — each is `<section role="region" aria-labelledby="preview-section-{source}-eyebrow">`. The "✓ READY" indicator is `<span aria-label="ready to commit">✓</span>` so screen readers announce the readiness state semantically.
- **Commit button disabled state** — when no source is ready, the button uses `aria-disabled="true"` (NOT the `disabled` attribute, so focus is retained and the user can still tab to it and get the live-counter context). The label reads "Commit everything (—) →".
- **Live deduplicated counter footer** — `aria-live="polite" role="status"` so screen readers announce the total as it updates (each preview section's "✓ READY" flip + each starting-balance card confirm both update the live total).
- **G6 OAuth modal mount-move** — the modal's focus-trap and Esc-dismiss behavior remain owned by the modal itself; the new mount location does not change keyboard handling. The dispatch event flow is opaque to assistive tech.
- **G2 + G4 fixes** — if either fix surfaces a previously-silent error inline, the error region uses `role="alert"` so screen readers announce immediately.
- **Tabular numerics** are mandatory on (additions to the parent list): starting-balance card numeric value, starting-balance card date, per-file chip filesize, per-source row-count, deduplicated commit-counter footer, commit button `(N transactions)` count.
- **Color is never the only signal** — additions to the parent list:
  - Starting-balance card "Confirmed" state uses emerald **border-left + ✓ glyph in eyebrow**, not color alone. Even with a color-blind user reading at grey, the 3px stroke and the glyph still differentiate.
  - Per-file chip "ready" uses emerald **✓ prefix**, not color alone.
  - "✓ READY" section indicator uses the glyph + the word, not glyph alone.
  - G3 CSV gate uses **glyph muting (filter: grayscale(1))** + **`aria-disabled="true"`** + **cursor: not-allowed** + **lead copy change**, not opacity alone.
- **Reduced motion** — see Animation section.
- **High contrast mode** — every new surface uses `border-style` and `background-color` for state encoding (never `outline` or `box-shadow` alone); the emerald confirmed-stroke uses `border-left` not `outline`, so Windows High Contrast mode renders it correctly.
