  pitfall_5_defense_in_depth:
    note: |
      The Pitfall 5 guard (RESEARCH.md "CSV ingestion without a bank-format hint") fires at TWO defense-in-depth layers — this is intentional, not redundant.

      **Layer A (server-side rules() validation) — fires FIRST on a tampered request:**
      - Location: `ConnectBankStep::rules()` (Task 2)
      - Trigger: `selectedFormat ∈ {asn-csv, ing-csv}` AND `selectedBankFormatHint === null`
      - Outcome: Livewire validator rejects the submit before any `runFromUpload` call; user sees the inline rose-tinted validation error under the chip row; no parser is ever invoked. This is the user-visible path.

      **Layer B (`ImportPipeline::preview()` InvalidArgumentException) — fires SECOND as a backstop:**
      - Location: `Modules/Import/Internal/Pipeline/ImportPipeline.php::preview()` (Task 1)
      - Trigger: `$sourceFormat ∈ {asn-csv, ing-csv}` AND `$formatHint === null` (passed directly via the public contract, bypassing the Livewire layer)
      - Outcome: `InvalidArgumentException('CSV imports require a format hint.')` raised before any adapter dispatch; this protects ANY caller of the public contract (including future programmatic callers or test code that bypasses the Livewire validator).

      **Why both:** The Layer A guard catches the realistic browser-tampering attack (developer-tools form-state edit) with a user-friendly error. The Layer B guard catches programmatic-API misuse — important because `RunsImports` is a Public contract that other modules + tests can call directly. Removing either layer narrows the trust perimeter: Layer A alone permits direct contract misuse to silently dispatch to a wrong adapter; Layer B alone permits browser tampering to escape with a developer-style exception instead of a graceful UX message.

      **Sequence on a tampered request:** Layer A fires first (Livewire validator runs before submit() body). Layer B is reached only when the caller bypasses ConnectBankStep entirely (e.g., a test or another module calling `RunsImports::runFromUpload(...)` directly). The Pest test in Task 1's third `it(...)` block specifically exercises the Layer B path; the Pest test in Task 2's third `it(...)` block exercises the Layer A path.
