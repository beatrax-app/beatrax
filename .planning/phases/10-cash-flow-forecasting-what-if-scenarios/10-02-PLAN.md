    Table `forecast_scenarios`:
    - `id` — auto-increment PK
    - `user_id` — `foreignId('user_id')->nullable()->constrained('users')->cascadeOnDelete()` (FND-03 nullable carry-forward; cascade-on-delete because scenarios are user-owned and deleting a user wipes their scenarios cleanly)
    - `name` — `string(120)`
    - `description` — `text()->nullable()`
    - `timestamps()` — `created_at` + `updated_at`

    Indexes: `unique(['user_id', 'name'])` (scenario names unique per-user — prevents collision and gives the rename action a deterministic conflict surface), `index(['user_id', 'created_at'])` (scenario picker sorts by recency).

    PHPDoc: "Saved what-if scenarios. Each scenario is a named container for a list of mutations the user wants to model against the baseline forecast. Strictly walled off from the transaction substrate — no JOIN onto transactions / recurring_series / chain_links is permitted (enforced by the noScenarioMutationsJoinedToTransactionQueries arch test)."

    **Migration 2 — `2026_05_19_010002_create_forecast_scenario_mutations_table.php`**

    Table `forecast_scenario_mutations`:
    - `id` — auto-increment PK
    - `user_id` — `foreignId('user_id')->nullable()->constrained('users')->cascadeOnDelete()` (FND-03)
    - `forecast_scenario_id` — `foreignId('forecast_scenario_id')->constrained('forecast_scenarios')->cascadeOnDelete()` (deleting a scenario wipes its mutations atomically)

    - `timestamps()` — `created_at` + `updated_at`

    PHPDoc: "A single mutation inside a saved scenario (cancel a series, add a one-off, etc.).
