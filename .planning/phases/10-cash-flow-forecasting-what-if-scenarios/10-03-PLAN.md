    **Modules/Forecasting/Internal/Pipeline/RangeProjector.php**

    Public method:
    ```
    public function envelope(\Modules\Recurring\Public\Dto\RecurringSeriesDto $series, \Illuminate\Support\Carbon $asOf, int $horizonDays, \Modules\Core\Models\User $user): array
    ```

    Returns `array<ForecastContribution>` — one per projected occurrence.

    Constructor DI: `Clock $clock`. (Wave 2 envelope tier reads NO database — projection comes from the in-memory series DTO. Wave 5 percentile tier adds an `occurrencesForSeries` Public query call.)

    Algorithm (envelope tier — D-1004):
    1. Compute per-occurrence dates from `$series->nextExpectedDate` walking forward by `$series->cadence` until `> $asOf + $horizonDays` days. Cadence intervals (D-816 carry-forward): `weekly = +7 days`, `monthly = +1 month`, `quarterly = +3 months`, `yearly = +1 year`. Use Carbon arithmetic.
    2. For each occurrence date:
       - `point = $series->latestAmountMinor` (signed; negative for expense, positive for income — Phase 8 D-816 polarity preservation).
       - `low = (int) round($series->latestAmountMinor * (1 - $series->varianceTolerancePercent / 100))`.
       - `high = (int) round($series->latestAmountMinor * (1 + $series->varianceTolerancePercent / 100))`.
       - **Sign-aware low/high**: for income (positive amounts), `low < point < high`. For expense (negative amounts), `low > point > high` numerically because the variance widens the absolute value. The cleaner formulation is: compute `magnitude = abs($latestAmountMinor)`, `lowMag = magnitude * (1 - tol)`, `highMag = magnitude * (1 + tol)`, then re-apply sign so `low = sign * highMag` (wider absolute = "more outflow" for expense) and `high = sign * lowMag` (narrower absolute = "less outflow"). This keeps the daily fold semantics correct: a more-negative point reduces running balance more.
    3. **FX series carry-through** (D-1006): the contribution carries `$series->latestCurrency` and `$series->latestFxRateUsed`. The projector does NOT convert to the account's default currency; the daily fold (Task 1 step 3 below) consumes the raw amounts AND the per-series fx_rate so the final per-day points are in the account's default currency. Wave 5 polishes the multi-currency rendering further.
    4. Wave 2 deliberately omits the cadence-date jitter (±3-day window per D-1004) — that's a Wave 5 deliverable; the Wave 2 occurrence dates are deterministic.
    5. Return `array<ForecastContribution>` with each entry: `new ForecastContribution(date: $occurrenceDate, pointMinor: $point, lowMinor: $low, highMinor: $high, currency: $series->latestCurrency, fxRateUsed: $series->latestFxRateUsed, seriesId: $series->id, accountId: $series->accountId)`.

    **Modules/Forecasting/Internal/Pipeline/DailyFold.php**

    Public method:
    ```
    public function fold(int $openingBalanceMinor, array $contributions, \Illuminate\Support\Carbon $asOf, int $horizonDays, string $defaultCurrency): array
    ```

    Returns `array<string, array{date: string, low_minor: int, point_minor: int, high_minor: int, currency: string}>` keyed by `Y-m-d`.

    Constructor: no DI; pure-math class. (Optionally inject Clock if needed for defensive bounds checks.)

    Algorithm (RESEARCH Pattern 4 — copy verbatim from RESEARCH lines 651-694, adapting types):
    1. Group `$contributions` by date string `Y-m-d`.
    2. For each day-bucket: `point = Σ(contribution.pointMinor)` (signed sum — expense reduces, income increases). `spread_sq = Σ(((contribution.highMinor - contribution.lowMinor) / 2)^2)` (half-width squared; quadrature combination assumes independent series — documented PHPDoc note).
    3. **FX conversion happens at this step** (D-1006): each contribution's `pointMinor` / `lowMinor` / `highMinor` is in the contribution's `currency`. Convert to `$defaultCurrency` using the contribution's `fxRateUsed` IF currency differs from default. The formula: `convertedPointMinor = (int) round(contribution.pointMinor * contribution.fxRateUsed)`. If `fxRateUsed` is null AND currencies differ, throw — every cross-currency contribution must carry a stored fx rate (Phase 8 D-840 guarantee).
    4. Iterate days in ISO-sorted order from `$asOf` through `$asOf + $horizonDays`. Maintain running totals: `running = $openingBalanceMinor`, `cumSpreadSq = 0`. For each day:
       - If the day has contributions: add `bucket.point` to `running`, add `bucket.spread_sq` to `cumSpreadSq`.
       - `spread = (int) round(sqrt($cumSpreadSq))` (RESEARCH Pattern 4 formula).
       - Emit `[$day => ['date' => $day, 'low_minor' => $running - $spread, 'point_minor' => $running, 'high_minor' => $running + $spread, 'currency' => $defaultCurrency]]`.
    5. Days with no contributions still emit a row (the running balance carries forward unchanged; the spread carries forward unchanged). This gives a continuous chart band — no missing dates.

    **PHPDoc on `fold()`**: "Combines per-occurrence spreads via quadrature (√(Σ spread²)). Statistically correct for INDEPENDENT series — if two series share an underlying cause (e.g., two streaming subscriptions on the same billing cycle), this UNDER-estimates the combined spread. Phase 10 treats every approved recurring series as independent; the percentile tier (Wave 5) sidesteps the assumption by reading the observed empirical distribution per series. Reference: Cornell 8.04 / MIT OCW 6.012."
