## Decisions Made

- **ForecastPage Livewire placeholder ships in Wave 0 (Rule 2 deviation).** The plan's Wave 0 scope had `Modules/Forecasting/Internal/Http/Livewire/` as an empty `.gitkeep` directory and deferred the `/forecast` SFC to a later wave. Discovered during Task 1 verification that Laravel boot fails on the `/forecast` route action lookup if `ForecastPage` does not exist (RouteAction::parse throws because the FQN does not resolve). Without the placeholder, PHPStan's Larastan bootstrap fails and Pest cannot discover the new testsuite. A minimal `final class ForecastPage extends Livewire\\Component` that renders an empty view is the smallest fix that keeps the route registered and the boot path clean. The class is a stub a later wave swaps the body of with the real 30/60/90 horizon switch + scenario CRUD panel — no signature change required.
- **Listener scaffold body references $this->bus::class and $event::class in the RuntimeException message.** The plan said the body should just throw, but PHPStan strict-rules + larastan-strict-rules flag unused constructor-promoted properties and unused parameters. The references keep both live for static analysis until the later wave fans out the projection job — they also produce a more useful exception message if the scaffold is exercised before its swap-in.
- **`->setUp()` and Database/Migrations directories are deferred to a later wave** (matches plan's Wave 0 → Wave 1 boundary). The ServiceProvider's `is_dir()` / `is_file()` guards mean the boot path is forward-compatible without runtime errors against the empty Wave 0 module.

Recovery confirmed by `git status` on the main repo showing only the unrelated pre-existing `STATE.md` modification and no stray `Modules/Forecasting/` untracked entries. Lesson: every Write that uses an absolute path must derive the prefix from `git rev-parse --show-toplevel` run inside the worktree.

- **Pest `--filter="Forecasting"` exits 1 even when all tests pass.** The new FixtureCorpusTest + the four new BoundaryArchTest invariants run cleanly (15 + 4 tests with 1056+65 assertions, no failures), but Pest's process exit code is 1 when a description-based `--filter` matches only arch tests + dataset cases that are status "WARN" (Pest's convention for trivially-satisfied arch invariants). `--testsuite=Forecasting` exits 0 correctly. Documented here so a later wave's CI does not chase a false negative — use `--testsuite=Forecasting` as the discoverability check, not `--filter=Forecasting`.
