<!-- ImpersonateUserAction — analog: none direct; constructor-DI action; 12-RESEARCH.md Pattern 6 -->

```
final class ImpersonateUserAction
  constructor: AuthManager $auth, Hasher $hasher,
               SessionContract $session,   // Illuminate\Contracts\Session\Session
               CurrentUser $currentUser,
               DatabaseManager $db          // for the system_alerts audit row
  __invoke(string $callerPasswordInput, int $targetUserId): ImpersonationResult
    $developer = $this->currentUser->user()
    if $developer is null OR ! $developer->is_developer:
      return ImpersonationResult::notAllowed()
    if already impersonating (session key set):
      return ImpersonationResult::notAllowed()   // no nested impersonation
    if ! $this->hasher->check($callerPasswordInput, $developer->password):
      emit system_alerts auth.impersonation_failed / critical
      return ImpersonationResult::wrongPassword()
    $target = User::query()->find($targetUserId)
    if $target is null OR $target->id === $developer->id:
      return ImpersonationResult::invalidTarget()
    // stash BEFORE the swap
    $this->session->put('auth.impersonating.original_user_id', $developer->id)
    $this->session->put('auth.impersonating.original_username', $developer->username)
    /** @var StatefulGuard $guard */ $guard = $this->auth->guard()
    $guard->loginUsingId($target->id)
    emit system_alerts auth.impersonation_started / warning
    return ImpersonationResult::success($target)
```

`Illuminate\Contracts\Session\Session` is a CONTRACT, not a facade — the
`noAuthFacadeOrHelper` regex matches `session(` (helper) / `request()->session(`,
NOT a typed contract import. The action IS on the allow-list (it calls
`loginUsingId`). Use the `StatefulGuard`-typed local-variable trick (see
12-03-SUMMARY.md — `AuthManager::guard()` needs the typed local to satisfy
Larastan L10 on `loginUsingId`).

<!-- EndImpersonationAction -->

```
final class EndImpersonationAction
  constructor: AuthManager $auth, SessionContract $session, DatabaseManager $db
  __invoke(): ImpersonationResult
    $originalId = $this->session->get('auth.impersonating.original_user_id')
    if $originalId is null: return ImpersonationResult::notAllowed()  // not impersonating
    /** @var StatefulGuard $guard */ $guard = $this->auth->guard()
    $guard->loginUsingId((int) $originalId)
    $this->session->forget('auth.impersonating.original_user_id')
    $this->session->forget('auth.impersonating.original_username')
    emit system_alerts auth.impersonation_ended / warning
    return ImpersonationResult::success(...)
```

<!-- CrossUserIsolationTest — analog: PATTERNS.md §CrossUserIsolationTest;
     dataset shape from SystemAlertsMigrationTest.php; two-user setup from AssignCategoryTest.php -->

The test introspects the route table and verifies cross-user isolation for
every auth-gated route. Strategy:
- Resolve the router (`$this->app->make(\Illuminate\Routing\Router::class)`),
  iterate `getRoutes()`, keep GET routes whose middleware includes `auth`.
- Two classes of route:
  (a) **Model-scoped routes** (`/transactions/{transactionId}`,
      `/recurring/series/{seriesId}`, `/chains/review` has no param, etc.) —
      user A creates the underlying record, user B (logged in) requests the
      record's URL, assert HTTP 404 (NOT 403 — 403 leaks existence).
  (b) **List / index routes** (`/`, `/settings`, `/transactions`,
      `/uncategorized`, `/rules`, `/recurring`, `/forecast`, `/drift`,
      `/inboxes`, `/imports/new`) — user A creates user-scoped data, user B
      requests the list and asserts B's own (empty / B-only) data renders and
      A's data is NOT present.
- The verifier explicitly named the gaps: Categorization `/uncategorized` +
  `/rules`, Core `/` + `/settings`, Ledger list `GET /transactions`. These MUST
  be covered. The five modules that already have isolation tests (Chains,
  DriftAlerts, Forecasting, Recurring, EmailScan) — this test does NOT need to
  duplicate their per-record tests, but it MUST be the first place that creates
  TWO users at once and exercises the previously-uncovered routes.
- Build the two users with `User::create([...])` (no User factory exists per
  12-02-SUMMARY.md — use direct create or the `Modules/Auth/Database/Factories/
  UserFactory.php` if 12-04 added one; read first to confirm). Acting-as shape
  from `AssignCategoryTest.php`.
- An explicit allow-list of routes that legitimately do NOT take cross-user
  data (e.g. `/login`, `/signup`, `/reset-password`, `/change-password`,
  `/recovery-codes`, `/impersonate`, `/impersonate/end`, `/logout`) is fine —
  declare it as a small array with a comment; those are auth/guest plumbing,
  not user-data surfaces.
