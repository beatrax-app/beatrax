# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Foundation + ASN CSV Vertical Slice. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope (UI surfaces produced):**

1. `/login` — single-user Fortify login form (hand-written Livewire/Flux UI per D-09)
2. `/` — first-run redirect; once seeded becomes the "this month at a glance" dashboard (UI-01)
3. `/imports/new` — upload form (declare-source-type, no auto-detection per ING-07)
4. `/imports/{id}/preview` — preview-then-confirm wizard with per-row NEW / DUPLICATE / ERROR status (D-13)
5. `/imports/{id}` — results summary ("N imported · M skipped · K errors")
6. `/transactions` — recent-window list (UI-04, default last 3 months)
7. `/uncategorized` — focused triage inbox with single-key category assignment (D-20, CAT-05)
8. `/settings` — minimal form to view/change `period_start_day` (deferred per D-19 closing note — planner may defer; spec covers it for completeness)
9. Account-naming inline step inside the wizard when an unknown IBAN is encountered (D-14)

**Out of scope this phase:** chain-resolution drill-downs, recurring-payments view, drift alerts, forecasting, dual-currency toggle, healthcheck surface, full-history view beyond the recent-window toggle.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline padding inside chips/badges |
| sm | 8px | Compact element spacing (form field internal padding, table cell row gap) |
| md | 16px | Default element spacing (between form fields, between cards in a stack) |
| lg | 24px | Section padding inside cards; gap between sibling sections on a page |
| xl | 32px | Layout gaps (between page-level blocks: KPI row → category list → recent transactions) |
| 2xl | 48px | Major section breaks; top padding of page content from header |
| 3xl | 64px | Page-level vertical breathing for the calm-density target |

**Exceptions:** none. All keyboard-tappable controls must hit a 40px effective height minimum (achieved via `py-2` on default Flux button + `text-sm` line-height); no separate 44px override token is needed because the localhost target is desktop-only.

**Page width:** Content max-width `max-w-5xl` (~1024px) centered with `px-2xl` on viewports ≥ 1024px. Calm aesthetic = generous whitespace, never edge-to-edge.

**Dashboard grid:** Three KPI tiles (In / Out / Net) on a single row with `gap-md`. Stack to vertical only below 720px (rare on localhost desktop use, but enforced for resilience).

## Typography

| Role | Size | Weight | Line Height | Notes |
|------|------|--------|-------------|-------|
| Micro / Caption | 12px | 500 (medium) | 1.4 | Table column headers, status badge labels, "last updated" annotations |
| Body | 14px | 400 (regular) | 1.5 | All running text, table cells, form labels and inputs, button labels |
| Section heading | 20px | 600 (semibold) | 1.3 | Card titles ("This month at a glance", "Recent transactions"), page-level subsection headers |
| Display (KPI numbers) | 32px | 600 (semibold) | 1.2 | The three top-of-dashboard amounts (In / Out / Net), and the per-row total on the wizard summary |

**Total declared:** 4 sizes, 2 weights — within the 3–4 sizes / 2 weights ceiling.

**Monospace:** none. Use Inter with `font-variant-numeric: tabular-nums` for every money column and date column. No second font family ships in Phase 1.

**Heading hierarchy on the dashboard:**
- Page title (e.g. "May 2026" / period range) — Display size (32px)
- Card / section titles — Section heading (20px)
- Everything else — Body (14px)

## Color

| Role | Value | Tailwind class | Usage |
|------|-------|----------------|-------|
| Dominant (60%) | `#FFFFFF` | `bg-white` | Page background, primary surface |
| Secondary (30%) | `#F8FAFC` | `bg-slate-50` | Card surfaces, sidebar/nav strip, table zebra (subtle), input backgrounds |
| Secondary borders | `#E2E8F0` | `border-slate-200` | Card outlines, table row dividers, input borders |
| Text — primary | `#0F172A` | `text-slate-900` | Body text, all monetary amounts (both inflow and outflow — see semantic note) |
| Text — muted | `#64748B` | `text-slate-500` | Captions, table column headers, "duplicate" badge text, secondary metadata |
| Accent (10%) | `#059669` (emerald-600) | `bg-emerald-600` / `text-emerald-600` | **Reserved for primary CTAs and confirmed-positive states only — see list below** |
| Destructive | `#E11D48` (rose-600) | `bg-rose-600` / `text-rose-600` | Destructive confirmations and ERROR row state only |
| Warning (subdued) | `#B45309` (amber-700) | `text-amber-700 bg-amber-50` | DUPLICATE row state in the import preview wizard |

**Accent (`emerald-600`) is reserved for — and ONLY for — these elements:**

1. The primary CTA button in the upload wizard ("Upload statement", "Confirm import")
2. The primary login button ("Sign in")
3. The "Net" KPI value on the dashboard **when positive** (negative net is rendered in `text-slate-900`, never red — calm aesthetic)
4. The "NEW" row-status badge in the import preview (`bg-emerald-50 text-emerald-700 ring-emerald-600/20`)
5. The success toast/banner on the import results page ("Imported N transactions")
6. The "Apply" / "Save" button on the categorization triage page when at least one assignment is pending

**Accent is never used for:**

- Generic links, table row hovers, or selected-row highlights (those use `bg-slate-100` / `text-slate-900` `underline`)
- The "Out" KPI value (rendered in `text-slate-900` — not red, deliberately calm)
- Sidebar/nav active state (uses `bg-slate-100 text-slate-900 font-semibold`)
- Any decorative element

**Destructive (`rose-600`) is reserved for:**

1. The ERROR row-status badge in the import preview (`bg-rose-50 text-rose-700 ring-rose-600/20`)
2. Inline form-validation error text under inputs
3. Any "Discard import" / "Cancel and discard" confirmation button (Phase 1 only has the mid-wizard discard; no transaction-delete in scope)

**60 / 30 / 10 audit:**
- 60% dominant white background covers all page chrome and most surface area
- 30% secondary (`slate-50` / `slate-200` borders) covers cards, table rows, form chrome
- 10% accent + destructive combined never exceeds the buttons + status badges + single net-positive figure

**No dark mode in Phase 1.** Defer to a later operational-polish phase. Tailwind 4 makes adding it later a config change, not a refactor.

## Component Inventory (Flux UI only)

All interactive components in Phase 1 must come from Flux UI. Naming below uses Flux 1.x conventions.

| Surface | Flux component(s) | Notes |
|---------|-------------------|-------|
| Login form | `flux:input`, `flux:button`, `flux:field` | Single-user, no "register" link, no social providers |
| Top nav | `flux:navbar` with `flux:navbar.item` | Items: Dashboard, Transactions, Uncategorized (with count badge), Settings; right-side: account email + Sign out |
| Page header | `flux:heading` + `flux:subheading` | Period range "May 2026" or "25 May → 24 Jun 2026" |
| KPI tiles | `flux:card` (3 across) | One per metric: In / Out / Net; display number above 12px caption label |
| Category bar list | Plain HTML + Tailwind (Flux does not yet ship a horizontal-bar list component) | Each row: category name (left), monospace amount (right), `<div class="h-1 bg-slate-200"><div class="h-1 bg-slate-900" style="width:N%"></div></div>` below |
| Transaction table | `flux:table` with `flux:table.column` | Columns: Date · Counterparty · Category · Amount (right-aligned, tabular-nums); row click opens transaction in a side panel |
| Transaction detail (side panel) | `flux:modal` variant=flyout | Read-only fields + category dropdown |
| Upload form | `flux:input type=file`, `flux:select` (source declaration), `flux:button` | Source select has one option "ASN CSV" in Phase 1; built as a select so Phase 2/3 can add options without UI surgery |
| Preview wizard table | `flux:table` | Adds a "Status" column with `flux:badge` (NEW / DUPLICATE / ERROR) |
| Status badges | `flux:badge` color={emerald,amber,rose} | One badge per row status |
| Confirm dialog | `flux:modal` | "Confirm import: N new, M duplicates, K errors. Proceed?" |
| Account-naming step | `flux:input` inside the wizard inline | Prompts: "We found an unfamiliar IBAN: NL12ASNB0123456789. Name this account." |
| Toast / success banner | `flux:toast` | "Imported N transactions" — 4 second auto-dismiss |
| Triage list (`/uncategorized`) | `flux:table` + Alpine.js keymap (1–9 = top 9 categories, `/` = search) | Single-keystroke category assignment; selected row highlighted with `bg-slate-100` |
| Category picker | `flux:select` (tree-flattened) or `flux:command` (preferred if available — Linear-style) | Phase 1 default: `flux:select` flattened ("Subscriptions / Streaming"); upgrade to `flux:command` if Flux ships it before implementation starts |
| Settings form | `flux:field` + `flux:input` (number, 1–28) for `period_start_day` | Save → success toast |

**Do not invent new components.** If Flux does not ship something needed, use plain Tailwind primitives (see "Category bar list") rather than a third-party library. Charts arrive in Phase 8 (recurring/fixed-payments view); Phase 1 ships zero charts — no ApexCharts dependency yet.

## Copywriting Contract

All copy below is **prescriptive**. The executor uses this verbatim.

### Primary CTAs

| Context | Copy |
|---------|------|
| Login form submit | `Sign in` |
| Upload form submit | `Upload statement` |
| Preview wizard confirm | `Confirm import` |
| Preview wizard cancel | `Discard` |
| Triage page bulk-save | `Save categories` |
| Settings page save | `Save` |

### Empty states

| Surface | Heading | Body |
|---------|---------|------|
| Dashboard (first run, no transactions) | `No transactions yet.` | `Upload an ASN CSV export to see this month at a glance.` (Single primary CTA button below: `Upload your first statement` — links to `/imports/new`. This is the only place Phase 1 deviates from the standard CTA copy, because it is also the empty-state hint.) |
| Transactions list (period has no rows) | `Nothing here for this period.` | `Step back a period with the arrows above, or upload a statement that covers it.` |
| Uncategorized triage (zero uncategorized) | `Inbox zero.` | `Every transaction has a category. Re-open this page after your next import.` |

### Status badges (import preview)

| Status | Badge label | Tooltip / inline description |
|--------|-------------|------------------------------|
| NEW | `New` | `Will be added to your ledger.` |
| DUPLICATE | `Duplicate` | `Already imported — will be skipped.` |
| ERROR | `Error` | `This row could not be parsed. Reason: {parser_error_message}` |

### Results summary (after Confirm import)

Top-line: `Imported {N} transactions · skipped {M} duplicates{K, plural, =0{} other{ · {K} errors}}.`

(Concrete example: `Imported 47 transactions · skipped 12 duplicates.`)

Below the line, two collapsed disclosures:

- `Show skipped duplicates ({M})` — expandable
- `Show errors ({K})` — only rendered if K > 0; expanded by default

### Error states

| Situation | Copy |
|-----------|------|
| Pre-parse validation fail (wrong MIME / extension) | `That file doesn't look like a CSV. Drop in the ASN CSV export you downloaded from the ASN portal.` |
| Pre-parse validation fail (header columns don't match ASN CSV) | `This CSV doesn't match the expected ASN column layout. If ASN changed their export format, file an issue.` |
| Per-row parse error (in the preview) | `Could not parse this row: {reason}. The row will be skipped if you confirm.` |
| Network / disk error on import commit | `Import failed: {error_message}. No transactions were written.` (No retry button — user re-uploads if they want to retry; phase is sync.) |
| Login failure | `Email or password is incorrect.` (Generic — never leak which field is wrong.) |

### Destructive confirmation

Phase 1 has **one** destructive action: discarding an in-progress import mid-wizard.

| Action | Confirmation copy |
|--------|-------------------|
| `Discard` button on preview wizard | `Discard this import? The parsed rows will be lost. No transactions have been saved yet.` Buttons: `Discard` (rose-600) · `Keep reviewing` (default) |

There is **no delete-transaction action in Phase 1**. Re-importing the same CSV is idempotent (the user can clear state by deleting the SQLite file out-of-band, but that is operator-level, not a UI affordance).

### Voice and tone

- **Calm, declarative, no exclamation marks.** "Imported 47 transactions." not "Imported 47 transactions!"
- **Second person ("you", "your") only where it adds clarity.** Default to declarative ("Inbox zero." not "You've reached inbox zero!").
- **No emojis anywhere in the UI.** No icons-as-decoration; icons must always carry meaning (Heroicons next to status badges is OK; a sparkle next to "Imported" is not).
- **Numbers are written as digits**: `12 duplicates`, not `twelve duplicates`.
- **No "Loading..." text** — Flux's button loading state (spinner) is sufficient.

## Interaction Contracts

### Currency display

- Amounts render as `€1,234.56` with comma thousand-separator and period decimal (Dutch user, but project uses the international convention to avoid confusion with the `1.234,56` format that varies by export). Lock-in: **`€ 1,234.56` with non-breaking space between symbol and number, period decimal, comma thousands.**
- Negative amounts: rendered with a leading minus sign and `text-slate-900` (NOT red). The minus carries the semantic; colour stays calm.
- Tabular-nums mandatory on every cell that contains money or a date.
- Currency symbol always rendered (`€` for EUR). Phase 1 only handles EUR amounts from ASN; the schema preserves original currency per MC-01 but the UI never needs to display a foreign currency in Phase 1 (deferred to Phase 3 / UI-06).

### Date display

- Default format: `12 May 2026` (day month year, no comma, English month name).
- Table cells: same format. No "2 days ago" relative dates in Phase 1.
- Period header: `May 2026` if `period_start_day = 1`, otherwise `25 Apr → 24 May 2026`.

### Period navigation

- Prev / next arrows on the dashboard `flux:button variant=ghost` with chevron icons.
- Keyboard: `←` / `→` step periods when no input is focused.
- Today shortcut: press `t` to return to the current period.

### Triage page keymap

- `1`–`9` assign the user's top-9 most-used categories (computed across history).
- `↑` / `↓` move the selection cursor.
- `Enter` confirm pending assignments (equivalent to clicking `Save categories`).
- `/` focus the category search input.
- `Esc` clear pending assignments.
- A small visible legend at the bottom of `/uncategorized` lists the active keymap. Calm, monochrome legend; no tooltip popovers.

### Loading & latency

- Phase 1 is synchronous end-to-end (D-15). For uploads <5 MB on local SQLite this completes in <2 s — no spinner needed beyond Flux's built-in button-loading state.
- If parsing exceeds 1 s, the wizard shows a `flux:button` in `loading` state on the upload submit; no separate skeleton screen.
- No optimistic UI in Phase 1. Confirm import is a hard write; the results page is the source of truth.

### Focus & a11y

- All interactive elements show a visible focus ring (`focus-visible:ring-2 ring-slate-900 ring-offset-2`).
- All form inputs use `flux:field` so the label is associated automatically.
- Color contrast: every text/background pair declared above hits WCAG AA (verified — `text-slate-900` on `bg-white` = 19.3:1; `text-emerald-600` on `bg-white` = 4.74:1; `text-slate-500` on `bg-white` = 5.41:1).
- Buttons have a minimum hit target of 40×40 (Flux's `size=base` default).
