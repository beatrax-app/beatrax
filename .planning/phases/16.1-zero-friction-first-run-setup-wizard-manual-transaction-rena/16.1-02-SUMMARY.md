## Decisions Made

- **Container-tag pattern (Receipts mirror):** Adopted verbatim from `Modules/Receipts/Providers/ReceiptsServiceProvider` lines 60-119 — `private const PAYMENT_TYPE_HINTER_FQNS`, `class_exists()` guard, `singleton()` + `tag([$fqn], 'import.payment_type_hinter')` per FQN, plus a closure-bound singleton for the classifier stage consuming `$app->tagged(...)`.
- **Hinter registration order = tie-break order:** CAMT.053 first (authoritative BkTxCd at confidence 95), MT940 / CSV (Dutch lexemes at 70-90), ICS PDF (CAPS tokens at 60-90), PayPal CSV (event types at 85-95), DescriptionKeywordFallbackHinter LAST (confidence 40). The registry test locks this order so a future hinter addition can extend the inventory without silently changing the tie-break.
- **CAMT.053 hinter: structured codes preferred over keywords.** The `rawPayload['sepa']['btc']` triple (`domain|family|subFamily` — e.g. `PMNT|CCRD|POSD`) is the ISO20022 authoritative source. Description-keyword scan is the fallback only.
- **PayPal CSV hinter scope:** Maps observed NL event types (`Express Checkout-betaling`, `Algemene valutaomrekening`, `Vooraf goedgekeurde betaling …`) plus an EN forward-compatibility set. Unknown event types return `null` — the description-keyword fallback can take a shot, and the adapter raises a typed exception at parse time for genuinely-unmappable events so this is forward-compatible noise rather than a silent miss.
- **ICS PDF hinter: default to Online.** The Mijn ICS portal carries no per-row transaction-type column. After the four CAPS-token branches (KOSTEN KASOPNAME → Fee, GELDMAAT → Pin, IDEAL BETALING → Online, INCASSO → DirectDebit), the residual is functionally always an online card-not-present charge — the hinter emits `PaymentType::Online` at low confidence (60) so the description-keyword fallback's verdict is preferred when it actually fires, and `Unknown` is the residual.
- **sourceHint scope:** carries the matched lexeme only (e.g. `betaalautomaat`, `btc:PMNT-CCRD-POSD`, `event_type:refund sent`). The full canonical description is NEVER logged — mitigation for T-16.1-02-02 in the threat model.
- **Arch invariant: `*Hinter` (not `*PaymentTypeHinter`).** The filename suffix matches both per-source classes (`*PaymentTypeHinter`) and the fallback (`DescriptionKeywordFallbackHinter`) — broader catch.

- `$this->app` is `null` in every Feature / Contracts test, including PRE-EXISTING tests (verified by running `ClassifyTransactionTypeTest` — a wholly unrelated test — under the worktree path and reproducing identical failures).
- `composer test --parallel` from this worktree reports 1972 test failures, all with the same `Call to a member function make() on null` / `tagged() on null` signature.

**Recommendation for follow-up:** A separate fix-it plan should canonicalise `tests/Pest.php`'s `in()` path argument (e.g. `realpath(__DIR__.'/../'.$module.'/tests/Feature') ?: ...`) so Feature/Contracts/Snapshot tests bind correctly under any working-tree path.
