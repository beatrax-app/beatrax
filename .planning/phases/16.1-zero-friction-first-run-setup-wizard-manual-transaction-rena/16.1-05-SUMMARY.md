## Accomplishments

- **Bundled corpus + loader:** `resources/corpus/merchant-mappings.yaml` (36 Dutch merchants) + `resources/corpus/built-in-heuristics.yaml` (12 dominant brands). CorpusLoader parses via symfony/yaml with `PARSE_EXCEPTION_ON_INVALID_TYPE` (ASVS V10 / T-16.1-05-01), validates per-entry required fields, logs warnings for unknown categories without aborting, computes generalized patterns via PatternGeneralizer.
- **Idempotent install-time seeding:** SeedCommunityCorpus listens for UserInstalled (mirrors SeedDefaultCategoryTree). Re-dispatching is safe: `updateOrInsert` keyed on `(pattern, user_id IS NULL)` updates in place. Per-entry try/catch keeps a single bad row from poisoning the whole seed.
- **Community fallback in MerchantNameResolver:** Steps c + d of the precedence walk (D-15) now consult `CommunityCorpusQuery::lookupExact` / `lookupGeneralized`. User-exact aliases still win (D-11), keeping a user's local rename authoritative even when the corpus matches the same raw description.
- **Cross-module Shell contract launch:** OpenExternalUrlAction is the sole sanctioned path from PHP into the NativePHP Shell contract. Validates https + github.com host allow-list before delegating; NoOpShell fallback bound when the bundle runs outside the NativePHP runtime so feature tests can substitute a ShellFake.
- **Suggest-mapping modal:** Globally-mounted Livewire SFC opened via the `suggest-mapping:open` event from any of three surfaces (Triage CTA / browse page card / Settings → Browse). YAML preview pane uses Alpine `x-data` + `$wire.entangle` for live updates (Browser tier, zero server roundtrips per keystroke).
- **`/community/mystery-merchants` browse destination:** Lists every transaction description the resolver cannot identify; payment-type chips come from Plan 02's PaymentType enum. Stats strip surfaces mystery-count, corpus mappings-count, auto-named percentage, and a reserved contributor-count slot.
- **Settings → Shared merchant list:** SharedListSettingsPanel renders three toggles per UI-SPEC. Toggle 1 + 2 persist into `users.community_settings`. Toggle 3 ships disabled with a version-agnostic inline note (B-5: zero `\d+\.\d+` literals) until Phase 18 activates the live-update mechanism.
- **Triage row integration:** HelpOthersTriageButton mounts per-row, server-side absent when `community_settings.offerToContribute=false`. Defence-in-depth (T-16.1-05-06): empty `<div>` wrapper instead of CSS-hidden so a tampered client cannot fish the CTA back into the DOM.
- **Two new arch invariants:** `noShellContractOutsideAllowList` restricts `Native\Desktop\Contracts\Shell` imports to OpenExternalUrlAction + NoOpShell + CommunityServiceProvider; the wider `noNativePhpImportsOutsideDesktopModule` is extended with the same three-file carve-out.

## Deviations from Plan

### 1. [Rule 3 — Blocking] MerchantNameResolverCommunityTest path: Unit → Feature

- **Found during:** Task 1 (initial test run)
- **Issue:** The plan placed `MerchantNameResolverCommunityTest.php` under `Modules/Import/tests/Unit/`, but the test exercises real DB tables (`community_merchant_mappings`, `merchant_aliases`) and Pest's Unit suite does not apply `RefreshDatabase`. Tests immediately failed with `SQLSTATE: no such table: users`.
- **Fix:** Moved the test to `Modules/Import/tests/Feature/MerchantNameResolverCommunityTest.php` (the architecturally correct home for DB-touching tests).
- **Files modified:** test relocated only; no source change.
- **Verification:** All 4 cases pass under the Feature suite with proper RefreshDatabase semantics.
- **Committed in:** `cfd51aa` (RED) + `1bbdd72` (GREEN)

### 2. [Rule 3 — Blocking] Allow-list extension on the pre-existing `noNativePhpImportsOutsideDesktopModule` arch invariant

- **Found during:** Task 2 (running the full BoundaryArchTest after adding the new `noShellContractOutsideAllowList` rule)
- **Issue:** The existing invariant restricted any `Native\Desktop\*` symbol to Modules/Desktop only. Plan 05's OpenExternalUrlAction + NoOpShell + the CommunityServiceProvider binding line all reference `Native\Desktop\Contracts\Shell`, so the invariant fired on them.
- **Fix:** Added a three-file allow-list to the existing invariant covering exactly the new Shell-contract consumer surface. The narrower `noShellContractOutsideAllowList` invariant added in this plan locks the Shell-contract import even tighter — these two rules are complementary defences (namespace-wide vs symbol-specific).
- **Files modified:** `tests/Contracts/BoundaryArchTest.php`
- **Verification:** Both invariants now pass; the wider rule is still enforced for every other module.
- **Committed in:** `73d9d79`

### 3. [Rule 1 — Bug] Blade `@livewire(...)` `key:` named-parameter syntax corrected

- **Found during:** Task 3b (running existing TriagePageTest after wiring the per-row HelpOthersTriageButton mount)
- **Issue:** Initially wrote `@livewire('community.help-others-triage-button', [...], key: 'help-'.$row->id)`. Blade's `@livewire` directive does not accept a named `key:` argument — it expects a positional third arg via the `key()` helper. The view compiled but threw `Unknown named parameter $key` at render time.
- **Fix:** Replaced with `@livewire(..., [...], key('help-'.$row->transactionId))` mirroring the existing patterns under `Modules/DriftAlerts` and `Modules/Recurring`.
- **Files modified:** `Modules/Categorization/Resources/views/livewire/triage-inbox.blade.php`
- **Verification:** Existing TriagePageTest (7 cases, 23 assertions) green.
- **Committed in:** `3bf7759`

## Issues Encountered

- **Vite manifest missing in fresh worktree** — The worktree had no `public/build/manifest.json` because the build artifact is gitignored. Symlinked from the main repo's existing build so TriagePageTest's `$this->get('/transactions')` can render. Workflow-level housekeeping; not a code issue.
