# Phase 16.1 — UI Design Contract

> Visual and interaction contract for the four user-facing surfaces of Phase 16.1: first-run setup wizard, manual rename of fallback-description rows, payment-type classification chip, and crowd-sourced merchant identification corpus.
>
> **Source-of-truth chain:** `Skill("sketch-findings-diederik")` defines the locked visual decisions (validated through sketch sessions 002–005, 2026-05-25); this spec wires the sketch findings + the existing Phase 16 token block (already shipped in `resources/css/app.css`) into a contract the planner and executor consume.
>
> **Pre-validated decisions are LOCKED** — sketches 002 (wizard shell), 003 (connect-source step), 004 (preview row), and 005 (crowd merchant) all picked winning variants and are referenced verbatim. This contract does not re-litigate them.

Existing tokens from `resources/css/app.css` (all multiples of 4). Phase 16.1 reuses; declares no new sizes.

| Token | Value | Usage in Phase 16.1 |
|-------|-------|---------------------|

| `--space-2` | 8px | Compact element spacing, `wiz-actions` button gap, format-chip gap, mini-tile grid gap (10px) |
| `--space-3` | 12px | Triage-row CTA group gap, mystery-card horizontal gap (16px), preview-table cell padding |
| `--space-4` | 16px | Default element spacing, settings-section padding, card padding, mini-tile vertical padding |
| `--space-5` | 20px | `wiz-card` lower padding strip, settings-section meta-side padding |
| `--space-6` | 24px | Section gaps, mini-tile row vertical margin, drop-zone vertical padding (28px) |
| `--space-8` | 32px | Page section breaks, `wiz-card` bottom padding (32px), preview-table outer margin |
| `--space-10` | 40px | Layout gaps inside the destination page |
| `--space-12` | 48px | Page-level spacing in the main-app surfaces (preview / triage / settings — keeps the `space-y-12` rhythm) |

**Density rules (locked):**

- **Wizard card** — 620px max-width centered, padding `44px 48px 32px`. The 44px / 48px / 32px geometry is sketch-locked from 002D and is the single padding triple inside the wizard.
- **Wizard card on first-import-preview step** — relaxed to ~1120px max-width (single exception to the 620px rule, per `onboarding-wizard.md` `## What to Avoid` clause; the preview table needs the room).
- **Mini-tile row** — 4-column grid, 10px gap, 14px / 12px tile padding.
- **Drop zone** — `28px 20px` padding (the 28px vertical is a deliberate breathing-room exception to the 4-multiple rule because the drop-zone glyph + lead + sub stack needs the room; sketch-validated in 003C).
- **Preview table cells (main app density)** — `12px 14px` cell padding (matches the main-app `--space-3` / `~14px` rhythm; denser than card padding but looser than the dev-console `9px 10px`).
- **Triage row** — `14px 16px` padding, grid template `88px 1.4fr 1fr auto` (sketch 005).
- **Settings section** — two-column grid `280px 1fr`, both halves padded at 22px.
- **Suggest-mapping modal** — fixed 540px width (sketch 005), 24px / 26px padding.
- **Rename popover** — min-width 320px, padding 14px (sketch 004D).
- **Format-chip / payment-type chip / category chip** — 2-8px / 8-14px padding per chip (sketch-locked pill geometry; these are sub-4px vertical to keep glyph + label baseline aligned).

**Exceptions (chip / popover / pill geometry only — never propagate to layout containers):**

- `padding: 2px 8px` on `.ptype-chip` — payment-type chip needs sub-4px vertical to keep glyph + word aligned at `--text-xs`.
- `padding: 3px 8px` on `.cat-chip` — category chip uses 3px vertical for the same reason.
- `padding: 4px 8px` on `.help-others-link` — quiet secondary CTA in triage row; sub-4px vertical keeps it visually lighter than the primary `.pill-btn`.
- `padding: 1px 6px` on the format-chip "recommended" badge — micro-pill inside a chip.
- `28px` vertical inside `.drop-zone` — visual breathing-room exception, sketch-validated; only place 4-multiple is bent inside a container.

These exceptions are pill/chip/popover-only and never propagate to layout containers, cards, or tables.

## Copywriting Contract

### Tone rules (locked, inherits from Phase 16)

- Calm, technical, never celebratory. "1 confirmed, 5 auto-suggested, 2 uncategorized." not "🎉 Almost ready!"
- Verbs are imperative and short: "Continue", "Skip this step", "Resume later", "Save", "Cancel", "Submit as draft PR", "Drop your statement file here", "Pick a category", "Help others identify this".
- Wizard headlines are action-oriented and friendly without being chatty. "Let's get diederik to know your money." sets the only conversational moment; every subsequent H1 reverts to action-led ("Grab a statement, then drop it below").
- Never use "Are you sure?" — the rename popover, the suggest-mapping modal, and the preview-import CTA all carry the consequence in the button label itself.
- Never punctuate kbd hints.
- Mystery codes, IBANs, file format names (CAMT.053 / CSV / MT940 / .eml / .ics PDF), and YAML keys render in monospace, even inline in body copy.
- **Action labels are always verb + noun** (Phase 16 rule, extended here): "Save" inside the rename popover is the single exception because the modal title ("Rename this counterparty") already supplies the noun; for every standalone button, use "Skip this step", "Resume later", "Pick a category", "Help others identify this", "Suggest a name", "Submit as draft PR", "Browse mystery merchants", "Open file in editor".

## Accessibility & Interaction

- **404-not-403 contract continues:** every Phase 16.1 route checks per-user data isolation (Phase 12 contract). The wizard is only reachable by users whose `onboarding_status` is not `completed`; completed users redirected to dashboard.
- **Keyboard model:**
  - Wizard: Tab cycles through mini-tile order (skipped if not interactive) → format chips → drop zone (Enter / Space activates file picker) → skip → continue. Esc cancels current step input but does not exit the wizard (would lose progress). The "Resume later" button is the deliberate exit affordance.
  - Preview row: Tab cycles row affordances in order — Type chip (read-only, skip) → counterparty (Enter on `.desc-fallback` opens popover) → category cell (Tab into chip, Enter activates picker / quick-action buttons). Bulk-confirm reachable via Tab from the legend bar.
  - Rename popover: focus traps; Esc + Cancel + click-outside all dismiss.
  - Suggest-mapping modal: focus traps; Esc + Cancel + click-outside all dismiss (non-destructive flow); first focus is on Field 2 (the only field the user types into).
  - Triage row CTA: Tab reveals `.row-cta` group (focus also triggers opacity-0 → 1 via `:focus-within`); both buttons are sequentially focusable.
- **No `alert()` / `confirm()` browser primitives** — Phase 16 rule extends here. Every confirmation is a styled modal / popover.
- **Form labels** on every input. The `.field-label` class supplies them; `aria-labelledby` references field-labels where the visual layout separates label from input.
- **Icon-only buttons require an accessible name.** The `.cat-action-btn.confirm` and `.cat-action-btn.clear` are the icon-only buttons in this phase; both carry `title` and `aria-label` (e.g. `aria-label="Confirm category"`, `aria-label="Clear category"`). The popover-trigger italic `.desc-fallback` is text-as-button: announce via `role="button"` + `aria-label="Rename counterparty (currently {raw description})"`.
- **Drop zone keyboard:** `role="button"`, `tabindex="0"`, Enter / Space opens file picker, `aria-label="Drop a {format} file here, or press Enter to browse"`. Drag-drop events on the same element.
- **File-format chips keyboard:** `role="radiogroup"` on the row, `role="radio"` on each chip, Tab into the group, Arrow keys move selection, Space activates.
- **Settings toggles keyboard:** Tab to focus, Space toggles. Reuses Phase 16's `.switch` focus-visible 2px emerald outline (already shipped per `app.css` line 542).
- **Tabular numerics** are mandatory on: step counter ("Step 3 of 6"), preview-table dates, preview-table amounts, mystery-card seen-count, stats-strip values, live-counter footer counts, bulk-confirm count chip, settings stats row.
- **Color is never the only signal:**
  - Payment-type chip carries **glyph + word**, not just color. Color is reinforcement; the glyph (`⛁ ⌘ ↔ ⤓ €`) and the word are the primary signals.
  - Category cell state uses **shape + chip style** (dashed-border + italic for auto, solid + checkmark for confirmed, ghost button with `+` glyph for uncategorized) in addition to color.
  - Wizard progress dots use **shape change** (8px circle → 24px rectangle) in addition to color shift.
  - Format-chip "recommended" badge carries the word "recommended", not just the emerald hue.
- **Screen-reader labels for the wizard:**
  - `<header class="wiz-top">` carries `aria-label="Setup wizard header"`.
  - `<div class="wiz-dots" aria-label="Step 3 of 6">` — already in the sketch HTML; matches `aria-current="step"` on the `.wiz-dot.now` element.
  - `<main class="wiz-body">` is the landmark for the step body.
- **Triage row CTA visibility:** opacity-on-hover is layered with `:focus-within` so keyboard users see the CTA group when they tab into the row. The CTA buttons are NOT `display: none` at rest — they're rendered but hover-faded, so screen readers always announce them.
- **YAML preview pane:** marked `aria-live="polite"` and `role="status"` so screen readers announce updates as the user types; the content is decorative for sighted users but functional for the assistive flow ("here's exactly what gets sent").
- **Reduced motion:** see Animation section.
- **High contrast mode:** the chip palette (PIN-violet, online-blue, dd-amber, cash-dark-amber, transfer-muted) all meet WCAG AA against their respective backgrounds in both light and dark themes. The dashed-border affordances (`.cat-chip.auto`, `.help-others-link`, `.cat-uncategorized` on hover) use `border-style: dashed` not `outline: dashed` so Windows High Contrast mode renders the dash pattern correctly.
