## Decisions Made

- **Method name `authorizeProvider` (not `authorize`)** on ConnectEmailStep. Livewire's `Component::authorize($ability, array $arguments = [])` parent method would otherwise be incompatibly overridden; Larastan L10 strict flags this as `method.childParameterType` and `parameter.missing`. Renaming disambiguates and is self-documenting (the wizard authorizes a provider, not an ability).
- **FirstImportStep self-wraps its wide card**, and SetupWizard's parent template branches on `currentStepKey === 'first-import'` to skip its standard `<article class="wiz-card">` wrapper. Without this branch the inner 1120px `wiz-card--wide` would be constrained inside an outer 620px `wiz-card`, defeating the UI-SPEC density-rules exception. The branch keeps the structural pattern uniform (every other step lives inside the parent's wrapper).
- **UploadWizard's submit() is NOT modified** — it still redirects to `/imports/{id}/preview` on success, exactly as the standalone `/imports` wizard does. FirstImportStep adds a manual `markImported()` action so a user who confirms a preview can return to `/setup-wizard` and advance the wizard explicitly. This honours the plan's constraint that no new file-upload surface enters the codebase.
- **Drop-zone uses a kebab-case attribute** (`wire-model="file"`) that Blade auto-converts to the camelCase `$wireModel` prop. The resulting `wire:model="{{ $wireModel }}"` binding mounts inside the parent step's Livewire state.
- **The four connector step blades flip brand references to `beatrax`** to satisfy Plan 01's `noDiederikLiteralAfterRename` arch invariant. Plan 03a's existing welcome/done/setup-wizard blades and ResumeWizardTest/ReRunWizardTest fixtures still carry the UI-SPEC-mandated `diederik` literal; that pre-existing failure is the brand-rename plan's responsibility and is documented in `deferred-items.md` as out of scope here.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Renamed `authorize` to `authorizeProvider` on ConnectEmailStep**

- **Found during:** Task 2 (after Larastan ran on the new components)
- **Issue:** `public function authorize(string $provider): void` collided with `Livewire\Component::authorize($ability, array $arguments = [])` — Larastan L10 strict flagged a `method.childParameterType` violation (non-contravariant override) and `parameter.missing` (the override drops `$arguments`).
- **Fix:** Renamed the method to `authorizeProvider`. Updated the blade view to use `wire:click="authorizeProvider('gmail')"` / `wire:click="authorizeProvider('microsoft')"`. Updated the docblock and the test fixtures accordingly.
- **Files modified:** `Modules/Onboarding/Internal/Http/Livewire/Steps/ConnectEmailStep.php`, `Modules/Onboarding/Resources/views/livewire/steps/connect-email-step.blade.php`
- **Verification:** Larastan L10 strict clean on the full Onboarding module; `vendor/bin/pest Modules/Onboarding/tests/Feature/EmailStepEmbedsOAuthModalTest.php` passes 6/6 cases.
- **Committed in:** `8f1f1ce` (Task 2 commit)

**2. [Rule 3 - Blocking] Parent SetupWizard template needed a branch for the first-import wide card**

- **Found during:** Task 2 (during blade integration smoke test)
- **Issue:** The plan asked FirstImportStep's blade to wrap its content in `<x-onboarding::wiz-card :wide="true">`. The SetupWizard parent already wraps every active step in `<article class="wiz-card">` (the standard 620px variant). Without intervention the wide variant rendered nested inside the standard variant, constraining the inner card to 620px and defeating the entire UI-SPEC density-rules exception that motivates the step.
- **Fix:** Added a `@php $selfWrapping = $currentStepKey === 'first-import'; @endphp` branch in `setup-wizard.blade.php`. When true, the parent skips its own wrapper and lets FirstImportStep's blade render its own `<x-onboarding::wiz-card :wide="true">`; otherwise the parent's 620px wrapper applies as before. The resume banner stays visible via a `wiz-resume-banner-floating` variant alongside the wide card.
- **Files modified:** `Modules/Onboarding/Resources/views/livewire/setup-wizard.blade.php`
- **Verification:** `vendor/bin/pest Modules/Onboarding/tests/Feature/FirstImportStepWidthTest.php` confirms `wiz-card--wide` is present on FirstImportStep and absent on ConnectBankStep.
- **Committed in:** `8f1f1ce` (Task 2 commit)

## Issues Encountered

- **Worktree vendor symlink redirected Pest's rootPath to the main repo.** Initial pest runs against the worktree failed every test with "Call to a member function connection() on null" because Pest's `bin/pest` resolves `dirname(autoload.php, 2)` to determine the root path. With `vendor/` symlinked from the main repo, the resolved root pointed at the main repo and the `tests/Pest.php` bindings for `Modules/Onboarding/tests/Feature` never matched the worktree's test files (so RefreshDatabase + the TestCase extension never applied). Resolved by replacing the symlink with an `rsync -a --link-dest` clone so `realpath(vendor/autoload.php)` resolves inside the worktree. Also copied `public/build/` (vite manifest) and `database/database.sqlite` (seeded DB file) into the worktree. Environment fix, not a code change.
