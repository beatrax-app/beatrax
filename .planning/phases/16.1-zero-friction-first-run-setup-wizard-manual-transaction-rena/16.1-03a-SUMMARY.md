## Decisions Made

- **Route URL stays `/setup-wizard`, route name stays `setup`.** Prior agent's call — keeping it because `/setup` is already owned by `Modules/Desktop/Routes/web.php` (the migration-splash route with name `desktop.setup`). The EnsureDatabaseReady middleware exempts the route-name prefix `setup`, which matches our wizard's route name; downstream callers (SignupPage redirect, future Settings tour link) use `route('setup')` symbolically so a future URL rename is a single config change. The plan's `<must_haves>` clause specifying "/setup" was therefore interpreted as "the named route `setup`", with the URL chosen to avoid the Desktop collision.
- **Livewire 3 `$this->redirect()` is the only working navigation protocol from a Livewire mount/action method.** Returning a `RedirectResponse` is silently dropped — confirmed by the ReRunWizard HTTP test (`$this->get(route('setup'))->assertRedirect('/')` failed against the original `return $redirector->to('/')` shape; same call with `$this->redirect('/')` passes). Same fix applied to `SetupWizard::skipRest()` and `DoneStep::finish()`. Mirrors the existing pattern in `Modules/EmailScan/.../InboxesPage::reconnect`.
- **Connector-step placeholders render in-place until Plan 03b lands.** Rather than leaving the 4 cases empty (Livewire mount exception when a user resumes mid-connect-card), the parent view renders a calm "Step pending — connector lands in a follow-up plan" message with the step_key inline. Plan 03b drops the placeholder by registering real `<livewire:onboarding.steps.connect-bank-step />` components against the same dispatch contract.
- **Static-step blades use raw Tailwind for glyph rows / next-step rows.** Plan 03b ships the bespoke `<x-onboarding::vd-glyph>` / `<x-onboarding::wiz-card>` Blade components; until then the markup is inline. UI-SPEC §"Component Inventory" calls these primitives out; the swap is a Plan-03b mechanical edit.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] SetupWizard's mount-returned RedirectResponse was silently dropped by Livewire 3, so the "all steps done → bounce to /" sentinel branch landed the user on a stale welcome view instead of redirecting.**

- **Found during:** Task 3 (ReRunWizardTest::redirects-to-slash-when-every-step-done)
- **Issue:** The plan called for `return $redirector->to('/')` from `mount()` for the empty-sentinel branch. Livewire 3's full-page renderer ignores a Laravel RedirectResponse return and proceeds to render the component. The HTTP test `$this->get(route('setup'))->assertRedirect('/')` failed with a 200 against a fully-rendered wizard page.
- **Fix:** Switched to `return $this->redirect('/')` (Livewire-aware redirect that the dispatcher honours). Applied the same fix to `SetupWizard::skipRest()` and `DoneStep::finish()` — both are action methods invoked via `wire:click`, where the same `RedirectResponse`-is-dropped rule applies. Signatures shifted from `: RedirectResponse` to `: mixed`. Unused imports (`Illuminate\Http\RedirectResponse`, `Illuminate\Routing\Redirector`) removed.
- **Files modified:** `Modules/Onboarding/Internal/Http/Livewire/SetupWizard.php`, `Modules/Onboarding/Internal/Http/Livewire/Steps/DoneStep.php`
- **Verification:** ReRunWizardTest now passes (both cases); Larastan + Pint clean for both files; existing tests still green.
- **Committed in:** `b8870b8`

**2. [Rule 1 - Bug] Pest `assertSee()` default-escapes apostrophes, so `assertSee("Let's get diederik...")` fails against the (correctly) literal-apostrophe Blade output.**

- **Found during:** Task 3 (initial test run)
- **Issue:** Blade's `{{ }}` escapes `"` and `&` but a literal `'` in the source text (`<h1>Let's...</h1>` outside any `{{ }}`) renders as-is. Pest's `assertSee` defaults to `escape=true`, which transforms the assertion string's apostrophe to `&#039;` before searching — yielding a no-match.
- **Fix:** Test assertions use the substring `'get diederik to know your money'` (no special characters), which matches the rendered HTML exactly.
- **Files modified:** `Modules/Onboarding/tests/Feature/ResumeWizardTest.php`, `Modules/Onboarding/tests/Feature/ReRunWizardTest.php`
- **Verification:** Both feature tests pass.
- **Committed in:** `84bf54b` (part of the test commit; fixed before the test was committed).
