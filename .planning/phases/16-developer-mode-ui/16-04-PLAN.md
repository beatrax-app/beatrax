## Phase Goal

**As a** developer in the Dev Console, **I want to** POST a SAFE-tier command name to /dev/artisan/spawn, receive a run_id, and tail its stdout via a GET /dev/artisan/stream/{run_id} SSE connection — AND, if the page refreshes mid-run, reconnect to the live stream of the same run_id without losing any new lines emitted after the reconnect — **so that** D-16's verbatim "pid + run_id persisted in cache so a page refresh reconnects to the live stream" guarantee holds before 16-04b layers the triple-gate, audit pipeline, heartbeat, and full runner UI on top of this pipeline.

## ARCHITECTURE LOCK — D-16 spawn-then-tail (was: spawn-in-controller)

CONTEXT D-16 verbatim: "`pid` + `run_id` persisted in cache (database driver) so a page refresh reconnects to the **live stream**." This rules out architecture (a) (spawn-in-controller) where the spawning HTTP request owns the Process for its lifetime and a refresh re-reads the audit row only. The committed architecture is **(b) — spawn-then-tail**:

1. POST /dev/artisan/spawn: a separate HTTP request starts the Process detached, redirecting stdout + stderr into a per-run tmp file at `storage/app/dev_mode/runs/{run_id}.out`. Returns `{ run_id, pid }`. The spawning request does NOT block on the Process; the Process keeps running after the request returns.
2. GET /dev/artisan/stream/{run_id}: the SSE controller adopts the cached PID + tmp-file path via RunRegistry::find($runId). It opens the tmp file read-only, seeks to (typically) offset 0 on first connect or to the client-supplied `Last-Event-ID` header offset on reconnect, then loops: `clearstatcache(); $size = filesize($path);` → if size grew, read+emit the new bytes; check `posix_kill($pid, 0)` for liveness; if process is gone, emit `event: done` + close.
3. POST /dev/artisan/cancel/{run_id}: reads the cached PID, sends SIGTERM, 3s grace, then SIGKILL. Marks the run cancelled in RunRegistry. The SSE controller's liveness check observes the process gone + emits its done event with the cancel marker.

This is the SAME tail primitive 16-05's LogStreamController uses (fseek + clearstatcache); the shared seam is `Modules/DevMode/Internal/Process/FileTailer.php` (created here, reused there). Document the decision to share the tailer in the SUMMARY so 16-05 inherits it instead of re-implementing.

STREAM TRANSPORT LOCK (D-16 / D-28 — repeated from 16-03): `wire:stream` remains REJECTED. SSE controller path is the only acceptable transport.

`CommandSpawner::start(string $command, array $args, int $callerUserId, string $tier): string` — architecture (b):
- Generates `run_id = (string) Str::uuid()`.
- Computes `$outPath = storage_path("app/dev_mode/runs/{$runId}.out");` (the per-run tmp file). Ensures the directory exists (mkdir -p semantics).
- Constructs `new Process(array_merge(['php', 'artisan', $command], $this->flattenArgs($args)), base_path())`.
- `setTimeout(null)` — the SSE controller owns the time budget (RESEARCH Open Q3: 24h cache TTL on `pid` + `run_id`).
- Configures the Process so its stdout + stderr are both piped into `$outPath`. Symfony Process exposes `mustRun()` + `getOutput()` but NOT a built-in stdout-to-file redirect. Two viable approaches:
  - (i) **Disable Symfony's output capture entirely** (`disableOutput()`) and pass shell-level redirection: `Process::fromShellCommandline(escapeshellcmd("php artisan $command ...args") . " > $outPath 2>&1 &")`. The `&` detaches so the HTTP request returns immediately. The risk: `Process::fromShellCommandline` enables shell interpolation — the args MUST be `escapeshellarg`'d before assembly. Whitelist guarantees the command name is safe; args pass through `escapeshellarg` per ArgSpec rules + validation.
  - (ii) **Use array form Process + start() (non-blocking) + a registered tick callback** that appends `getIncrementalOutput()` to the tmp file. The HTTP request returns after `start()` even though the Process keeps running. The risk: PHP-FPM may kill the worker on response close; mitigate via `ignore_user_abort(true)` + a register_shutdown_function that finishes the tick loop. The Symfony docs do NOT promise this works under FPM — the Linux process model says the Process child survives parent death, but the buffered output piped through the parent does not.
- **Decision:** Use approach (i) — shell-level redirect + `&` detach. It is the only approach that survives FPM worker shutdown reliably (the Process becomes a session leader independent of the HTTP request). Document the `escapeshellarg` discipline in CommandSpawner's PHPDoc.
- After spawn: `$this->registry->store($runId, $process->getPid(), $command, $args, now(), $callerUserId, $tier, $outPath)`.
- Returns `$run_id`.
- The `flattenArgs($args)` helper formats the args per Symfony Process expectations: positional args first, then `--key=value` for options. The ArgSpec DTO tells the spawner which is which. Every arg passes through `escapeshellarg`.

`ArtisanStreamController` (`__invoke(string $runId, Request $request, CurrentUser $user, RunRegistry $registry, FileTailer $tailer): StreamedResponse`):
- Verifies the request user is `is_developer === true` (defense-in-depth — the route already has `ensureDeveloperMode`).
- Resolves RunRecord from RunRegistry; 404 if absent.
- Defense-in-depth ownership: the controller checks `$record->callerUserId === $user->user()->id` — a developer cannot inspect another developer's run stream by guessing the UUID.
- Resolves starting offset from `Last-Event-ID` header (browser sends this on EventSource reconnect) or from the `?from=` query param; default 0.
- Returns `response()->stream($cb, 200, ['Content-Type' => 'text/event-stream', 'Cache-Control' => 'no-cache', 'X-Accel-Buffering' => 'no'])`.
- Inside the closure: loop body:
  - `$result = $tailer->tailOnce($record->outPath, $offset); $offset = $result['newOffset']; if ($result['chunk'] !== '') { echo 'id: '.$offset."\n"; echo 'data: '.json_encode(['line' => $result['chunk']])."\n\n"; @ob_flush(); @flush(); }`
  - Liveness: `if (! posix_kill($record->pid, 0)) { echo "event: done\ndata: ".json_encode(['exit' => $this->resolveExitCode($record)])."\n\n"; break; }`
  - `if (connection_aborted()) break;`
  - `usleep(150_000);`
- RESEARCH Pitfall 4 mitigation: set `X-Accel-Buffering: no`, ini_set output_buffering, ob_flush() + flush() per chunk.
- NOTE: this plan does NOT write the audit row. 16-04b will add a `finalize($runId)` step that writes the audit row from the captured tmp-file contents — at that point the SSE controller calls into the audit pipeline. This plan's controller emits only the SSE protocol; the run is "complete" in RunRegistry terms but unaudited until 16-04b lands.
