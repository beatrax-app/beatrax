<objective>
Wave 1: Land the entire Phase 5 schema (chain_links + card_statements + card_statement_credits + back-population), the corresponding Eloquent Models, the typed DTOs, AND the CardStatementStateMachine which is the only legal mutator of `card_statements.state` (D-95). Purpose: A vertical schema slice — every table + its enum CHECK triggers + its model + the state machine that guards it. The back-population migration immediately populates `card_statements` from existing Phase 3 `statement_summaries` rows so the moment Wave 4 ships the dashboard tile, the user sees real data. The state machine + its BoundaryArchTest invariant (D-95 was added in Wave 0 plan 05-01) is enforced before any resolver lands in Wave 2, preventing the "resolver patches state directly" anti-pattern.

Output:
- Four migrations: `create_chain_links_table`, `create_card_statements_table`, `create_card_statement_credits_table`, `backpopulate_card_statements_from_statement_summaries`. All forward-only, idempotent in dev (`insertOrIgnore` on back-population).

- Tests: schema test (CHECK triggers reject invalid enum values), back-population test (Phase 3 fixture data appears in card_statements), state machine unit test (open → partially_settled → settled / overpaid lifecycle).
