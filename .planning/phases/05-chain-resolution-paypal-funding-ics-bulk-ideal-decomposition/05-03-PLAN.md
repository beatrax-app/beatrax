use Modules\Chains\Internal\CardStatementStateMachine;

final class IcsSettlementResolver
{
    public const AMOUNT_TOLERANCE_MINOR = 500;       // ±€5 (D-97)
    public const AMOUNT_TOLERANCE_PERCENT = 2;        // ±2% (D-97)
    public const PERIOD_WINDOW_DAYS = 10;             // ±10 days (D-97)
    public const SETTLED_TOLERANCE_MINOR = 1;         // ±€0.01 floor (D-95)

    public function __construct(
        private readonly DatabaseManager $db,
        private readonly Clock $clock,
        private readonly CardStatementStateMachine $stateMachine,
        private readonly PairLookup $pairLookup,
        private readonly \Modules\Chains\Internal\ChainLinkInsertHelper $inserter,

    public function resolveForUser(User $user): void
    {
        // Per RESEARCH Pattern 4:
        // 1. SELECT every transfer_in T where:
        //    - T.user_id = $user->id
        //    - T.account_id matches an ICS-kind Account
        //    - NOT EXISTS confirmed chain_link of kind='ics_bulk_settle' from T
        $connection = $this->db->connection();
        $candidateTransfers = $connection
            ->table('transactions')
            ->join('accounts', 'accounts.id', '=', 'transactions.account_id')
            ->leftJoin('chain_links', function ($join) {
                $join->on('chain_links.from_transaction_id', '=', 'transactions.id')
                     ->where('chain_links.kind', 'ics_bulk_settle')
                     ->where('chain_links.state', 'confirmed');
            })
            ->where('transactions.user_id', $user->id)
            ->where('accounts.kind', 'ics_card')
            ->where('transactions.type', 'transfer_in')
            ->whereNull('chain_links.id')   // not yet resolved
            ->select(
                'transactions.id',
                'transactions.account_id',
                'transactions.settled_amount_minor',
                'transactions.amount_minor',
                'transactions.posted_at',
                'transactions.booked_at',
            )
            ->get();

        foreach ($candidateTransfers as $transfer) {
            $this->resolveOne($transfer, $user);
        }

        // refund rows whose posted_at falls inside an already-settled
        // statement period. (D-98 — emits chain_link from refund → original
        // purchase + card_statement_credits row of reason='refund_after_close')
        $this->resolveRefundsAfterClose($user);
    }

    // ... private helpers: resolveOne(), findCandidateStatement(),

**Algorithm details (per RESEARCH Pattern 4 lines 696-757):**

`resolveOne($transfer, $user)`:
1. Find candidate `card_statement` S where:
   - `S.user_id = $user->id`
   - `S.account_id = $transfer->account_id`
   - `S.state IN ('open', 'partially_settled')`
   - `S.period_end BETWEEN $transfer->posted_at - 10 days AND $transfer->posted_at + 10 days`
   - `abs(S.total_amount_minor - $transfer->settled_amount_minor) <= max(500, S.total_amount_minor * 0.02)`
2. If multiple candidates: pick the one whose `period_end` is closest to `$transfer->posted_at`.
3. If no candidate: skip (resolver does not write a chain_link — leaves the transfer for a future pass when the statement lands).
4. Pull all expense rows E in the statement period (`E.posted_at BETWEEN S.period_start AND S.period_end`, `E.type IN ('expense', 'refund')`, `E.account_id = S.account_id`, `E.user_id = $user->id`, NOT EXISTS confirmed chain_link of `kind='ics_bulk_settle'` to E).
5. Pull prior credits: `SUM(card_statement_credits.amount_minor) WHERE to_statement_id = S.id`.
6. Compute `delta_minor = SUM(E.settled_amount_minor) - prior_credits_minor - $transfer->settled_amount_minor`.
7. `tolerance_threshold = max(self::AMOUNT_TOLERANCE_MINOR, abs(S.total_amount_minor) * self::AMOUNT_TOLERANCE_PERCENT / 100)`.
8. If `abs(delta_minor) <= tolerance_threshold`:
   - Insert N chain_links (one per expense E_i), state='confirmed', confidence=1.0, resolver='auto', evidence per spec.
   - Call `$this->stateMachine->applySettlement(S.id, $transfer->settled_amount_minor, $user)`.
   - If state lands as `overpaid` (returned in StatementSettlement DTO): insert `card_statement_credits` row with reason='overpayment', amount_minor=abs(newOpen), from_statement_id=S.id, to_statement_id=NULL (next statement may not exist yet — a future resolver pass updates this).
9. Else (exceeds tolerance):
   - Insert ONE chain_link of state='candidate', confidence = max(0.6, min(0.99, 1.0 - abs(delta_minor) / max(1, abs(S.total_amount_minor)))), kind='ics_bulk_settle', from=transfer, **to_transaction_id=NULL** (issue #10 fix — Wave 1 schema now allows NULL for exceeded-tolerance ics_bulk_settle candidates via the chain_links_to_transaction_id_check_insert trigger pair). evidence.tolerance_used = "exceeded". The UI dereferences via `evidence.statement_id`, not via `to_transaction_id`. Wave 3 `ChainLinkQuery::forTransaction` MUST handle `to_transaction_id IS NULL` gracefully (walk stops at that node — no children to dereference).

`resolveRefundsAfterClose($user)`:
1. Find every `refund` row whose `posted_at` falls inside a `settled` or `overpaid` card_statement period AND lacks a confirmed chain_link of `kind='ics_bulk_settle'`.
2. For each: find the original purchase row in the same period (heuristic: same merchant + opposite-signed amount within the period; if multiple matches, pick the most-recent).
3. Insert chain_link from refund → original purchase, `kind='ics_bulk_settle'`, `state='confirmed'`, `confidence=1.0`, evidence includes `reason='refund_after_close'`.
4. Find the next-open statement for the same Account (state IN ('open','partially_settled'), period_start > closed statement's period_end, ordered by period_start ASC, limit 1).
5. Insert card_statement_credits row with reason='refund_after_close', from_statement_id=closed statement.id, to_statement_id=next open statement.id (or NULL if none), amount_minor=abs(refund.settled_amount_minor).

PaypalFundingResolver (Wave 3) already json_encodes evidence at insert time. IcsSettlementResolver MUST use the same encoding. Promote the encode logic to a shared internal helper so both resolvers call it:

```php
<?php

declare(strict_types=1);

namespace Modules\Chains\Internal;

use Illuminate\Database\DatabaseManager;
use Modules\Core\Models\User;
use Modules\Core\Public\Contracts\Clock;

/**
 * Shared INSERT path for chain_links. Both IcsSettlementResolver and
 * PaypalFundingResolver call this so evidence JSON encoding stays
 * byte-identical at every write site (issue #4).
 *
 * Also enforces the per-pair pre-insert guard (rejected-pair stay-
 * rejected behavior) so neither resolver duplicates the check.
 *
 * @internal Resolvers only.
 */
final class ChainLinkInsertHelper
{
    public function __construct(
        private readonly DatabaseManager $db,
        private readonly Clock $clock,
    ) {}

    /**
     * @param array<string, mixed> $row
     *   Required keys: user_id, from_transaction_id, kind, state, confidence, resolver, evidence(array).
     *   Optional: to_transaction_id (int|null — NULL only valid for exceeded-tolerance
     *   ics_bulk_settle candidates per Wave 1 schema rule).
     */
    public function insertIfNotExists(array $row, User $user): bool
    {
        $existsQuery = $this->db->connection()->table('chain_links')
            ->where('user_id', $user->id)
            ->where('from_transaction_id', $row['from_transaction_id'])
            ->where('kind', $row['kind']);
        if (($row['to_transaction_id'] ?? null) === null) {
            $existsQuery->whereNull('to_transaction_id');
        } else {
            $existsQuery->where('to_transaction_id', $row['to_transaction_id']);
        }
        if ($existsQuery->exists()) {
            return false;
        }
        $now = $this->clock->now()->toDateTimeString();
        $this->db->connection()->table('chain_links')->insert([
            'user_id' => $row['user_id'],
            'from_transaction_id' => $row['from_transaction_id'],
            'to_transaction_id' => $row['to_transaction_id'] ?? null,
            'kind' => $row['kind'],
            'state' => $row['state'],
            'confidence' => $row['confidence'],
            'resolver' => $row['resolver'],
            'evidence' => json_encode(
                $row['evidence'],
                JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES,
            ),
            'created_at' => $now,
            'updated_at' => $now,
        ]);
        return true;
    }
}
```

    use InteractsWithQueue;
    use Queueable;
    use SerializesModels;

    public function __construct(public readonly int $userId) {}

    public function uniqueFor(): int
    {
        return 600;   // 10-minute lock ceiling

    {
        return Cache::driver('redis');
