## Operator recovery

### Stuck Redis unique-lock keys (Pitfall 1)

When a worker crashes mid-job, the per-user unique-lock key `unique-lock:resolve-chain-links:{userId}` may remain in Redis blocking the next `ResolveChainLinksJob` dispatch for that user. The lock has a 600-second TTL (D-101) but pre-TTL recovery is sometimes necessary.

List stuck locks:
```bash
docker exec diederik-redis redis-cli KEYS '*unique-lock:resolve-chain-links:*'
```

Clear a specific lock:
```bash
docker exec diederik-redis redis-cli DEL '<key>'
```

Clear ALL stuck locks (use with care — only when no jobs are mid-run):
```bash
docker exec diederik-redis redis-cli --scan --pattern 'unique-lock:resolve-chain-links:*' | xargs -I {} docker exec diederik-redis redis-cli DEL {}
```

> An artisan command `php artisan chains:clear-stuck-locks --user=<id>` that wraps the equivalent via the injected `Cache::driver('redis')` Repository is deferred to a future phase — the redis-cli snippets above are sufficient for Phase 5.
