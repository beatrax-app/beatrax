<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser WebAuthn assertion → server | The assertion is untrusted until verified against the stored public key, counter, rpId, and full origin |
| per-device biometric secret → data key | A successful assertion releases the second wrap; the PIN wrap remains the root (D-14) |
| enrollment → data key exposure | Enrollment wraps the live data key under a new per-device secret; only possible while already unlocked |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-19 | Spoofing | Replayed biometric assertion | mitigate | WebAuthn signature counter checked and incremented per assertion (BiometricDeviceStore::updateCounter); a non-increasing counter is rejected |
| T-05-20 | Spoofing | Forged assertion / origin mismatch | mitigate | AuthenticatorAssertionResponseValidator verifies signature, rpId='localhost', and full origin from config('app.url') (RESEARCH Pitfall 3) |
| T-05-21 | Elevation of privilege | Biometric endpoints unreachable while locked OR reachable as a bypass | mitigate | The two biometric routes are the ONLY additions to AppLockMiddleware ALLOWED_ROUTE_NAMES; they release the key only on a verified assertion, never unconditionally |
| T-05-22 | Spoofing | Biometric brute force | mitigate | N failures disable the button until the next PIN unlock re-arms (D-16); only PIN failures feed the sign-out meter — biometric failures never sign out |
| T-05-23 | Information disclosure | Auto-fired OS prompt leaking presence/timing | mitigate | Button-tap-to-prompt only (D-15); no navigator.credentials.get on render |
</threat_model>
