<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS app-switcher / bystander → screen | A backgrounded or idle window must not expose balances in screenshots or to onlookers |
| client tab → other tabs | One tab unlocking/locking must propagate without leaking the key across tabs |
| client idle timer → server | The client timer is convenience only; the server last_activity_at is the authority |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-11 | Information disclosure | OS screenshot of financial data | mitigate | Veil drops in <=80ms on visibilitychange/blur (D-07); pointer-events set synchronously; prefers-reduced-motion keeps it instant (RESEARCH pitfall 4) |
| T-05-12 | Information disclosure | PIN digits cached by OS / password manager | mitigate | PIN rendered as bullet dots in an aria-live region, not <input type=password>; no autocomplete; digits never leave the component until submit |
| T-05-13 | Elevation of privilege | Idle client timer trusted as authority | mitigate | Idle dispatch only asks the server to lock; AppLockMiddleware + last_activity_at remain authoritative (D-17) |
| T-05-14 | Tampering | Stale veil after another tab unlocks | accept | BroadcastChannel is the UX signal; the next Livewire request reconciles against the authoritative session (RESEARCH pitfall 6) — acceptable sub-second latency |
</threat_model>
