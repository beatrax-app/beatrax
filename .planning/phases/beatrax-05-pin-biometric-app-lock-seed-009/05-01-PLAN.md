<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user PIN → server | The PIN is untrusted input; it must never be persisted in plaintext and only ever reaches Argon2id |
| DB at rest → process | Wrapped key blobs sit in `user_app_lock_configs`; they are useless without the PIN/password-derived wrap key |
| Phase 14 consumer → AppLockKeyService | Cross-module boundary; only the Public service may release the key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information disclosure | PinHasher | mitigate | PIN stored only as `sodium_crypto_pwhash_str` Argon2id verifier; raw PIN never written to a column or log (asserted: pin_hash starts `$argon2id$`) |
| T-05-02 | Tampering | AppLockKeyWrap | mitigate | Authenticated `sodium_crypto_secretbox`; unwrap returns false on any tamper/wrong-key (unit-tested), callers must treat false as "do not use" |
| T-05-03 | Information disclosure | AppLockKdf derived key | mitigate | Docblock + caller contract mandates `sodium_memzero` on the derived wrap key after use (BackupEncryptor discipline); enforced in consuming plans |
| T-05-04 | Elevation of privilege | AppLockKeyService.release | mitigate | release() returns null whenever the session is locked — the lock state is the single gate; no bypass path |
| T-05-05 | Tampering | Argon2id KDF params from DB | accept | Unlike BackupEncryptor (attacker-controlled file header), KDF limits here are compile-time constants (INTERACTIVE), not read from untrusted input — no MAX_OPSLIMIT guard needed |
</threat_model>
