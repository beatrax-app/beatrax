Algorithm (verbatim from RESEARCH.md Example 3 — lines 850–893 — and D-76 / D-77):
1. If `$tx->type` ∈ {`refund`, `fee`, `adjustment`} → return unchanged (preserve already-classified)
2. Cross-account-IBAN check (UNIVERSAL — applies to every source format):
   - If `$tx->counterpartyIban !== null` AND `Account::where('user_id', $user->id)->where('iban', $tx->counterpartyIban)->where('id', '!=', $tx->accountId)->exists()`:
     - Return `$tx->withType($tx->amountMinor < 0 ? 'transfer_out' : 'transfer_in')`
3. PayPal-specific source-format event-type map:
   - If `$tx->rawPayload['format'] === 'paypal-csv'`:
     - Read the FIRST event in `$tx->rawPayload['events']` to get the parent event type
     - Look up via `$this->eventTypes->transactionType($eventType, $language)` (language from rawPayload extras OR fall back to first registered language)
     - Apply that type if not already a transfer (the cross-account step takes precedence — `General Withdrawal` to a known own IBAN becomes `transfer_out` regardless of the map)
4. Income detector (D-77 — subtractive):
   - If `$tx->amountMinor > 0` AND `$tx->type` ∉ {`transfer_in`, `transfer_out`, `refund`, `fee`} → return `$tx->withType('income')`
5. Default: return `$tx` unchanged (NormalizeStage's amount-sign default — negative = expense, positive will have been flipped to income in step 4)

Pitfall 3 invariant: NEVER query `transactions` from this stage (no `Transaction::query()`). The stage is a pure pre-load transformer.

Algorithm:
1. Defensive: assert `$event->transaction->user_id === $event->user->id`; throw on mismatch (T-04-02)
2. Bail if `$tx->type` ∉ {`transfer_out`, `transfer_in`}
3. Bail if `$tx->pair_transaction_id !== null` (already paired — defensive)
4. Bail if `$tx->counterparty_iban === null`
5. Look up the partner account: `Account::where('user_id', $user->id)->where('iban', $tx->counterparty_iban)->first()`; bail if null
6. Window: `$tx->booked_at->subDays(3)` … `$tx->booked_at->addDays(3)`
7. Partner query (uses the partial index from the migration):
   ```php
   Transaction::query()
       ->where('user_id', $user->id)
       ->where('account_id', $partnerAccount->id)
       ->where('amount_minor', -$tx->amount_minor)
       ->where('currency', $tx->currency)
       ->whereBetween('booked_at', [$windowStart, $windowEnd])
       ->whereNull('pair_transaction_id')
       ->whereIn('type', ['transfer_out', 'transfer_in'])
       ->where('id', '!=', $tx->id)
       ->orderBy('booked_at')
       ->first();
   ```
8. If partner === null: return (half-pair state per D-74)
9. Symmetric write — inherit outer transaction (NO `DB::transaction(...)` wrapper):
   ```php
   $tx->pair_transaction_id = $partner->id;
   $tx->save();
   $partner->pair_transaction_id = $tx->id;
   $partner->save();
   ```

Anti-patterns: DO NOT add `ShouldHandleEventsAfterCommit` (Pitfall 1). DO NOT update `type` (Pitfall 3). DO NOT wrap in nested transaction (inherits frame).

    public function __construct(

    public function run(CanonicalTransaction $tx, User $user): CanonicalTransaction
    {
        // Step 1: preserve already-classified rows (rare but defensive).
        if (in_array($tx->type, ['refund', 'fee', 'adjustment'], true)) {
            return $tx;
        }

        // Step 2: cross-account-IBAN check (UNIVERSAL — every source format).
        // When the counterparty IBAN matches one of the user's own Account
        // rows, the row is a transfer leg. Same-currency / window matching
        // happens later in the listener; here we only TYPE the row.
        if ($tx->counterpartyIban !== null) {
            $isOwnAccount = Account::query()
                ->where('user_id', $user->id)
                ->where('iban', $tx->counterpartyIban)
                ->where('id', '!=', $tx->accountId)
                ->exists();
            if ($isOwnAccount) {
                return $tx->withType($tx->amountMinor < 0 ? 'transfer_out' : 'transfer_in');
            }
        }

        // Step 3: source-format event-type map (PayPal only — ASN/ICS adapters
        // do not emit event-type metadata in rawPayload).
        if (is_array($tx->rawPayload) && ($tx->rawPayload['format'] ?? null) === 'paypal-csv') {
            $events = $tx->rawPayload['events'] ?? [];
            if (is_array($events) && $events !== [] && isset($events[0]['type'])) {
                $parentEventType = (string) $events[0]['type'];
                $language = (string) ($tx->rawPayload['language'] ?? PaypalCsvLanguageProfile::supported()[0] ?? 'en');
                try {
                    $mappedType = $this->eventTypes->transactionType($parentEventType, $language);
                    return $tx->withType($mappedType);

                    // Unknown event type — fall through to subtractive default.
                    // The adapter raised an UnknownPaypalEventTypeException at parse-time;
                    // if a row reached here without typing it means the event-type map only
                    // resolves classify() but not transactionType() for this row's parent.
                }
            }
        }

        // Step 4: subtractive income detector (D-77).
        if ($tx->amountMinor > 0
            && ! in_array($tx->type, ['transfer_in', 'transfer_out', 'refund', 'fee'], true)) {
            return $tx->withType('income');
        }

        // Step 5: default — keep NormalizeStage's amount-sign default
        // (negative = expense, positive will be re-classified above).
        return $tx;
    }

<?php

declare(strict_types=1);

namespace Modules\Transfers\Internal\Listeners;

use Illuminate\Database\DatabaseManager;
use Modules\Import\Public\Events\TransactionImported;
use Modules\Ledger\Models\Account;
use Modules\Ledger\Models\Transaction;

final class PairTransferCandidates
{
    /**
     * ±3-day window per D-73. Stored as an integer constant so the
     * tolerance is greppable and reusable in tests.
     */
    private const WINDOW_DAYS = 3;

    public function __construct(
        private readonly DatabaseManager $db,
    ) {}

    public function handle(TransactionImported $event): void
    {
        // Defensive: T-04-02 mitigation — never write to another user's
        // transactions even if an event carries a mismatched payload.
        if ($event->transaction->user_id !== $event->user->id) {
            throw new \RuntimeException(
                'TransactionImported user/transaction user_id mismatch — refusing to pair.'
            );
        }

        $tx = $event->transaction;
        $user = $event->user;

        // Layer-1 only fires when this row is itself a transfer leg.
        if (! in_array($tx->type, ['transfer_out', 'transfer_in'], true)) {
            return;
        }

        // Defensive: skip if already paired.
        if ($tx->pair_transaction_id !== null) {
            return;
        }

        // The counterparty IBAN must be present (synthetic IBANs 'ICS-CARD',
        // 'PAYPAL' participate as ordinary Account.iban values per D-73).
        if ($tx->counterparty_iban === null) {
            return;
        }

        $partnerAccount = Account::query()
            ->where('user_id', $user->id)
            ->where('iban', $tx->counterparty_iban)
            ->first();
        if ($partnerAccount === null) {
            return;
        }

        $windowStart = $tx->booked_at->subDays(self::WINDOW_DAYS);
        $windowEnd = $tx->booked_at->addDays(self::WINDOW_DAYS);

        /** @var Transaction|null $partner */
        $partner = Transaction::query()
            ->where('user_id', $user->id)
            ->where('account_id', $partnerAccount->id)
            ->where('amount_minor', -$tx->amount_minor)
            ->where('currency', $tx->currency)
            ->whereBetween('booked_at', [$windowStart, $windowEnd])
            ->whereNull('pair_transaction_id')
            ->whereIn('type', ['transfer_out', 'transfer_in'])
            ->where('id', '!=', $tx->id)
            ->orderBy('booked_at')
            ->first();

        if ($partner === null) {
            return;   // half-pair state per D-74; partner may land later
        }

        // Symmetric write — inherits the outer RecordTransactions transaction frame.
        // NO new DB::transaction wrapper (Pitfall 1 + Anti-pattern note in PATTERNS).
        $tx->pair_transaction_id = $partner->id;
        $tx->save();
        $partner->pair_transaction_id = $tx->id;
        $partner->save();
    }
}
