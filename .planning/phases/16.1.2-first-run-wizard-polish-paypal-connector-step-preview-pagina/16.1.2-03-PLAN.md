<objective>
Replace the static "5 rows shown · N more" footer with an interactive "Load more (N remaining)" button that adds 25 rows per click for that section only — bank section, card section, PayPal section, email section each expand independently (D-09 through D-13). Extend `BuildConsolidatedPreviewQuery::build()` to accept a `sectionLimitOverrides: array<string, int>` parameter; FirstImportStep tracks per-section caps in a new public `array<string, int> $expandedRowCount` keyed by source_format and re-runs the query through PreviewCache on each click (sub-100ms because the cache is in-memory). The SAMPLE_ROW_LIMIT = 5 constant stays as the first-paint default; the wire:click bubbles up from the Blade component to the FirstImportStep Livewire instance with no extra dispatch/listener wiring. Server-side clamp: negative or zero overrides are silently ignored (DoS mitigation T-16.1.2.03-04).

Purpose: The FirstImportStep currently caps every section at 5 sample rows with no way to expand — UAT feedback flagged this as a hard wall preventing the user from sanity-checking what's about to be imported. Per-section expand keeps the page calm (no global "expand all" affordance per D-09 minimalism) while letting the user verify per source.

Output: Three modified production files + one modified CSS file + one new Pest test + extended BuildConsolidatedPreviewQueryTest.
</objective>
