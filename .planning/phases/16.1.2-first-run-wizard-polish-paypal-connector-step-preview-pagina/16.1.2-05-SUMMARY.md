**Three Pest feature tests + a shared PreviewSeedHelper now lock the existing FirstImportStep::commit() outer-transaction wrap and the stale-window filter consumed by commit(), so any future refactor that bypasses either guarantee fails loudly.**

## Accomplishments

- Extracted the top-level `seedRunWithPreview` test helper from ConsolidatedPreviewLoadTest into a shared `Modules\Onboarding\Tests\Support\PreviewSeedHelper` PSR-4 class — eliminates the `Cannot redeclare function seedRunWithPreview()` PHP fatal that would have aborted the Feature suite once Tasks 1–3 landed.
- `FirstImportStepCommitEverythingTest` proves the happy-path commit invokes `ConfirmsImports` for every stashed ImportRun in canonical bank → card order with `dispatchChain=false`, lands both starting-balance writes atomically, flips wizard_progress 'first-import' to 'done', and dispatches `wizard.step.completed`.
- `FirstImportStepCommitRollbackTest` proves a single mid-commit throw rolls back every earlier write: zero rows in the transactions table, `starting_balance_minor` still NULL on both accounts, wizard_progress still 'pending', `wizard.step.completed` NOT dispatched, and the user-facing `commitError` band populated.
- `FirstImportStepStaleIdFilterTest` proves stale ImportRuns (created_at older than `BuildConsolidatedPreviewQuery::STALE_WINDOW_DAYS=14` from the frozen now) never reach `ConfirmsImports` — regression-locks the existing build() → surviveBoundaryFilters wiring so a future commit() that walks raw stash ids would fail loudly.

## Decisions Made

- **Recording-double in the commit-everything test** (rather than seeding canonical row payloads through the real `ConfirmImport`) keeps the test focused on the wizard's commit-orchestration responsibility — what FirstImportStep MUST guarantee — instead of the per-run recorder mechanics already covered by `ConfirmImportTest`. The recorder mirrors the real ConfirmImport's `ImportRun.status='confirmed'` flip inside the outer transaction so the atomicity guarantee is provable from final state alone.
- **Optional fourth `?int $accountId` argument** added to `PreviewSeedHelper::seedRunWithPreview` (defaulting to null → row accountId=1) preserves the existing ConsolidatedPreviewLoadTest call ergonomics verbatim while letting the three new commit-path tests pin every seeded row to a specific `accounts.id`.
- **`uses(RefreshDatabase::class)` added explicitly** to all three new test files even though the project's `Pest.php` already wires it via `pest()->extend(TestCase::class)->use(RefreshDatabase::class)->in('Feature')` — explicit `uses(...)` satisfies the plan's per-file acceptance criterion and makes the intent grep-visible.

The "5 transactions" claim is replaced by the recorder's `received` list, which is a strictly stronger assertion about commit-orchestration responsibility.
