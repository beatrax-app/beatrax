# Phase 16.1.2 Plan 03: Per-section preview pagination — Load more (N remaining) Summary

## Accomplishments

- **Task 1: `BuildConsolidatedPreviewQuery::build()` accepts a per-section row-cap override.** Added a third named argument `array<string, int> $sectionLimitOverrides = []`. The map is consulted per section by `buildSection()` which now accepts a `?int $override` third argument; the slice computes `$limit = ($override !== null && $override > 0) ? $override : self::SAMPLE_ROW_LIMIT` so non-positive values silently fall back to the default 5-row cap (server-side clamp defending against a tampered wire-snapshot payload — threat T-16.1.2.03-03). The existing `SAMPLE_ROW_LIMIT = 5` constant stays unchanged; `ConsolidatedPreviewBatch` + `ConsolidatedPreviewSection` DTO shapes do not change. Four new Pest cases prove default behaviour, per-section override (asn-csv = 25 while ics-pdf stays at 5), totalRows-clamp on oversized override (override 999 against a 10-row run returns 10 rows), and non-positive rejection (both 0 and -5 fall back to 5).

- **Task 2: `FirstImportStep` tracks per-section expansion state + Blade footer becomes interactive + CSS rules ship.** New public property `array<string, int> $expandedRowCount` keyed by `source_format` value (`'asn-camt053'`, `'paypal-csv'`, `'ics-pdf'`, …); initialised in `mount()` alongside the existing properties. New action method `loadMoreRows(string $sourceFormat): void` increments the per-section cap by 25 (starting from `BuildConsolidatedPreviewQuery::SAMPLE_ROW_LIMIT` on first click). `render()` passes the map through to `BuildConsolidatedPreviewQuery::build()` as `sectionLimitOverrides:`. The `consolidated-preview-section.blade.php` footer swaps the static "N rows shown · M more" line for a `<button type="button" wire:click="loadMoreRows('{{ $section->sourceFormat }}')">Load more (N remaining)</button>` when `$remaining > 0`, collapsing to "{N} rows shown" once fully revealed. The wire:click bubbles up from the Blade component to the `FirstImportStep` parent without needing `dispatch`/`#[On]` wiring. `resources/css/app.css` gains two new rules inside the existing `@layer components` block immediately after `.preview-section-more` (line 1521): `.preview-section-more-actions` (centred flex wrapper, 12px top margin) and `.preview-section-load-more` (calm-slate semantic button using `var(--text-sm)` + `var(--color-text)` + `var(--color-surface)` + `var(--color-border)` + `var(--radius-md)` + `var(--tx-quick)` — only existing tokens per D-17). Two new Pest cases prove (a) clicking `loadMoreRows('asn-camt053')` grows the bank section from 5 → 30 → 55 → 60 rows (clamped at totalRows) and (b) clicking the bank section does not grow the PayPal section.

- **Cross-cutting wiring carried forward:** Plan 02's `paypal_import_run_id` stash is now flowing through this plan's pagination — the PayPal preview section can be expanded independently of the bank section, exactly as the consolidated-preview surface intends. ## Decisions Made

- **Named parameter on `build()` (`sectionLimitOverrides: []`) rather than a fluent `->withSectionLimits()` builder.** The class is `final readonly`, the service is a singleton, and the existing call sites all do `build($ids, $user)` as a single statement — adding a third optional named argument is a strict additive change with zero ergonomic cost and zero state-mutation surface. Both shapes were listed as planner's discretion in CONTEXT.md (line 221).
- **Server-side clamp on non-positive overrides lives inside the query, not the action.** The `loadMoreRows` Livewire action does naive `+25` arithmetic without checking anything; the per-render clamp inside `buildSection()` (`$override > 0`) defends the DTO-shape contract against any path that might land a zero / negative cap in the property (e.g. a tampered wire-snapshot client). Defence-in-depth: the clamp also lives at the only place that converts the cap into an `array_slice` argument.
- **Idempotent over-clicks rely on `array_slice`'s natural clamping at array length.** A user who keeps clicking past `totalRows` will see `loadMoreRows` increment `expandedRowCount` past the row count, but the slice + the blade footer (`$remaining = max(0, $section->totalRows - $shownCount)`) cooperate so the button hides and successive clicks return identical UI. No explicit `min()` math required inside the action.
- **CSS rules live inside the existing `@layer components` block, immediately after `.preview-section-more`.** Keeps all preview-section primitives together so future readers see the pagination chrome next to the section table chrome. The next plan (05) appends sketch-006 framed-sub-card CSS to the same file — these two rules are insulated from that change because they sit before the new sub-card block.
- **No new theme tokens.** All five CSS values use existing slate-derived tokens (`--color-surface`, `--color-surface-2`, `--color-border`, `--color-text`, `--text-sm`, `--radius-md`, `--tx-quick`). Per CONTEXT.md D-17, the calm-slate aesthetic stays the design contract.
