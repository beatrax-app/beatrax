Back-fill the three regression tests that Plan 16.1.1-07b's SUMMARY called for but never shipped (D-18, D-19, D-20). The `commit()` logic itself at FirstImportStep.php:178+ already exists — these tests are pure regression coverage to lock the current behavior so future refactors cannot silently break it. The plan is structured so the three test files do NOT each redeclare the `seedRunWithPreview` helper at the top level — that would trigger a `Cannot redeclare function seedRunWithPreview()` PHP fatal when Pest loads every `*Test.php` under `tests/Feature/` into one script run (the pre-existing `ConsolidatedPreviewLoadTest.php:73` already declares one such top-level function). Each test follows the established `ConsolidatedPreviewLoadTest` scaffold: frozen Clock via `$this->app->instance(Clock::class, ...)`, real DB via `RefreshDatabase`, no Mockery on the DB layer (per memory `feedback_no_mocking_db`). For tests that need to control whether ConfirmsImports throws or records, the pattern is a container-bound anonymous-class implementation of the `ConfirmsImports` public contract — exactly mirroring how ConsolidatedPreviewLoadTest binds an anonymous Clock implementation.

Purpose: The commit() flow is the load-bearing surface of FirstImportStep — if it ever stops being transactional, the user can end up with half-imported statements, mismatched starting balances, and a wizard that thinks it's done when it isn't. These three tests turn the implicit "we'll trust the code" stance into explicit Pest assertions that fail loudly on regression.

Output: One new shared helper class + one edit to ConsolidatedPreviewLoadTest (dedup) + three new Pest feature tests, all green against current code, no production code touched.
