## Decisions Made

- **Sketch token substitution (`--color-primary` → `--color-text`, `--color-primary-text` → `--color-text-inverse`).** The sketch reference CSS at `first-import-review-step.md:224-228` literally writes `var(--color-primary)` and `var(--color-primary-text)` for the `.commit-btn-primary` rule, but neither token is declared in `resources/css/app.css` or `sources/themes/default.css` (verified: `grep -nE '^\s*--color-primary' resources/css/app.css` returns no matches). The plan's hard rule D-17 forbids introducing new theme tokens. The live app's only locked primary-button color mapping lives at `.pill-btn-primary` (`background: var(--color-text); color: var(--color-text-inverse);` at app.css:1000-1001), so `.commit-btn-primary` mirrors that exact pair — keeping the calm-slate palette unified and the `.pill-btn-primary` ↔ `.commit-btn-primary` color contract trivially reviewable.
- **Eyebrow copy tightened.** The live `wiz-eyebrow` was `'Step 5 — Review everything we found'`, identical to the H1 directly beneath it — a regression introduced in an earlier pass. The sketch HTML at `first-import-review-step.md:241` shows `'Step 5 — Review & commit'`, which differs from the H1 and gives the eyebrow a distinct labeling job. Updated to the sketch literal (Blade-escaped as `Review &amp; commit`).
- **`tabular-nums` utility class retained over the sketch's `tnum`.** The live blade already uses `class="tabular-nums"` for every numeric `<span>` / `<strong>`. Tailwind v4 ships `tabular-nums` as a utility; the sketch's `tnum` is a sketch-local convention that would require either declaring `.tnum { font-variant-numeric: tabular-nums; }` in `app.css` (out of scope for this presentation-only plan) or paying a missing-class debt. Sticking with `tabular-nums` keeps the contract honest.
- **Per-section wrapping in Blade (not CSS sibling selector).** The `.empty` modifier is applied via a Blade ternary on `$section->status`. Doing the fill swap via a CSS sibling selector on `.preview-section-table` would require fragile structural assumptions; the Blade-driven class is declarative, threat-model-safe (the `'empty'` literal is the only value that ever reaches the class attribute — see T-16.1.2.04-03), and matches the sketch's HTML structure at `first-import-review-step.md:252`.
- **CSS placement inside the existing trailing `@layer components` block.** The file already has a long `@layer components { ... }` block running from line 1316 to line 1548; the new rules were inserted just before the closing brace, immediately after Plan 03's `.preview-section-load-more` block. Keeps the file structurally identical (one block, one closing brace) and keeps every preview-side primitive grouped for future readers.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 — Blocking] Substituted undeclared sketch tokens (`--color-primary` / `--color-primary-text`) with the live app's locked `.pill-btn-primary` color pair (`--color-text` / `--color-text-inverse`)**

- **Found during:** Task 1 (CSS append)
- **Issue:** The sketch reference CSS for `.commit-btn-primary` at `first-import-review-step.md:224-228` uses `var(--color-primary)` (background + border) and `var(--color-primary-text)` (text colour). Neither token is declared in this codebase — confirmed by `grep -nE '^\s*--color-primary' resources/css/app.css sources/themes/default.css` returning no matches. Pasting the sketch's literal CSS would (a) produce un-styled button colours at runtime (CSS would fall back to `currentColor` / browser defaults) and (b) violate D-17 (no new theme tokens) if I declared the missing tokens.
- **Fix:** Replaced both token references with the live app's locked primary-button colour pair — `background: var(--color-text); color: var(--color-text-inverse); border: 1px solid var(--color-text);` — the exact mapping `.pill-btn-primary` uses at `app.css:1000-1001`. This keeps the calm-slate palette unified (every primary action surface in the wizard shares one colour pair) and the `.pill-btn-primary` ↔ `.commit-btn-primary` substitution boundary trivially reviewable. The plan's `<action>` block explicitly instructs this substitution: "Any sketch selector that references a token NOT already declared in `app.css` MUST be replaced by an existing token."
- **Files modified:** `resources/css/app.css`
- **Verification:** `git diff resources/css/app.css | grep -cE '^\+\s+--(color|radius|text|tx|space)-[a-zA-Z0-9_-]+:'` returns 0 (zero new token declarations). All twelve new selectors render against declared tokens only.
- **Committed in:** `6665665` (Task 1 commit)

**2. [Rule 1 — Bug] Eyebrow line duplicated the H1**

- **Found during:** Task 2 (Blade rewrite)
- **Issue:** The pre-rewrite eyebrow read `'📥 Step 5 — Review everything we found'`, identical to the H1 directly beneath it. The two lines were rendering as a literal duplicate-line block on the FirstImportStep page — a UX regression from an earlier pass, never matching the sketch's intended hierarchy (eyebrow labels the step, H1 names the action).
- **Fix:** Updated the eyebrow to the sketch's literal `'📥 Step 5 — Review & commit'` (HTML-escaped via Blade as `&amp;`). The H1 still reads `'Review everything we found'`, so the two lines now play distinct roles per the sketch contract at `first-import-review-step.md:241-242`.
- **Files modified:** `Modules/Onboarding/Resources/views/livewire/steps/first-import-step.blade.php`
- **Verification:** Visual contract matches sketch reference; FirstImportStepWidthTest stays green (the test only asserts the `.wiz-card--wide` class is present, not the eyebrow text).
- **Committed in:** `9d52aba` (Task 2 commit)

**3. [Rule 3 — Blocking] Built a hybrid worktree `vendor/` (same setup Plans 01-03 used)**

- **Found during:** Pre-execution baseline (no `vendor/` in the worktree).
- **Issue:** Per Plans 01-03's documented issue, the worktree starts without a `vendor/`. Pest and PHPStan need to resolve from a `vendor/bin/*` physically inside the worktree (so `__DIR__` resolves correctly and PHPStan does not double-load the main repo's autoload). Without it, `vendor/bin/pest` and `vendor/bin/phpstan` are missing and every acceptance gate fails immediately.
- **Fix:** Symlinked every read-only package dir from the main repo's `vendor/` into the worktree's `vendor/`, then copied `composer/` + `pestphp/` + `bin/` as real local copies. Renamed the `ComposerAutoloaderInit{SUFFIX}` + `ComposerStaticInit{SUFFIX}` classes inside the worktree's `composer/autoload_real.php` + `composer/autoload_static.php` (added `wt04` suffix) to avoid `Cannot redeclare class` errors when PHPStan analysis touches a file that pulls the main repo's autoload alongside the worktree's. Created a worktree-local `vendor/autoload.php` that returns the renamed class's loader. Also created `.env` (copied from `.env.example` + ran `php artisan key:generate`) so phpdotenv stops emitting a warning during Pest runs.
- **Files modified:** none in the repo — local-execution-only (the `vendor/` directory is gitignored; `.env` is gitignored).
- **Verification:** `vendor/bin/pest` resolves; FirstImportStepWidthTest passes; full Onboarding Feature suite green.
