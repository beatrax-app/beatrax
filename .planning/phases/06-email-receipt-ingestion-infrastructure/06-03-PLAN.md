<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Laravel /oauth/callback/{provider} | OAuth code arrives from a redirect; CSRF state must verify |
| user paste → OAuthSecretsRepository | OAuth client_id + client_secret typed by user; validate format, write atomic |
| Google IdP → diederik | Refresh-token exchange responses include sensitive material; never log payloads |
| browser → /inboxes/{id}/* | Routed actions cross user_id boundaries; defensive where + assertion |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03-01 | Tampering | OAuth callback CSRF | mitigate | Per-flow random state via OAuthStateRepository; verified by exact comparison + session pop on callback; mismatch raises InvalidStateException → HTTP 400 |
| T-06-03-02 | Information disclosure | refresh_token in exception traces | mitigate | Try/catch around getAccessToken() rethrows a typed OAuthExchangeFailed exception whose message contains ONLY the IdP error code / description, never the request body or any token payload; Log calls (if any — none in module code) NEVER reference $token |
| T-06-03-03 | Tampering | redirect_uri smuggling via /oauth/connect/{provider}?redirect_uri=evil | mitigate | OAuthConnectController computes the redirect_uri server-side from config('app.url') + the fixed loopback host; never accepts a query-string-supplied redirect_uri |
| T-06-03-04 | Tampering | Bring-your-own client_id / client_secret injection via the wizard form | mitigate | Server-side validation of client_id format (Google: ends in .apps.googleusercontent.com; Microsoft equivalent in Plan 04); regex + non-empty checks; stored via OAuthSecretsRepository (chmod-600) NEVER the DB |
| T-06-03-05 | Repudiation | Cross-user OAuth callback (user A's flow tries to mutate user B's row) | mitigate | OAuthCallbackController inserts a NEW inboxes row keyed on the current authenticated user_id; reconnect flow asserts existing inbox row's user_id === currentUser->id before rotating |
| T-06-03-06 | Information disclosure | Login session hijack via OAuth state in URL | mitigate | OAuth state is stored in the user's Laravel session (encrypted via APP_KEY) — leaks only if the cookie leaks; same posture as Phase 1 Fortify-auth |
| T-06-03-SC | Tampering | composer install of google/apiclient + 3 OAuth + 1 MIME packages | mitigate | All 6 packages slopcheck-clean (RESEARCH.md § Package Legitimacy Audit, 2026-05-16); composer.json conflict block from Plan 01 blocks any webklex/ext-imap regression; Plan 01 NoExtImapTest extension covers composer.lock |
</threat_model>
