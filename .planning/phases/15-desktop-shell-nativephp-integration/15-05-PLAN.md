<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fresh-install boot → DB creation | First launch creates and migrates the SQLite database |
| Hardened Runtime → bundled PHP | The notarized runtime executes the embedded PHP interpreter |
| Published Electron project → build | The published project's config controls bundle contents + entitlements |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-14 | Denial of Service | Hardened Runtime blocks the bundled PHP runtime → app won't launch | mitigate | `build/entitlements.mac.plist` (Task 3) configures `allow-unsigned-executable-memory` + `disable-library-validation` so the embedded interpreter runs under notarization |
| T-15-15 | Information Disclosure | Hardened-Runtime entitlements relax code-signing protections | accept | The two entitlements are the documented minimum for an embedded interpreter (RESEARCH.md Pitfall 6); they are scoped to the app bundle, not system-wide; this is the standard Electron+embedded-runtime tradeoff |
| T-15-16 | Tampering | First-launch migration runs on every boot | mitigate | `FirstLaunchBootstrap` runs only the framework migration runner against the `UserDataPathService`-resolved local SQLite file; idempotent, no external input drives it (D-23) |
| T-15-17 | Information Disclosure | Secrets reaching the shipped bundle via the published Electron project | mitigate | `cleanup_env_keys` (plan 01) strips dev/secret env; `.env.bundled` (Phase 17 CI-06) carries no real secrets; the published project config is reviewed when edited |
</threat_model>
