<objective>
Make the packaged bundle self-supervising and respect the window-close intent: configure the queue worker as a NativePHP persistent child process (D-05), wire the timer-based email auto-scan as a scheduler entry (D-06), surface worker crash-loops to the partner (D-07), and add the first-close Quit-vs-Keep-in-tray prompt (D-08) — closing to the tray is what keeps the D-05 worker alive.

Purpose: The non-technical partner has no Horizon and no dev console. After this slice, queued jobs drain and scheduled scans fire automatically while the app is alive (including when minimized to the tray), the partner is told if the worker dies, and the close button no longer silently kills background processing. This is the shipped-build worker daemon Phase 14 deferred here.
Output: Bundle-supervised worker + scheduler, a worker-health alert listener, and the close-window prompt.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Electron main process → PHP child process | NativePHP spawns + supervises the `queue:work` process |
| Scheduler closure → job dispatch | The timer scan enumerates inboxes and dispatches jobs |
| Window-close event → process lifecycle | The close choice decides whether background processing keeps running |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-06 | Denial of Service | Bundled queue worker crash-loop | mitigate | NativePHP `persistent` supervision auto-restarts; `SurfaceWorkerCrashAlert` escalates a sustained crash-loop to a critical `system_alerts` row + OS notification so the partner can act (D-07) |
| T-15-07 | Tampering | `queue:work` child process command | mitigate | The worker command is fixed in `config/nativephp.php` (`queue:work`, `default` queue), not constructed from any external input; no untrusted data reaches the spawned process args |
| T-15-08 | Information Disclosure | Worker logs / STDERR | accept | Worker STDERR is local to the machine (local-only constraint); secret redaction in surfaced logs is a Phase 16 Dev Console concern, out of scope here |
| T-15-22 | Tampering | `users.close_behavior` value | mitigate | The close-behavior value is written only via the validated instant-apply path (allow-list `quit`/`tray`); `WindowCloseBehavior` maps it to a fixed action, never executes it as input |
</threat_model>
