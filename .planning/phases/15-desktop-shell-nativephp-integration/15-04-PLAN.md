<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS "Open With" → app | The OS hands diederik an arbitrary, attacker-influenceable file path |
| Electron main process → PHP route | The file path is POSTed from JS into Laravel |
| Logged-out file-open → session | A pending intent is held across the unauthenticated→authenticated transition |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-09 | Tampering / Elevation of Privilege | Malicious file path via "Open With" (argv injection) | mitigate | `FileOpenIntake` (Task 2) canonicalizes the path, enforces a strict `csv`/`eml` extension allow-list, rejects directories/non-existent paths, size-limits, and NEVER `exec()`s the path; the file is processed only through the existing validated `FileDropEmlBlobStore`/Import pipelines |
| T-15-10 | Information Disclosure | File-open intent leaking across users on a multi-user box | mitigate | `PendingFileIntent` is session-scoped; `ContinuePendingFileIntentAfterLogin` re-checks the intent belongs to the just-authenticated session before continuing — a cross-user test (Task 4) proves user B cannot inherit user A's intent |
| T-15-11 | Spoofing | Forged POST to the file-open intake route | mitigate | The intake route is behind `['web']` (CSRF-protected); the Electron main process is the only legitimate caller and runs in-process; the route only triggers validation + staging, never a privileged action |
| T-15-12 | Elevation of Privilege | Electron renderer with `nodeIntegration` | mitigate | Keep NativePHP v2 "secure by default" renderer settings in the published Electron project (Task 1); do not enable `nodeIntegration` |
| T-15-13 | Information Disclosure | Local web server bound beyond loopback | mitigate | Verify (Task 1 spike) the bundle serves the app on loopback only — no routable port exposed |
</threat_model>
