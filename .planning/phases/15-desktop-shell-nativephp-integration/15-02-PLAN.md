<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS notification click → app navigation | A clicked notification drives in-app navigation via `NotificationDeepLink` |
| Electron main process → PHP | Window focus/blur events cross from Electron into PHP state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-03 | Tampering | `NotificationDeepLink` screen-route payload | mitigate | The deep-link `reference` is a route name/URL produced by the app itself when firing the notification, not user input; the click handler navigates only to named app routes and the destination screens sit behind `auth` middleware — a clicked notification cannot reach another user's data |
| T-15-04 | Information Disclosure | OS notification body text | accept | Notification bodies contain merchant/amount summaries (low sensitivity, already shown in-app); OS notification surfaces are a standard desktop affordance — no PII beyond what the user already sees |
| T-15-05 | Elevation of Privilege | Electron renderer settings | mitigate | Keep NativePHP v2 "secure by default" renderer settings; do not enable `nodeIntegration` in the published Electron project (the project is published in plan 05; file-association edits land in plan 04) |
</threat_model>
