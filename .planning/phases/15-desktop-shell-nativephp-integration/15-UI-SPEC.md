# Phase 15 — UI Design Contract

> Visual and interaction contract for the Desktop Shell phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope of this contract.** Phase 15 ships native chrome and a small set of *new* in-app screens (`.csv`/`.eml` staging pages, the "Setting up…" boot screen, the welcome screen, the close-button prompt, the Settings theme control) **and** a full dark theme retrofitted across every existing module's Blade views (D-15). This contract therefore covers two surfaces: (1) the new screens, and (2) the dark-variant token mapping that every existing view must adopt. It is **not** a re-design of the v1.0 light UI — the light contract is the established codebase convention and is reproduced here as the source of truth the dark theme mirrors.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn not applicable — server-rendered Livewire 4 + Blade, no Vite component graph) |
| Preset | not applicable |
| Component library | Flux UI 2 (`livewire/flux ^2.0`) — `flux:badge`, `flux:card`, `flux:heading`, `flux:modal`, `flux:radio`, `flux:radio.group` already in use. New screens reuse these; raw Tailwind utilities otherwise. |
| Icon library | none installed — Heroicons-outline rendered inline as `<svg>` (project convention; see dashboard reauth toast). New tray/menu glyphs follow the same inline-SVG pattern. |
| Font | Inter (local-installed preferred; falls back to `system-ui, -apple-system, sans-serif`). No webfont fetched — local-only constraint forbids outbound HTTP. Money/date/KPI cells use `font-variant-numeric: tabular-nums`. |

**Dark mode strategy (D-15 / D-16).** Tailwind v4 is CSS-first (`@import "tailwindcss"` in `resources/css/app.css`). The dark theme is delivered with the **`class` dark-mode strategy**: add `@custom-variant dark (&:where(.dark, .dark *));` to `app.css` and toggle a `dark` class on `<html>`. The class is set server-side from the user's `theme` preference (`light` / `dark` / `system`); for `system`, an inline `<head>` script reads `prefers-color-scheme` before first paint to prevent a flash. NativePHP's `Native\Laravel\Facades\Window` dark-mode signal (quarantined in `Modules/Desktop/`) feeds the `system` resolution. Every existing view gains `dark:` variants per the token table below — no view keeps a hard-coded `bg-white` / `text-slate-900` without a `dark:` companion.

## Spacing Scale

Declared values (all multiples of 4 — matches the established v1.0 codebase: `space-y-12` sections, `p-6` cards, `gap-4` grids):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gaps, badge inset (`gap-1`, `px-2 py-0.5`) |
| sm | 8px | Compact element spacing, nav-item gaps (`gap-2`) |
| md | 16px | Default element spacing, card/banner padding (`p-4`, `gap-4`) |
| lg | 24px | Card inner padding (`p-6`), page gutters (`px-6`/`px-8`) |
| xl | 32px | Form-section spacing (within a page) |
| 2xl | 48px | Major section breaks (`space-y-12`) |
| 3xl | 64px | Page-level vertical rhythm on tall screens |

Exceptions: none — every layout spacing token above is a multiple of 4 from the standard set.

> Minimum interactive target-size constraints (a distinct concern from layout spacing) live as per-component accessibility notes in the Component Inventory below.

## Typography

Inter throughout. Weights restricted to **two**: regular (400) and semibold (600). `font-medium` (500) appears in the v1.0 codebase on buttons/badges and is retained where already present, but **new** Phase 15 markup uses only 400/600 to keep the contract honest. Sizes restricted to the **four** roles below. The Heading role is a **single size** — `text-2xl` (24px); all card titles, section headings, and full-screen titles (Sign in, Upload, "Welcome to diederik", "Setting up…") map to it. The legacy v1.0 `text-xl` (20px) usage is folded up into the 24px Heading role; `text-3xl` dashboard/settings titles map to Display.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 12px (`text-xs`) | 600 semibold, `uppercase tracking-wide` | 1.4 |
| Body | 14px (`text-sm`) | 400 regular | 1.5 |
| Heading | 24px (`text-2xl`) | 600 semibold, `tracking-tight` | 1.3 |
| Display | 30px (`text-3xl`) | 600 semibold, `tracking-tight` | 1.2 |

Four-size scale: 12 / 14 / 24 / 30 px — exactly four distinct pixel values. KPI/money numbers render at Display size with `tabular-nums`. Help/caption text is Body size at `text-slate-500` (light) / `text-slate-400` (dark).

## Color

60/30/10 split. The v1.0 palette is slate-based with emerald as the single positive accent and rose as the single negative/destructive semantic. Phase 15 adds the dark column — **no new hues are introduced**; dark is a tonal inversion of the same slate/emerald/rose families.

| Role | Light value | Dark value | Usage |
|------|-------------|------------|-------|
| Dominant (60%) | `white` (`#ffffff`) | `slate-950` (`#020617`) | Page background, primary app surface, modal/dialog bodies |
| Secondary (30%) | `slate-50` (`#f8fafc`) | `slate-900` (`#0f172a`) | Cards, table headers, form-input fills, nav bar, tray menu surface |
| Accent (10%) | `slate-900` (`#0f172a`) — "ink" | `slate-100` (`#f1f5f9`) | See reserved-for list below |
| Positive | `emerald-600` (`#059669`) → hover `emerald-700` | `emerald-500` (`#10b981`) → hover `emerald-400` | Primary submit CTAs, positive net amounts, "Saved." confirmation text |
| Destructive | `rose-600` (`#e11d48`) → hover `rose-700` | `rose-500` (`#f43f5e`) → hover `rose-400` | Destructive actions, error text, critical alert chrome only |

**Accent (ink) reserved for:** primary nav-item active state (`bg-slate-100` pill + `slate-900` text), KPI/heading text, body text on surfaces, badge fills (the `slate-900` count pills), category-bar fill, focus ring (`focus-visible:ring-slate-900`), and secondary-link hover. Accent is **not** the primary-action color — the primary submit button is emerald (established v1.0 convention; the close-button prompt and the `.csv` "Start import" button follow this).

**Semantic carve-outs already in the codebase (preserved, not expanded):** `amber-50/300/900` for warning-tier system alerts, `rose-50/500/900` for critical-tier system alerts and the drift "↗/↘" pills. These are alert-severity chrome, not free-use colors — Phase 15 adds their `dark:` variants (`amber-950/amber-800/amber-200`, `rose-950/rose-800/rose-200`) and introduces nothing new.

**Dark-theme contrast requirement:** every `dark:` text/background pair must clear WCAG AA (4.5:1 for body, 3:1 for large/Display). `slate-100`-on-`slate-950` and `slate-400`-on-`slate-950` both pass; `slate-500` body text on dark is **not** permitted — caption text steps up to `slate-400` in dark mode.

**System-tray icon:** monochrome/template image (D-19) — single-color silhouette, no fill palette; the OS tints it for the active menu-bar theme. Excluded from the 60/30/10 accounting.

## Copywriting Contract

Tone: calm, plain, second-person, no exclamation marks, no jargon — matches the v1.0 voice ("This period at a glance.", "Nothing here for this period."). Verbatim copy from CONTEXT.md `<specifics>` is locked; the rest is specified below.

| Element | Copy |
|---------|------|
| Primary CTA — `.csv` staging page (D-01) | **"Start import"** (button; page heading "File received: `<name>`") |
| Primary CTA — `.eml` staging page (D-02) | **"Start import"** (mirrors the `.csv` staging pattern for consistency; page heading "File received: `<name>`") |
| Primary CTA — welcome screen (D-22) | **"Get started"** (button; heading "Welcome to diederik") |
| Primary CTA — Settings theme control (D-16) | No button — instant-apply segmented control (Light / Dark / System), matching the existing instant-apply auto-import toggle pattern |
| Empty state heading — staging page, no file resolved | "We couldn't open that file" |
| Empty state body — staging page, no file resolved | "diederik couldn't read the file you opened. Try importing it from the Imports page instead." (links to `route('imports.new')`) |
| Boot screen (D-21) | Heading **"Setting up…"** — body: "diederik is preparing your data. This only takes a moment." (no button; auto-advances when migrations finish) |
| Error state — first-boot DB init failure | Heading "Setup didn't finish" — body: "diederik couldn't finish setting up its database. Quit and reopen the app to try again." + a single "Quit" button. |
| Error state — bundled worker crash (D-07) | In-app `SystemAlertsBanner` (focused) / native OS notification (backgrounded): title "Background work stopped" — body: "diederik's background processing stopped unexpectedly. Imports and email scans are paused. Reopen the app to restart it." |
| Destructive confirmation — close window, first time (D-08) | Dialog title "Keep diederik running?" — body: "Closing the window can either quit diederik completely or keep it running quietly in the menu bar so scheduled email scans continue." Two buttons: **"Quit diederik"** (destructive, `rose-600`) and **"Keep running in the tray"** (primary, `emerald-600`). A checkbox below: "Remember my choice" (checked by default — the choice persists per D-08). |
| Tray right-click menu (D-09, verbatim) | "Open diederik" · "Scan email now" · "Quit" |
| App-menu additions (D-11, verbatim) | File → "Import file…", File → "Scan email now"; Help → "GitHub repo", "Report an issue", "About diederik" |
| OS notification — import finished (D-12) | Title "Import finished" — body: "`<n>` transactions added from `<source>`." (click deep-links to that import, D-14) |
| OS notification — drift alert (D-12) | Title "A recurring charge changed" — body: "`<merchant>` is now `<amount>`, up/down from `<prior>`." (click → drift alerts page) |
| OS notification — new receipts found (D-12) | Title "New receipts found" — body: "`<n>` receipts matched from your email." (click → Inboxes) |
| OS notification — forecast shortfall (D-12) | Title "Cash-flow shortfall ahead" — body: "Your projected balance dips below zero within the next 30 days." (click → Forecast) |

**Destructive actions in this phase:** exactly one — the window-close "Quit diederik" path (D-08). It is non-data-destructive (quits the process; data is on disk) but treated as the heavier choice: rose-styled, not the default-focused button. The default-focused button is "Keep running in the tray". No typed-confirmation modal is needed (that pattern is reserved for Phase 16's `db:restore`-tier commands).
