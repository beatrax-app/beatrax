## Evidence

- timestamp: 2026-05-23T22:00:00Z
  checked: `file resources/brand/tray-icon.png` + `sips -g all`
  found: 44×44 PNG, 8-bit RGBA, RGB color space, hasAlpha=yes, 96 DPI. Visually appears as black-on-transparent — content looks monochrome but file is encoded as full RGBA.
  implication: SIZE is the immediate problem (44×44 instead of ~18×18 / 22×22), but color encoding (RGBA vs grayscale) is irrelevant for template — Electron uses alpha channel for shape and ignores RGB color when `setTemplateImage(true)` is set. Bigger blocker: regardless of image properties, Electron NEVER auto-treats an image as template unless `nativeImage.setTemplateImage(true)` is called OR (on macOS only) the filename ends in `Template@*x.png` and is created via `nativeImage.createFromNamedImage` or shipped as @x assets — NOT for arbitrary filesystem images.

- timestamp: 2026-05-23T22:00:00Z
  checked: `Modules/Desktop/Internal/NativeAppServiceProvider::boot()` and `TrayMenuBuilder`
  found: Boot calls `MenuBar::create()->icon(resource_path('brand/tray-icon.png'))->onlyShowContextMenu(true)->withContextMenu(...)`. There is no `->templateIcon(...)` or similar template-flag call. TrayMenuBuilder just builds the right-click menu — no icon plumbing.
  implication: PHP layer never tells Electron the icon is a template. Need to check NativePHP MenuBar fluent API for a template flag, and if missing, the Electron-side handler for whether it calls setTemplateImage at all.

## Resolution

root_cause: NativePHP's Electron-side `electron-plugin/dist/server/api/menuBar.js` `/create` route handler constructs `new Tray(icon || state.icon.replace('icon.png', 'IconTemplate.png'))` with a raw filesystem path string and never calls `setTemplateImage(true)`. NativePHP's PHP `MenuBar` API also surfaces no template-image option. Electron does not auto-detect template images from arbitrary filesystem paths via `nativeImage.createFromPath` (the filename auto-detection only applies to images loaded from the macOS app bundle Resources via `nativeImage.createFromNamedImage` with `*Template@*x.png` naming). The image asset itself at `resources/brand/tray-icon.png` is fine (44×44 RGBA black-on-transparent — works as a template because Electron uses the alpha channel and ignores RGB color when the template flag is set), so hypothesis (a) is FALSE and hypothesis (b) is TRUE.
fix: Added prebuild script `scripts/nativephp_patch_tray_template_image.php` that, every build, patches the built `nativephp/electron/electron-plugin/dist/server/api/menuBar.js` to replace `new Tray(<arg>)` with `new Tray((() => { const _img = require('electron').nativeImage.createFromPath(<arg>); _img.setTemplateImage(true); return _img; })())`. The patch uses a character-by-character paren-balancing walker so the nested `state.icon.replace('icon.png', 'IconTemplate.png')` call inside the `new Tray(...)` argument is captured correctly. Registered in `config/nativephp.php` `prebuild` array alongside the existing electron-side hooks. Idempotent: subsequent runs detect the existing `setTemplateImage` call and skip.
verification: Direct invocation patches the dist correctly, idempotency confirmed by running twice. 6 Pest unit tests in `Modules/Desktop/Tests/Unit/PatchTrayTemplateImageScriptTest.php` cover injection, paren balancing, string-literal-with-paren edge case, two failure modes, and single-injection guarantee. All 103 Desktop module tests pass. Larastan level 10 strict: no errors. Pint: passed.
